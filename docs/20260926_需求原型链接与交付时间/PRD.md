# PRD:需求原型链接与交付时间

> 创建日期:2026-09-26
> 状态:**已确认**(2026-09-26,三项边界已拍板,待确认清单为空)
> 关联:平台主 PRD R4(需求);依赖需求「需求关联用户与评审通过通知」(docs/20260926_需求关联用户通知,R3 提醒对象=其关联用户)

## 背景与目标

需求缺少产品原型入口与交付截止时间:开发者找原型靠问,交付时间靠口头约定。本需求为需求实体增加**原型链接(多条)**与**交付时间**两个字段,并配合逾期标记与到期提醒。

## 用户故事

1. 作为产品,我希望把原型地址(蓝湖/Figma 等)挂在需求上,以便开发直接访问
2. 作为开发者,我希望看到需求的交付截止时间,以便安排优先级;临近/逾期时有提醒

## 需求点清单

### R1:原型链接字段(多条)

- **描述**:需求新增原型链接列表,每条=标签+URL;创建表单与详情页可维护
- **触发场景**:创建需求填写;详情页信息区查看/编辑
- **前置条件**:有需求编辑权限(口径沿用需求现有编辑权限)
- **边界定义**:
  - 做什么:链接可增删改,每条含标签(如「原型」「设计」「API 文档」)与 URL;详情页点击新开标签页;创建时可不填
  - 不做什么:不做链接有效性校验(不请求 URL);不做附件上传
- **字段定义**:
  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | prototype_links | array | 否 | [] | 每条 {label: string ≤20 字, url: http(s):// 开头};最多 10 条;label 可空(空则前端展示「链接 N」) | 原型/文档链接列表;存储方案 rd-plan 定 |
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 表单「添加链接」 | 追加一行(标签+URL 输入) | 可删除单行 |
  | URL 非 http(s) 开头 | 行内校验提示 | 不允许保存该行 |
  | 详情页点击链接 | window.open 新开标签页(rel=noopener) | 不离开平台 |
- **依赖**:无
- **异常与边界场景**:超 10 条禁止添加(前端禁用+提示);空列表=不展示该信息区行
- **验收标准**:
  1. 创建时添加 2 条链接保存成功,详情可见可点击(新开)
  2. 非 http(s) URL 被拦截
  3. 编辑增删链接保存生效

### R2:交付时间字段

- **描述**:需求新增交付时间(截止日,精确到天);创建/详情可维护;列表与详情展示,逾期红色标记
- **触发场景**:创建需求填写;详情查看;列表列展示
- **前置条件**:同 R1 权限口径
- **边界定义**:
  - 做什么:date 类型(到天);需求列表新增「交付时间」列(未逾期常态展示,已逾期红色「已逾期」徽章叠加);详情信息区展示
  - 不做什么:不做工作日/节假日计算;不做自动改状态(逾期不改变需求状态)
- **字段定义**:
  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | delivery_date | date | 否 | 空 | 合法日期;不做早于今天的限制(允许补录历史) | 交付截止日;GMT+8 墙钟 |
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | delivery_date < 今天 且需求未到终态(done/archived) | 列表与详情标红色「已逾期」徽章 | 视觉提醒 |
  | 需求已终态 | 不显示逾期徽章 | - |
- **依赖**:无
- **异常与边界场景**:空值不展示列内容与徽章;时区按平台 GMT+8 约定计算「今天」
- **验收标准**:
  1. 设置交付时间保存后列表/详情可见
  2. 截止日早于今天且需求未终态 → 红色「已逾期」
  3. 需求归档后逾期徽章消失

### R3:交付时间提醒通知

- **描述**:交付时间临近/逾期时,向需求**关联用户**发站内提醒(名单复用「需求关联用户」需求的字段)
- **触发场景**:系统定时检查(每日一次,GMT+8)
- **前置条件**:需求设置了 delivery_date 且未到终态且有关联用户(依赖「需求关联用户」R1)
- **边界定义**:
  - 做什么:两个时点各提醒一次——截止日前 1 天、逾期第 1 天;对象=当次关联用户(排除口径同关联用户通知需求);站内信(复用 R18)
  - 不做什么:不做逐日重复提醒;不发钉钉;需求已终态或无关联用户则跳过
- **字段定义**:无新字段(需提醒去重记录——方案 rd-plan 定,如通知去重键 or 字段标记)
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 定时检查命中「明天截止」 | 向关联用户发「需求《X》交付时间临近(明天)」 | NotificationCenter |
  | 定时检查命中「逾期第 1 天」 | 发「需求《X》已逾期」 | NotificationCenter |
  | 已发过同阶段提醒 | 去重跳过(每需求每阶段一次) | - |
- **依赖**:「需求关联用户与评审通过通知」R1(名单);R2(日期)
- **异常与边界场景**:关联用户为空/均已移出项目 → 跳过;单用户发送失败不阻塞(同关联用户通知口径);存量需求补录 delivery_date 且已逾期 → 只发逾期第 1 天提醒(前 1 天时点已过则跳过)
- **验收标准**:
  1. 明天截止的需求 → 关联用户收到「临近」提醒一次,次日不重复
  2. 逾期第 1 天 → 收到「已逾期」提醒
  3. 需求归档后 → 不再收到任何提醒

## 非功能需求

- 提醒为定时批量动作,单条失败不阻塞批次(记日志)

## 范围外

- 链接有效性检测、附件上传、工作日/节假日计算、逐日重复提醒、钉钉通道
- 存量需求自动补录

## 设计稿引用

- 无外部设计稿;表单/列表/详情按现有样板风格(globals.css 体系)
