# R5.F1:项目详情页需求列表(/projects/{pid})编辑 + 删除(纯前端)

> 状态:✅ | 关联 BUG:BUG-013 | 创建日期:2026-09-27

## 问题描述

项目详情页需求列表(`frontend/src/pages/requirements/RequirementList.tsx`,路由 `/projects/{pid}`)创建需求后没有编辑/删除入口。manage 四维(DimensionPage)已在 R2.F1/R4.F1 补齐,项目详情页未同步。

## 修复方案

**后端零改动**——PATCH /api/requirements/{req_id} 与 DELETE(含 owner/状态/关联三级守卫)R2/R4 轮已就绪,本分片纯前端:

1. **操作列**:需求行新增「编辑」+「删除」(danger)按钮,`stopPropagation` 防触发行跳转;样式与 manage 四维一致
2. **编辑弹窗**:与 DimensionPage 的 `RequirementEditDialog` 同逻辑——回填全部可改字段;**不含**需求分支/PRD 路径/项目;提交走 `requirementsApi.update`,**恒传 delivery_date**;评审中禁 title/description
   - **优先抽共享组件**:把 DimensionPage 内联的 RequirementEditDialog 移到共享文件(如 `frontend/src/pages/requirements/RequirementEditDialog.tsx`),DimensionPage 改为 import,两页共用;若抽取牵连过大,允许复制但逻辑逐行一致
3. **删除**:确认弹窗(含标题+危险提示)照 DimensionPage 同款;禁用条件=status ∈ 禁删集合(approved 及之后)+ title「评审通过的需求不可删除」;关联任务前端不可知 → 后端 400 兜底 + 错误 message 展示;成功后 invalidate 列表
4. 权限:按钮恒显,后端 403/400 兜底(与 manage 页同口径)

### 涉及文件

- `frontend/src/pages/requirements/RequirementList.tsx`(主)
- `frontend/src/pages/manage/DimensionPage.tsx`(仅当抽共享组件时改为 import)
- 新增(可选)`frontend/src/pages/requirements/RequirementEditDialog.tsx`

## 测试验证逻辑(含 BUGS.md 复现步骤与期望值)

1. (修复前复现)/projects/{pid} 需求行无编辑/删除操作
2. 待评审需求行:点「编辑」→ 弹窗回填、无分支/PRD 项 → 改优先级/交付时间保存 → 200 列表刷新
3. 评审中需求:标题/描述禁用 + 提示;改优先级仍可保存
4. 评审通过行:删除按钮禁用 + title;待评审行删除 → 确认弹窗 → 200 列表刷新
5. 有关联任务的需求删除 → 后端 400,页面展示 message,数据不删
6. API 层守卫回归:R4 轮删除/编辑用例全绿(后端未动,重点防回归)

## 验收标准

1. 项目详情页需求行可编辑、可删除,约束与 manage 四维完全一致
2. 分支名/PRD 路径不可改(弹窗不出现)
3. tsc 零错误;后端 pytest 套件无回归(未动后端)
4. 两页编辑弹窗语义一致(恒传 delivery_date、评审中禁 title/description)

## 实施轨 / 设计稿 / 路由入口

- 前端单轨;无外部设计稿,样式沿用 globals.css 与现有弹窗体系
- 路由 `/projects/{pid}`,入口=需求列表行操作列

## 渲染核对期望

- 待评审/已取消行:编辑可点 + 删除(danger)可点;评审通过及之后:删除禁用 + title
- 编辑弹窗:标题/背景/描述/验收标准/优先级/交付时间/关联用户/原型链接;无项目/分支/PRD 项
- 删除确认弹窗:含需求标题 + 危险提示;失败 Alert 展示后端 message

修复重点:项目维与 manage 维编辑/删除口径完全一致(用户要求"同样的")。

## 设计规范

- 按钮复用 `.btn` 体系与 danger 色系;弹窗、Alert、禁用态与 DimensionPage 同款
