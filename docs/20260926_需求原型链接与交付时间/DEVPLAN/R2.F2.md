# R2.F2:任务三维(/manage/tasks、/manage/tests、/manage/releases)列表编辑 + 后端任务 update 接口

> 状态:⬜ | 关联 BUG:BUG-008 | 创建日期:2026-09-27

## 问题描述

`/manage/tasks`、`/manage/tests`、`/manage/releases` 三个列表(共用 `DimensionPage.tsx` 表格)与需求维同样没有修改入口;且后端 `tasks.py` **完全没有** update 接口(全部端点无 PATCH/PUT,`tasks.py:35-547`),前端 `api/tasks.ts` 也无 updateTask——不是"漏接",是两层都不存在。任务字段创建后没有任何修改通道。

## 根因分析

- 前端:与 BUG-007 同根因,操作列无按钮(L202/L211-214)
- 后端:`backend/app/api/tasks.py` 端点清单仅 GET/POST/DELETE(文件/消息)与动作类端点,无任何字段修改端点
- 前端 `frontend/src/api/tasks.ts`(L136-229)无 updateTask,与后端一致

## 修复方案

### 后端:新增 `PATCH /api/tasks/{task_id}`

字段面设计(创建后修正错别字/调整参数的最小安全集;**设计决策,如需调整在评审时改**):

- **通用可改**:`title`(1-128)、`description`
- **dev 维特定(pending)**:`base_branch`、`work_branch`
- **release 维特定(pending)**:`deploy_host`、`deploy_port`、`deploy_script`(`deploy_port` 复用现有端口全平台唯一校验逻辑,冲突 → 400)
- **不可改**:`type`、`req_id`、`status`(任务与需求/分支的关联及状态流转不允许从编辑口进入)
- **状态守卫**:仅 `pending` 可编辑;非 pending → 400「任务已开始,不可编辑」(测试/发布任务同理)
- **权限**:项目 editor 及以上;viewer → 403
- **语义**:PATCH 缺省 = 不动(不引入需求 PATCH 那种"缺省置 NULL"字段)

### 前端

- `api/tasks.ts` 新增 `updateTask` + `useUpdateTask`
- `DimensionPage.tsx` dev/test/release 三维行末格:chevron + 「编辑」按钮(`stopPropagation`)
- `TaskEditDialog`:按 type 出字段(通用 title/description + dev 分支两项 + release 部署三项);非 pending 行按钮禁用(或弹窗内提示不可编辑);pending 行回填后保存
- 与 R2.F1 共用同一套操作列改造骨架,一次改 `DimensionPage.tsx`

### 涉及文件

- `backend/app/api/tasks.py`(新增 PATCH 端点 + UpdateTaskRequest;现有任务 schema 内联在该文件)
- `frontend/src/api/tasks.ts`(新增 updateTask)
- `frontend/src/pages/manage/DimensionPage.tsx`(三维操作列 + TaskEditDialog)

## 测试验证逻辑

### 功能验证(含 BUGS.md 复现步骤与期望值)

1. `/manage/tasks`、`/manage/tests`、`/manage/releases` 三页行内出现「编辑」按钮(修复前:无任何操作按钮,现状复现)
2. API 级(修复前):`PATCH /api/tasks/{id}` → 404/405(接口不存在);修复后 → 200
3. pending dev 任务改 title/description/base_branch/work_branch → 200,详情与列表生效
4. pending release 任务改 `deploy_port` 为已被占用端口 → 400 端口冲突;改为空闲端口 → 200
5. 非 pending(如 running/done)任务 PATCH → 400「任务已开始,不可编辑」
6. PATCH 带 `type`/`req_id`/`status` → 被忽略,响应中不变
7. viewer 成员 → 403
8. title 空/超 128 字 → 422 带字段名

### 回归验证

- 任务创建、运行、发布等现有链路不受影响:`test_tasks_api.py`、`test_dev_tasks.py`、`test_test_tasks.py`、`test_release_tasks.py` 全绿
- 需求维编辑(R2.F1)不受影响

## 验收标准

1. 后端 PATCH /api/tasks/{task_id} 落地,字段面与守卫符合上述设计
2. 三维列表操作列「编辑」可用,pending 任务可改字段并生效
3. 不可改字段(type/req_id/status)API 层与 UI 层双重不可达
4. release 端口唯一校验生效
5. tsc 零错误;新增 pytest + 现有任务套件全绿
