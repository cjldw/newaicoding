# R4.F1:/manage/requirements 列表「删除」+ 后端 DELETE /api/requirements/{req_id}(关联守卫)

> 状态:⬜ | 关联 BUG:BUG-011 | 创建日期:2026-09-27

## 问题描述

需求列表无删除操作,后端也无本体 DELETE 端点。用户口径:删除只针对没有关联、未产生数据的记录——**评审通过的需求不可删**,有关联任务的不可删。

## 修复方案(依据 .scratch/fix-analysis-delete.md §三)

### 后端:`DELETE /api/requirements/{req_id}`

- **权限**:owner-only(对齐 cancel 端点档位;非 owner → 403/1901,复用 `require_project_role`)
- **守卫顺序**(从严,后端强制):
  1. role(owner)
  2. status ∈ 禁删集合 → 400。禁删集合 = **approved 及之后的状态**(approved/in_progress/done/archived,枚举以 `models/requirement.py:29-35` 为准;评审通过即 approved,产生任务数据)
  3. 关联任务存在(`select(Task.id).where(Task.req_id == req_id).limit(1)`)→ 400「需求已关联 N 类任务数据,不可删除」
- **可删**:待评审/已取消等未产生数据状态 且 无关联任务
- **级联**:硬删本体 + 显式删除从属数据(原型链接行、关联用户关联、评审记录,以分析文件 §2 关联图谱为准;无 DB FK 需显式)
- **留痕**:`audit_write`(仓库删除三段式惯例:守卫 → 删 → 审计)
- **错误码**:BizError + 400/403/404,文案中文,风格同现有端点

### 前端:操作列「删除」按钮 + 确认弹窗

- `DimensionPage.tsx` requirements 维:编辑按钮旁新增「删除」(danger 态,`stopPropagation`)
- 禁用条件:status ∈ 禁删集合,title 提示「评审通过的需求不可删除」;**关联任务前端列表无此数据,按钮不因此禁用,后端 400 兜底 + 错误 message 用 Alert 展示**(文件已有 Alert)
- 确认弹窗照 `ModelConfigManagement.tsx:426-432` 惯用法,文案含需求标题
- `frontend/src/api/requirements.ts` 加 `requirementsApi.remove`(+ mutation),成功后 invalidate `['dimension']` 等相关 query
- 权限恒显,后端 403 兜底(同 R2 口径)

### 涉及文件

- `backend/app/api/requirements.py`(DELETE 端点;service 层按需)
- `frontend/src/api/requirements.ts`、`frontend/src/pages/manage/DimensionPage.tsx`

## 测试验证逻辑(含 BUGS.md 复现步骤与期望值)

1. (修复前复现)列表操作列无删除按钮;curl DELETE → 404/405
2. owner 删除「待评审且无关联任务」需求 → 200,列表消失,从属数据(原型链接/关联用户)一并清除
3. owner 删除「评审通过」需求 → 400,文案含「不可删除」;需求仍在
4. owner 删除「有待关联任务的需求(任意任务状态)」→ 400;需求与任务均在
5. editor/viewer 删除 → 403/1901;未认证 → 401
6. 前端:评审通过行的删除按钮禁用 + title;待评审行可点 → 确认弹窗 → 删除成功列表刷新
7. 删除操作留审计痕迹(audit_write)
