# R1.F1:/manage/requirements 新建需求 dialog 补齐完整字段

> 状态:⬜ | 关联 BUG:BUG-004 | 创建日期:2026-09-26

## 问题描述

`/manage/requirements` 页面的「新建需求」弹窗(`QuickCreateDialog`)仅有 title + description 两个字段,而项目详情页(`RequirementList.tsx`)的创建 dialog 已实现完整字段(background/acceptance_criteria/priority/req_branch/delivery_date/related_user_ids/prototype_links)。用户在页面需求管理创建需求时无法填写交付时间、原型链接等字段。

## 根因分析

`DimensionPage.tsx` 的 `QuickCreateDialog` 设计为四维(需求/任务/测试/发布)通用快速创建模式,采用最小字段集(title+description)以适配所有维度。requirements 维度仅提交 `{ title, description }`,缺少完整字段。

## 修复方案

将 `/manage/requirements` 的创建 dialog 从通用 `QuickCreateDialog` 替换为需求专用完整表单,对齐 `RequirementList.tsx` 的创建 dialog 字段结构:

### 字段清单(保留项目选择器)

1. **项目选择器**(保留,manage 页面跨项目需要)
2. **标题**(必填,带分支预览)
3. **背景**(可选 textarea)
4. **描述**(必填 textarea)
5. **验收标准**(可选 textarea)
6. **优先级**(select: low/medium/high,默认 medium)
7. **需求分支**(可选,带预览占位符)
8. **交付时间**(可选 input[type=date])
9. **关联用户**(可选,复用 `RelatedUserSelect` 组件)
10. **原型链接**(可选,行组:标签≤20 + URL http(s)://,最多 10 条)

### 实现要点

- **复用策略**:从 `RequirementList.tsx` 抽取表单逻辑为独立组件 `RequirementForm.tsx`,两处共用
- **项目选择器**:manage 页面保留项目下拉(首项默认),项目详情页不需要(由 URL 参数决定)
- **关联用户**:需要加载当前项目成员列表(`useProjectMembers`),manage 页面按 `activePid` 动态加载
- **提交逻辑**:调用 `requirementsApi.create(projectId, fullPayload)`,payload 包含全部字段
- **创建成功跳转**:保持现有行为(跳需求详情页 `/requirements/{req_id}`)

### 涉及文件

- `frontend/src/pages/manage/DimensionPage.tsx`:替换 requirements 维度的 QuickCreateDialog 逻辑
- `frontend/src/pages/requirements/RequirementList.tsx`:抽取表单为 `RequirementForm` 组件
- `frontend/src/pages/requirements/RequirementForm.tsx`:新建公共表单组件(可选,若复用复杂度高则直接复制)

## 测试验证逻辑

### 功能验证

1. 访问 `/manage/requirements`,点击「新建需求」
2. 验证弹窗包含全部 10 个字段(项目选择器 + 9 个需求字段)
3. 填写完整表单:
   - 选择项目
   - 标题:「测试需求-完整字段」
   - 背景:「测试背景」
   - 描述:「测试描述」
   - 验收标准:「测试验收标准」
   - 优先级:高
   - 需求分支:留空(使用默认预览)
   - 交付时间:选择明天日期
   - 关联用户:选择 1-2 个项目成员
   - 原型链接:添加 2 条({label:「原型」, url:「https://example.com/1」}, {label:「设计」, url:「https://example.com/2」})
4. 点击「创建」,验证:
   - 创建成功,跳转需求详情页
   - 详情页显示全部字段(交付时间、原型链接、关联用户等)
5. 验证原型链接校验:
   - 添加一条 URL 为 `invalid-url` 的链接,应显示行内错误提示「URL 需以 http(s):// 开头」
   - 无法提交直到修正
6. 验证原型链接上限:
   - 添加 10 条链接后,「添加链接」按钮禁用,显示「最多 10 条」提示

### 回归验证

- 项目详情页(`/projects/{pid}/requirements`)的创建 dialog 不受影响,功能正常
- 其他三维(任务/测试/发布)的快速创建 dialog 不受影响(仍使用通用 QuickCreateDialog)

## 验收标准

1. `/manage/requirements` 新建需求 dialog 包含全部 10 个字段
2. 填写完整字段后创建成功,详情页回显正确
3. 原型链接校验逻辑与项目详情页一致(http(s):// 前缀、≤10 条上限)
4. 关联用户选择器正常工作(加载项目成员、可搜索、chips 可移除)
5. 项目详情页创建 dialog 功能不受影响
6. 其他三维快速创建 dialog 功能不受影响

## 实施轨

- **后端**:无改动(接口已支持全部字段)

## 对应设计稿

- 无外部设计稿;复用 `RequirementList.tsx` 现有表单样式(globals.css 体系)

## 路由与入口

- **路由**:`/manage/requirements`
- **入口**:页面右上角「新建需求」按钮

## 渲染核对期望

修复后 `/manage/requirements` 新建需求 dialog 应包含:
- 项目选择器(select,manage 页面特有)
- 标题(input + 分支预览)
- 背景(textarea)
- 描述(textarea)
- 验收标准(textarea)
- 优先级(select: 低/中/高)
- 需求分支(input + 预览占位符)
- 交付时间(input[type=date])
- 关联用户(RelatedUserSelect 组件)
- 原型链接(行组:标签 + URL + 删除按钮 + 添加链接按钮)

修复重点:字段完整性与项目详情页一致,校验逻辑一致。

## 设计规范

- 表单样式复用 globals.css `.input` / `.btn` 体系
- 字段间距 `space-y-4`(与 RequirementList.tsx 一致)
- 必填字段标红色 `*`
- 可选字段标灰色提示文字「(可选)」
- 原型链接行内错误提示 `text-xs text-red-fg`
