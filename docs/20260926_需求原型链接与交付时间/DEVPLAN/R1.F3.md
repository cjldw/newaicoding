# R1.F3:/manage/tests 和 /manage/releases 快速创建任务 422 报错

> 状态:⬜ | 关联 BUG:BUG-006 | 创建日期:2026-09-26

## 问题描述

`/manage/tests` 和 `/manage/releases` 页面快速创建任务时,选择需求后直接提交,后端返回 422:
```json
{
    "code": 422,
    "data": null,
    "message": "String should have at least 1 character"
}
```

## 根因分析

`DimensionPage.tsx` 的 `QuickCreateDialog` 在 test/release 维度:
1. **没有 description 输入框**(test 维度 L529-534 只渲染需求下拉 + hint;release 维度类似)
2. `description` state 恒为 `''`
3. 提交 payload 无差别组装 `description: description.trim()`(L432-436)→ 恒发空串
4. 后端 `CreateTaskRequest`(`tasks.py:89-92`)的 `description: str = Field(min_length=1)` 必填
5. `canSubmit`(L458-463)对 test/dev/release 维度只校验 `!!reqId`,不拦空描述

title 有 `|| req.title` 兜底所以没事,description 没有兜底。

## 修复方案

### 前端(必改)

1. **QuickCreateDialog test/release 分支给 description 兜底**:
   - 提交时 `description: description.trim() || req.title || '任务描述'`
   - 或:test/release 维度渲染 description 输入框(可选,默认值为需求标题)

2. **title `.slice(0, 200)` 改为 `.slice(0, 128)`**:
   - 对齐后端 `max_length=128`
   - L391:`title: (title.trim() || ...).slice(0, 128)`

### 后端(建议)

1. **`CreateTaskRequest` 对 test 类型放宽 description 校验**:
   - `description: str | None = Field(default=None, max_length=2000)`
   - service 层对 test 类型落默认文案(如 `f"测试需求:{req.title}"`)

2. **422 处理器带上字段名**:
   - `response.py:195-206` 返回 `{"field": "description", "message": "..."}`
   - 便于前端定位问题

## 测试验证逻辑

### 功能验证

1. 访问 `/manage/tests`,点击「新建测试任务」
2. 选择需求(标题超 128 字的需求,验证 title 截断)
3. 不填 description,直接点击「创建」
4. 验证:
   - 创建成功,返回 200 + task_id
   - 跳转任务详情页 `/tasks/{task_id}`
   - 任务 description 为需求标题或默认文案
5. 访问 `/manage/releases`,点击「新建发布任务」,重复步骤 2-4

### 回归验证

- `/manage/dev` 快速创建开发任务同样生效
- `/manage/requirements` 快速创建需求不受影响
- 需求详情页的 TaskCreateDialog 创建任务功能不受影响

## 验收标准

1. `/manage/tests` 和 `/manage/releases` 快速创建任务成功,不报 422
2. title 超 128 字时自动截断,不报 422
3. description 为空时使用需求标题或默认文案
4. TypeScript 编译通过(`npx tsc --noEmit` 零错误)

## 实施轨

- **前端**:QuickCreateDialog test/release 分支 description 兜底 + title slice 对齐
- **后端**(可选):description 放宽校验 + 422 处理器带字段名
