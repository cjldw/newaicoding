# R2.F1:/manage/requirements 列表操作列新增「编辑」+ 需求编辑弹窗

> 状态:⬜ | 关联 BUG:BUG-007 | 创建日期:2026-09-27

## 问题描述

`/manage/requirements` 创建需求后没有任何修改入口:列表操作列只有跳转箭头(`DimensionPage.tsx` L202/L211-214,整行点击跳详情),需求详情页也仅能改关联用户+交付时间。标题/背景/描述/验收标准/优先级/交付时间/原型链接创建后无处可改。

## 根因分析

- 四维共用 `DimensionPage.tsx` 表格,操作列无任何按钮,编辑 dialog 从未实现
- 项目详情页 `RequirementList.tsx` 同样只有创建 dialog,无可复用编辑组件
- 后端能力早已具备:`PATCH /api/requirements/{req_id}`(`requirements.py:123-161`)支持全部可改字段;`req_branch`/`prd_file_path` 不在 `UpdateRequirementRequest` schema 中(pydantic 默认忽略),**天然不可改**——用户要求的"分支名、PRD 路径不可修改"后端已满足
- 前端 `requirementsApi.update` + `useUpdateRequirement`(`requirements.ts:139-140, 208-217`)契约齐全,仅缺消费入口

## 修复方案

### 字段约束(用户口径)

- **可修改**:标题、背景、描述、验收标准、优先级、交付时间、关联用户、原型链接
- **不可修改**:项目、需求分支(req_branch)、PRD 路径(prd_file_path)——编辑弹窗不出现这两项

### 实现要点

- `DimensionPage.tsx` requirements 维行末格(L213):chevron 保留 + 新增「编辑」按钮,`stopPropagation` 防触发行跳转
- 新建 `RequirementEditDialog`(同文件内,表单结构复用 `RequirementCreateDialog` L563-856 的样式体系):
  - 打开时 `useRequirementDetail(reqId)` 回填全部可改字段
  - **不含**项目选择器与需求分支输入
  - 提交走 `requirementsApi.update`(PATCH),成功后 invalidate 列表
  - **恒传 `delivery_date`**(PATCH 语义:该字段缺省即置 NULL,`requirements.py:156`,不恒传会静默清空交付时间)
  - 评审中状态:title/description 输入前置禁用 + 提示(后端 400 兜底已有,`requirements.py:137-138`)
- 权限:按钮恒显,后端 403 兜底(与需求详情页关联用户编辑同口径,不做逐行角色判定)
- 后端**零改动**

### 涉及文件

- `frontend/src/pages/manage/DimensionPage.tsx`(操作列按钮 + RequirementEditDialog)
- `frontend/src/api/requirements.ts`(契约已有,不改)
- `backend/`(不动,仅复用现有 PATCH)

## 测试验证逻辑

### 功能验证(含 BUGS.md 复现步骤与期望值)

1. 访问 `/manage/requirements`,需求行操作列出现「编辑」按钮(修复前:仅 chevron)
2. 点「编辑」→ 弹窗回填全部字段(标题/背景/描述/验收标准/优先级/交付时间/关联用户/原型链接)
3. 弹窗中**不存在**需求分支输入项与 PRD 路径项
4. 改标题、优先级、交付时间、原型链接后保存 → 200,列表与详情刷新生效
5. 不动交付时间直接保存 → 交付时间**不被清空**(恒传语义;修复前若缺省提交会被置 NULL)
6. API 级:PATCH 带 `req_branch`/`prd_file_path` 字段 → 响应中两字段不变(schema 忽略)
7. 评审中需求:改标题 → 400「评审中需求不可编辑」;改优先级 → 成功
8. viewer 成员保存 → 403 兜底提示
