# R4.F2:任务三维(/manage/tasks、tests、releases)列表「删除」+ 后端 DELETE /api/tasks/{task_id}(pending 严档守卫)

> 状态:⬜ | 关联 BUG:BUG-011 | 创建日期:2026-09-27

## 问题描述

任务三维列表无删除操作,后端任务本体无 DELETE 端点(仅 `tasks.py:605` 删上传文件)。用户口径:删除只针对没有关联、未产生数据的记录——**任务/测试:进行中的不可删;发布:发布完成的不可删**。

## 修复方案(依据 .scratch/fix-analysis-delete.md §三,从严档)

### 后端:`DELETE /api/tasks/{task_id}`

- **权限**:editor 及以上(对齐任务 PATCH 档;viewer → 403/1901)
- **守卫(严档,后端强制)**:
  - **通用**:仅 `status='pending'` 且无容器行、无消息行可删;其余一律 400「任务已开始,已产生数据,不可删除」(dev/test 的 running 及之后全禁——用户点名"进行中不可删",done 等已产生运行数据,同禁 ⚠ 替用户的保守决策)
  - **release 特有**:「发布完成」判定 = `status='done'` 且 `extended_attributes.deploy_phase='deployed'`,或有活跃 Route 关联 → 400「发布已完成,请先下线部署」;**不得按不存在的 `deployed` 状态值判断**(枚举无此值,见分析文件存量缺陷注记)
  - 容器存在性检查参考 `runner_service.py:296-312` 的形态
- **级联**(仅可删分支,即 pending 无数据):`db.delete(task)` + 显式删 `task_messages` / `task_uploaded_files`(无 DB FK、无 ORM cascade)+ Route 残留摘除 + 审计 `task.delete`
- **错误码**:BizError + 400/403/404,中文文案

### 前端:三维操作列「删除」按钮 + 确认弹窗

- 与 R4.F1 同批改造 `DimensionPage.tsx` 操作列:任务三维行「删除」`disabled={item.status !== 'pending'}` + title「任务已开始,不可删除」(与编辑按钮禁用同款)
- 确认弹窗照 `ModelConfigManagement.tsx:426-432`,文案含任务标题与类型
- `frontend/src/api/tasks.ts` 加 `tasksApi.remove`(+ mutation),成功后 invalidate `['dimension']`
- 权限恒显,后端 403 兜底;400 错误 message 用 Alert 展示
- **勿引入 `deployed` 状态值**(存量筛选缺陷已另登记 BUG-012,不在本分片处理)

### 涉及文件

- `backend/app/api/tasks.py`(DELETE 端点;service 层按需)
- `frontend/src/api/tasks.ts`、`frontend/src/pages/manage/DimensionPage.tsx`

## 测试验证逻辑(含 BUGS.md 复现步骤与期望值)

1. (修复前复现)三维列表操作列无删除按钮;curl DELETE /api/tasks/{id} → 404/405
2. pending dev/test/release 任务(无容器/消息)owner/editor 删除 → 200,本体+消息+上传文件级联清除
3. running(进行中)任务删除 → 400「不可删除」;done dev 任务删除 → 400(已产生数据 ⚠)
4. release「发布完成」(done+deploy_phase=deployed)删除 → 400「发布已完成,请先下线部署」;有活跃 Route → 400
5. 有容器/消息行的 pending 任务 → 400(严档)
6. viewer → 403/1901;未认证 → 401
7. 前端:非 pending 行删除禁用 + title;pending 行确认弹窗删除成功,列表刷新
