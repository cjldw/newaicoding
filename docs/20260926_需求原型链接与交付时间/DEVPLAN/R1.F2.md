# R1.F2:需求创建弹窗分支预览改为调后端接口取真实拼音

> 状态:⬜ | 关联 BUG:BUG-005 | 创建日期:2026-09-26

## 问题描述

需求创建弹窗(`RequirementList.tsx` L109-120 / `DimensionPage.tsx` 新增的 `RequirementCreateDialog`)的分支预览逻辑在本地把汉字 map 成 `'□'`,实时显示 `feat/□□□□□□20260926`。后端拼音策略已生效(提交 93242f9,`default_req_branch(title)` 返回 `feat/yhdlgnyh20260926`),但前端预览未调后端接口取真实拼音,用户看到的 `□` 极易被误读为「乱码」。

## 根因分析

- **前端预览逻辑**:`RequirementList.tsx` L109-120 的 `branchPreview` 本地计算,汉字 map 成 `'□'`(注释注明「汉字以□占位提示,后端权威」)
- **后端拼音策略**:提交 93242f9 已接线,`requirement_service.py` L192 调用 `default_req_branch(req_data.get("title") or "")`,拼音策略真实生效
- **用户感知**:用户看到的是前端预览的 `□`,创建后才见真实拼音,产生「乱码」误解

## 修复方案

### 后端:新增分支预览接口

新增 `GET /api/requirements/branch-preview?title=...`,返回 `default_req_branch(title)`:

```python
@router.get("/branch-preview")
async def branch_preview(title: str = Query(..., min_length=1, max_length=128)):
    """预览需求分支名(拼音策略)"""
    return {"branch": default_req_branch(title)}
```

位置:`backend/app/api/requirements.py`,在 `create_requirement` 之前。

### 前端:预览改为调后端接口

1. **RequirementList.tsx**:
   - 删除本地 `branchPreview` 计算逻辑(L109-120)
   - 新增 `useQuery` 调用 `/api/requirements/branch-preview?title=...`,debounce 300ms
   - 预览显示后端返回的真实拼音分支

2. **DimensionPage.tsx**:
   - `RequirementCreateDialog` 同样改造,删除本地 `branchPreview`,改用 `useQuery` 调接口

3. **API 客户端**:
   - `frontend/src/api/requirements.ts` 新增 `branchPreview(title: string)` 方法

### 实现要点

- **debounce**:标题输入 300ms 后触发接口调用,避免频繁请求
- **缓存**:相同 title 复用缓存(React Query 默认行为)
- **错误处理**:接口失败时显示占位符「生成中...」或空字符串
- **跨日日期偏差**:后端 `default_req_branch` 使用 GMT+8 当前日期,前端预览与后端一致

3. 等待 300ms debounce,验证分支预览显示 `feat/yhdlgnyh20260926`(或带脱撞后缀)
4. 修改标题,验证预览更新
5. 留空分支字段,点击创建,验证 `req_branch` 为后端生成的真实拼音

### 回归验证

- 手动填写分支字段(覆盖默认策略),创建后 `req_branch` 为用户填写值
- 英文标题预览正常(无拼音转换)
- 特殊字符标题(如 `需求@#$%`)预览正常(特殊字符被过滤)

## 验收标准

1. 需求创建弹窗分支预览显示真实拼音(非 `□`)
2. 标题输入 300ms 后触发接口调用,预览更新
3. 创建需求后 `req_branch` 与预览一致(留空分支字段时)
4. `/manage/requirements` 新建需求 dialog 同样生效
