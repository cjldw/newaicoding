# R5:容器镜像后台可配置(container_image 设置项)+ 默认镜像切 aliyun registry

## 背景

R1/R2 落地后,任务容器镜像 `platform/devbox:v2` 硬编码于两处常量:
`container_service.DEFAULT_IMAGE` 与 `system_asset_service.DEFAULT_PROBE_IMAGE`,
换镜像(如切 aliyun registry)需要改代码发版。2026-09-28 用户拍板:

1. 新增平台设置项 `container_image`(超管后台「全局参数」组),不配置时回落代码默认;
2. 代码默认值由 `platform/devbox:v2` 改为 `registry.cn-hangzhou.aliyuncs.com/zhanqinet/devbox:v2`
   (镜像由用户自行推送到该 registry,本需求不含推送动作)。

## 拍板与语义

- **生效语义**:镜像在**容器创建时刻**定格(与 R1 同语义)。设置改动/默认值变更
  只影响之后新起的容器,存量与运行中容器不受影响。
- **解析链**(schedule_and_start 与 probe collect 同链):
  `显式传参 > get_setting("container_image") > DEFAULT_IMAGE / DEFAULT_PROBE_IMAGE 常量`。
- **校验**:新 vtype `image`——必须带 tag 的 docker 引用
  (`^[A-Za-z0-9][A-Za-z0-9._/-]+:[A-Za-z0-9._-]+$`,≤255)。
  强制 tag 保证 pull 确定性(latest 随推送漂移,违背"创建时刻定格");不复用 `str`
  类型因其 ≤64 上限,registry 路径含 namespace 时易超。
- **前端**:留空 = 未配置(不发该键),后端回落常量;前端 IMAGE_REF_RE 预检与后端同口径。

| 层 | 文件 | 内容 |

| 容器 | `backend/app/services/container_service.py` | DEFAULT_IMAGE 改 aliyun;schedule_and_start `image=None` 参数 + 解析链 |
| probe | `backend/app/services/system_asset_service.py` | DEFAULT_PROBE_IMAGE 同步;collect 同解析链(锁内解析,单次采集全程一致) |
| 模型 | `backend/app/models/container.py` | Column default/server_default 翻转(应用层恒显式传值,列默认仅兜底) |
| 迁移 | `backend/alembic/versions/b4f8e2a9c1d7_container_image_default_aliyun.py` | 列默认元数据变更(down_revision=e9b3f7c1a6d4),存量行不动 |
| 前端 | `frontend/src/api/admin.ts` + `frontend/src/pages/admin/PlatformSettings.tsx` | 全局参数组加「任务容器镜像」字段(placeholder 展示默认;留空不发键) |
| 测试 | test_platform_settings_api / test_container_platform / test_system_assets_collect | 常量绑定断言更新 + 解析链三态 + 校验正负用例 |

## 运营提醒(平台外)

- Runner 机器需能 pull `registry.cn-hangzhou.aliyuncs.com/zhanqinet/devbox:v2`;
  若 zhanqinet 命名空间为**私有**,各 Runner 机需先 `docker login` registry.cn-hangzhou.aliyuncs.com。
- 换镜像 = 后台改 `container_image` 即可(无需发版);镜像内容升级仍需重建+推送(tag 建议带版本号)。
