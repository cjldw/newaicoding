# R31.F2:修复 BUG-048 宿主终端 WS 零输出(Windows 管道模式双层缺陷)

> 状态:✅ 完成(2026-09-24 rd-fix 第 25 轮;verified 迁移 ISSUES.md)
> 模块:M5(runner/terminal_manager.py 宿主 shell;R31.F1 数据面缺口,其创建/关闭链路正常)
> 关联:BUG-048;用户报障 2026-09-24(「runner 新建的终端没有建立 session,ws://… 没有响应」)

## 描述与根因(双层,均 Windows 管道模式专属)

- **一手证据**:裸 WS 探针握手成功但零字节回包;runner 日志「宿主 shell 已创建 cmd=['cmd.exe']」→ 13s 后「宿主 shell 读取结束」(读循环自发 EOF);敲命令无响应
- **层 1**:`_default_host_shell_cmd()` 返回 `["cmd.exe"]` 缺 `/K`——cmd 检测到 stdin 是管道时进入非交互模式,执行完缓冲命令即退出 → stdout EOF → 读循环结束 → 永久静默
- **层 2**:xterm 的 Enter 发裸 `\r`,管道下的 cmd 只认 `\r\n`——裸 `\r` 滞留不执行(探针实证:`\r` 零输出,`\r\n` 立即执行)。真实 pty 会做行尾仿真,管道模式没有 pty,必须自行补

## 修复(runner/terminal_manager.py,容器 pty 路径零改动)

1. `_default_host_shell_cmd()`:Windows 分支 `["cmd.exe"]` → `["cmd.exe", "/K"]`(/K=执行后保持,管道下常驻等输入)
2. `write_input()` 宿主分支:写入前行尾归一 `\r\n→\n→\r→\n→\r\n`(幂等,不重复扩行尾)——补上管道模式缺失的 pty 行尾仿真

## 决策留痕

- 修复收敛在 runner 侧(管道模式专属分支),后端路由/前端零改动;容器内 pty 会话(任务终端)路径不受影响(write_input 仅宿主分支加翻译)
- 层 2 的行尾仿真放在 runner 写入点而非前端(xterm 协议就是裸 \r,前端零改动;且与真实 pty 的行为对齐)
