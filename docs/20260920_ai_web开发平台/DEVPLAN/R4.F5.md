# R4.F5:修复 BUG-070 文件树目录显示成文件 + 打不开预览(用户指令)

> 状态:✅(fixed;2026-09-29 第 37 轮;runner pytest 8/8+backend 归一化用例过+tsc/build 零错+ui-check 4/4;verified 待浏览器复验)
> 模块:M5 runner 列目录 + M4 工作台文件树(波及 R11 编辑器预览/R3 打磨工作区)
> 关联:BUG-070;用户指令 2026-09-29(rd-fix 第 37 轮:「任务打磨页面的工作区,和任务开发页面的全部文件,对应的文件管理组件BUG, 目录也显示成文件,且打不开预览」)
> 分析底稿:`.scratch/fix-analysis.md` § 第 37 轮

## 描述(即 bug)

任务工作台左栏文件管理组件两个缺陷,双页面复现:

1. **任务打磨页面**(requirement 类型任务)「工作区」Tab:目录与文件全部显示为 FileText 文件图标,无目录/文件区分,无展开交互;点击任何条目(含目录)只设 selectedPath,中栏无编辑器/预览渲染分支——打不开预览
2. **任务开发页面**(dev 类型任务)「全部文件」Tab:目录也显示成文件图标,点击目录不展开、反而触发 read_file 读目录 → 失败,预览打不开

**复现步骤**:
1. 打开打磨任务工作台 → 左栏「工作区」Tab → 观察文件列表:目录显示为文件图标,点击文件无预览
2. 打开开发任务工作台 → 左栏「全部文件」Tab → 观察目录:显示为文件图标;点击目录:不展开且报错/无响应

**期望 vs 实际**:
- 期望:目录显示 Folder/FolderOpen 图标 + 展开箭头,点击展开/折叠子目录;文件显示 File 图标,点击打开编辑器/预览(vp 基线 `.ftree` 目录/文件以 `.dir`/`.file` class 区分图标)
- 实际:目录显示文件图标;点击目录触发 read_file 失败(开发 Tab)或仅设 selectedPath 无预览(打磨 Tab)

## 实现要点(根因 + 修复方案)

**根因(三层断裂)**:

1. **Runner 层字段失配(主因)**:`runner/container_manager.py:365` `list_dir` 返回 `"type": "tree" if ftype == "d" else "file"`——目录 type 为 `"tree"`,而前端契约 `FileItem.type` 期望 `'file' | 'dir'`(frontend/src/api/files.ts)。FileTree 组件(`frontend/src/components/FileTree.tsx`)按 `node.type === 'dir'` 判断:排序(L42-45)、点击展开分支(L97-103)、Folder/File 图标选择(L105-107)全部失效 → 目录被当文件处理
2. **后端透传无归一化**:`backend/app/services/file_service.py:154-159` `task_file_list` 直接 `return data.get("items", [])`,不校验/归一化 type 字段
3. **打磨「工作区」Tab 未复用 FileTree**:`frontend/src/pages/tasks/TaskDetail.tsx:454-472` 硬编码扁平列表——所有项 `<FileText size={14} />` 图标,点击仅 `setSelectedPath(f.path)`,无 setEnabled/setCenterTab 分支;对比开发任务「全部文件」Tab(L641-652)正确复用 `<FileTree mode="task" ... onSelectFile={(p) => { setSelectedPath(p); setEnabled(true); setCenterTab('edit') }} />`

**修复方案(三层分进,F1+F2+F3)**:

- **F1 runner 归一化(治本)**:`runner/container_manager.py` list_dir `"tree"` → `"dir"`(对齐前端契约;注意旧 runner 容器镜像可能仍是旧代码,故 F2 兜底必要)
- **F2 后端防御归一化**:`backend/app/services/file_service.py` task_file_list 返回前遍历 items,`type == "tree"` 归一为 `"dir"`(防 runner 镜像版本不一致)
- **F3 前端打磨 Tab 复用 FileTree**:`TaskDetail.tsx` 需求打磨「工作区」Tab 硬编码列表替换为 `<FileTree mode="task" files={filesData?.items} onSelectFile={(p) => { setSelectedPath(p); setEnabled(true); setCenterTab('edit') }} />`,与开发任务「全部文件」Tab 行为完全对齐

**并行会话防冲突**:第 36 轮(R5.F2/BUG-069)触碰面 = runner/container_manager.py `claude_prompt_stream` 函数(~L495-620)、runner/main.py 流式 handler、backend task_service.py、TaskChat.tsx——与本修复触碰的 `list_dir`(L351-369)/file_service/TaskDetail 工作区 Tab **函数级零交集**,同文件不同函数,可安全并行(修复时只做点状 Edit,不整文件重写)。

## 修复重点(渲染核对期望)

- 修复重点:文件管理组件目录/文件区分 + 点击预览链路(BUG-070)
- FileTree 组件行为零改动(组件本身无缺陷,是数据 type 字段失配)——修复后开发「全部文件」Tab 目录自动恢复展开/图标语义
- vp 基线:vp/index.html `.ftree` 目录/文件图标区分(Folder/File),打磨工作区 Tab 对齐开发 Tab 的树交互

## 决策留痕

- 不选 F3' 替代方案(打磨 Tab 独立实现 dir/file 区分):重复实现展开状态机,且与开发 Tab 行为发散,违背组件复用
- FileTree 组件不加对 "tree" 的容错分支:契约应单一("dir"),容错放后端归一化层(F2),避免前端契约发散
- 旧 runner 容器内代码为镜像时点快照,F1 改仓库代码后需容器/镜像重建才生效——F2 后端归一化保证「旧 runner + 新后端」组合下 UI 依然正确
