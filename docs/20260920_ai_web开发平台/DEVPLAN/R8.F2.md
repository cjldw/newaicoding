# R8.F2 — 修复 BUG-027:Runner 事件监听归属过滤 + 心跳饿死

> 来源:BUGS.md BUG-027(本地 Runner 实测发现 2026-09-23)
> 状态:✅ verified(2026-09-23:重启后心跳 last_hb 每 30s 刷新(22:47:55→22:48:25 实测)+ 越权接管 0 次;E2E round3/4 全程在线)

## 描述(即 bug)

本地 Runner 实测暴露两个运行时缺陷(2 合 1,同一事件监听链路):
1. **无归属过滤**:`event_listener` 对宿主机**所有**容器的 die 事件做自动重启(≤3 次)并回报平台——实测反复重启用户自己的 `monkeycode-ai-backend`(crash-loop 中,与平台无关,containers 表无记录)
2. **心跳饿死**:`iter_events()` 同步阻塞生成器直接在协程内迭代,堵死 asyncio 事件循环 → 30s 心跳发不出 → 平台 60s 判 offline(实测 last_hb 停在注册时刻)

## 实现要点(根因 + 修复方案,均已实现于 runner/main.py)

- **归属过滤**:容器创建时已打标签 `qicheng.managed=true`(container_manager L93)——event_listener 按 `Actor.Attributes["qicheng.managed"]` 过滤,非平台容器 `continue`(不接管、不回报)
- **线程泵送**:阻塞 events 流移入 daemon 线程(`threading.Thread(target=_pump)`),经 `queue.Queue` 泵回;async 侧 `while empty: await sleep(0.2)` 轮询——事件循环不再被阻塞
- 新增模块导入:`queue`/`threading`

## 测试验证逻辑(修复后按此回归)

1. 重启 Runner → 平台 `GET /api/admin/runners` 该 Runner `status=online` 且 `last_heartbeat_at` 每 ≤30s 刷新(观察 ≥2 分钟)
2. 宿主机上存在 crash-loop 的非平台容器(实测环境即有)→ Runner 日志**不再出现**对该容器的"容器自动重启"
3. E2E(与 R8.F1 联动):创建任务 → 容器拉起 → 平台收到 start 事件 → 终端/预览可用
