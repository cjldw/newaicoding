# R37.F9:修复 BUG-083 done 任务误弹容器门卫 + 打磨完成后回需求详情页

- **状态**:⬜
- **关联 BUG**:BUG-083(用户报障「页面完了后一直任务容器未启动,启动也不行。我需要点完成,页面置灰提交,回到需求详情页」)
- **根因**:
  1. `TaskDetail.tsx:397-416` 容器门卫条件 `display_status ∉ {running, starting}` → done 也生效(done=容器正常销毁的终态,弹「任务容器未启动」+「启动」引导;点启动 → retryTask → 后端 4001 终态不可重试 → 死弹框)
  2. finish onSuccess 只 toast 不导航(且 toast 文案在 BUG-082 场景下是谎言,随 R37.F8 修复后语义成立)
- **修复方案**:
  1. 门卫 effect 顶部加终态排除:`done` 不进门卫(done 无「启动」语义;failed/cancelled/timeout 保留——retry 合法且正是门卫的启动通道)
  2. `handleFinishClick` onSuccess:toast + `navigate(`/requirements/${task.req_id}`)`(任务详情载荷已含 req_id;requirement 型任务完成后回需求详情看 PRD)
- **涉及文件**:`frontend/src/pages/tasks/TaskDetail.tsx`
- **测试验证逻辑**:
  - done 任务打开详情页:无门卫遮罩/弹框(tsc + build + 浏览器复验)
  - 打磨任务点「打磨完成」成功:toast + 跳转需求详情页,PRD 区块可见(prd_content 由 R37.F8 链路回填)
  - failed/cancelled/timeout 任务:门卫行为不变(启动=retry 仍可用)
- **完成判据**:tsc 零错 + vite build 过;用户浏览器复验
