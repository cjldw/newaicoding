## PRD 引用

### 边界定义

- **做什么**:
  - 创建发布任务 → 容器内 `git checkout master && git merge req-{reqId}` → 冲突 AI 解决,失败任务 failed
  - 执行**发布脚本**(项目级配置,如 `npm run build && pm2 reload`,或平台默认:在容器内启动服务)
  - **生成对外地址**:`http://{deploy_host}:{port}`(deploy_host 默认 `{slug}.{deploy_base_domain}`,deploy_base_domain 取平台设置(Q28,R2);**创建发布任务时可自定义对外域名**(Q29,仅 HTTP,需自行解析 DNS))
  - 部署产物(CHANGELOG / deploy-log)**commit 到 master** 的 `docs/{YYYYMMDD}_{descSlug}_{taskShortId}/`
  - 发布后**需求状态推进**,全部部署完成 → 需求 done → 触发归档
- **不做什么(V1)**:
  - HTTPS(端口直连)
  - 多环境(staging/prod)
  - **不做**域名级高级能力(DNS 托管 / 泛域名证书 / 多域名绑定;仅发布任务级设置一个对外域名,Q29)
  - 外部服务器部署(SSH/K8s)
  - 回滚(失败就走驳回)
  - 蓝绿/金丝雀

### 字段定义

沿用 R4 通用字段;特定字段:
| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| target_env | enum | 是 | subdomain | V1 仅 HTTP 单环境 |
| deploy_host | string | 是 | `{slug}.{deploy_base_domain}`(平台设置 Q28) | 对外主机名;合法主机名格式;全平台唯一;**创建时可自定义覆盖**(Q29) |
| deploy_url | string | 是 | `http://{deploy_host}:{port}` | - | 运行时拼接 |
| deploy_port | int | 是 | - | 用户自定义,范围 10000-10099 |
| deploy_script | text | 是 | 项目默认 | 用户可改 |
| deploy_log_path | string | 是 | `docs/{YYYYMMDD}_{descSlug}_{taskShortId}/deploy-log.txt` | Q26:YYYYMMDD=发布任务创建日期;descSlug=所属需求标题 slug 截断 32;taskShortId=任务 uuid 前 8 位;**CHANGELOG.md 与 deploy-log.txt 同目录** |
| merge_commit_sha | string(40) | 否 | null | merge 到 master 的 commit |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 创建发布任务 | 用户填 deploy_port(平台检测冲突)+ **deploy_host(按 `{slug}.{deploy_base_domain}` 预填,可自定义,Q29)** → 拉起容器 → checkout master → **merge req-{reqId}(容器内执行,但 merge commit 通过 GitLab API 用平台 bot token 创建,确保系统动作可追溯)** | deploying |
| merge 冲突 | AI 自动解决(在容器内 merge + commit + push 用 bot token)→ 仍冲突 → failed,提示人工在终端介入 | |
| 部署脚本执行 | 容器内运行,日志实时推送到工作台 | |
| 健康检查 | `GET http://localhost:{port}/` 200(可配置路径)→ deployed | URL 可公开访问 |
| **部署产物 commit** | CHANGELOG.md + deploy-log.txt commit 到 master 的 `docs/{YYYYMMDD}_{descSlug}_{taskShortId}/`(**用平台 bot token,系统动作**) | |
| 部署失败 | status=failed → 可驳回回测试(新建 test 任务)或重试 | |
| 需求下所有发布任务 deployed | 需求 → done → 触发 R14 归档 | |
| **容器不销毁** | **部署中的任务容器保持运行**(对外提供服务),直到"下线"或"项目归档" | 持续运行 |

### 异常与边界场景

- 端口冲突:平台检测 `deploy_port` 在**全平台**唯一,冲突拒绝
- **deploy_host 冲突/非法**(Q29):全平台唯一(routes 表 host UNIQUE 兜底);合法主机名校验(不含协议/路径,支持多级子域);**自定义域名未解析到网关不阻塞创建**——部署 URL 创建成功但外网不可达,创建成功 toast 附提示"请先将域名 A 记录解析到 {网关地址}"
- deploy_base_domain(平台设置,Q28)变更:仅影响**之后**创建的发布任务默认值;存量任务 deploy_host 不变(创建时固化)
- 单项目**同时部署数 ≤ 5**
- 部署中的任务**不占用** R4 的"并发 running 任务 ≤ 3"配额
- 部署容器崩溃 → 告警到项目 owner **站内信 + 钉钉 webhook**(Q12 已确认)
- 下线 = 用户点击"下线" → 摘除路由 + 销毁容器

### 验收标准

1. 发布后 `http://{deploy_host}:{port}` 可公开访问(默认域名与自定义域名两种均可用)
2. deploy_host 自定义后 URL 与路由随之变化;非法/重复 host 被拒绝(7003)
3. 部署产物 commit 到 master
4. 需求下所有发布完成后,需求自动 done 并触发归档
5. 下线后 URL 立即不可访问

### 服务端行为规格

#### 创建发布任务

1. 校验需求下至少一个 test 任务 passed
2. 校验 deploy_host(Q29):合法主机名格式 + 全平台唯一(routes 表 host UNIQUE + `tasks.extended_attributes.deploy_host` 双重检测);默认值 `{slug}.{deploy_base_domain}`(实时读平台设置 Q28)
3. 校验 deploy_port 全平台唯一(查 `tasks` 表的 `extended_attributes.deploy_port`)
4. 校验单项目同时部署数 ≤ 5
5. 创建任务(type=release),拉起容器在 **deploy Runner** 上(R16)
6. 容器内执行:
   ```bash
   cd /workspace/main
   git checkout master
   git merge req-{reqId}
   ```
7. merge 冲突 → AI 自动解决(在容器内 merge + commit + push 用 **bot token**)→ 仍冲突 → failed
8. 执行部署脚本(项目级配置或平台默认)
9. 健康检查:`GET http://localhost:{port}/` 200
10. 成功 → 注册路由(R15,host=`{deploy_host}:{port}`,upstream 指向 deploy Runner 宿主机映射端口 `public_ip:deploy_port`,按 D20 直连)→ status=deployed
11. 部署产物 commit 到 master(用 bot token):
    ```bash
    git add docs/{YYYYMMDD}_{descSlug}_{taskShortId}/
    git commit -m "[ai:release] {task_title}"
    git push origin master
    ```
12. 容器**不销毁**(保持运行)

#### 下线

1. 用户点"下线"
2. 平台摘除路由(R15)
3. 平台通知 Runner 销毁容器
4. status=undeployed

### 页面结构说明

#### 部署状态页 `/tasks/{task_id}/deploy`

- **区块结构**:
  1. **页面标题**:"部署状态"
  2. **状态卡片**:部署 URL(可点击)/ 状态徽章(deploying=primary/deployed=success/failed=danger)/ 部署时间
  3. **部署日志**(Textarea,只读,等宽字体)
  4. **操作栏**(若 deployed):"下线"按钮(danger)

### 页面交互流程

#### 创建发布任务流程

1. 用户在需求详情页点"创建发布任务" → 打开对话框
2. 填 deploy_port(平台实时检测冲突)+ **deploy_host(默认预填 `{slug}.{deploy_base_domain}`,可改;实时预览完整对外 URL)** + deploy_script(可选,默认项目配置)
3. 点"创建" → 调 `POST /api/requirements/{req_id}/tasks`
4. 成功 → 跳转部署状态页(自定义域名时 toast 附 DNS 解析提示)
5. 部署中 → 显示 deploying 状态 + 实时日志
6. 部署成功 → 显示 deployed 状态 + 部署 URL

#### 下线流程

1. 用户在部署状态页点"下线"
2. 弹出确认对话框:"确定下线吗?下线后 URL 将不可访问"
3. 点"确定" → 调 `POST /api/tasks/{tid}/offline`
4. 成功 → URL 不可访问
