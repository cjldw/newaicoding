# R21.F1:BUG-051 工作台门槛口径错位(summary 增 visible_projects,门槛与数据同源)

> 状态:✅ 完成(2026-09-26 rd-fix 第 28 轮;verified 迁移 ISSUES.md)
> 模块:M10(前端 Dashboard.tsx + 后端 dashboard.py;M1 project_service 只读不动)
> 关联:BUG-051(用户报障「工作台的开发任务统计好像不对」);前承 R21(全局 Dashboard)

## 描述(分析底稿要点,全文见 .scratch/fix-analysis.md 第 28 轮小节)

- **现象**:非 owner 成员(测试账号 13900001111,项目 5b9ba156 的 editor)登录后工作台只渲染「还没有项目」空态,四张统计卡片整体不出现——统计「看似丢失/不对」
- **数字对账**:summary 与 DB 真值逐项一致(created_by=me 口径合规,R21 Q21 超管也不放大);该账号 dev=0 / requirements=1(done)均为正确值,数字本身无 bug
- **根因**:门槛口径 ≠ 数据口径——Dashboard.tsx:45-46/:103 `hasProject` 取自 owner-only 的 GET /api/projects(project_service.py:326-331 conditions=[owner_id==me]),而 summary 数据口径=「owner 或成员可见」(_visible_project_ids,dashboard.py:26-43);成员但非 owner 被误判「无项目」

## 实现要点(推荐案,分析底稿 §5)

1. **后端(2-3 行)**:dashboard.py summary 返回体增 `visible_projects: len(pids)`(_visible_project_ids 结果数;超管=全部 active,与统计口径同源)
2. **前端(2-3 行)**:Dashboard.tsx 门槛改与数据同源——`hasProject = (summary?.visible_projects ?? 0) > 0`(弃 owner-only projects 查询作门槛依据;若该查询另有他用则保留查询仅改门槛判定)
3. 明确不做:不改统计口径(created_by=me,R21 Q21 规格);不动 /api/projects 的 owner-only 遗留(R2/R12 范围,service docstring 自注,另轮处理);四维管理页零改动(同口径数字已一致)
