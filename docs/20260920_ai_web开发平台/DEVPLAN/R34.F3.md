# R34.F3 — 依赖安装链加固:requirements.txt 默认安装路径(用户指令)

> 2026-09-28 rd-fix 第 32 轮新增;关联 BUG-062(用户指令,BUG-061 根因链延伸)。

## 描述

用户指令:「生成 requirements.txt 默认启动,安装好对应的依赖 -r requirements.txt」。

背景(BUG-061 根因链):本机运行时依赖历来散装安装,无清单化安装路径——`pip install -e .` 因 setuptools 包发现配置在 editable 构建阶段失败;`backend/venv` 为空壳;R34.F1 声明的 pypinyin 从未被装入(BUG-061 直接根因);快照实证另有 fastapi 0.104.0 **低于** pyproject 声明的 `>=0.110`、ruff(dev)完全缺失。

## 实现要点

1. **`backend/requirements.txt`**(运行时,14 项):与 `pyproject.toml [project].dependencies` **同源同约束逐字对应**(含 pypinyin 及其 R34.F1 注释);文件头注明同步纪律——改依赖先改 pyproject,再同步本文件;
2. **`backend/requirements-dev.txt`**(开发/测试):`-r requirements.txt` + pytest/pytest-asyncio/httpx/ruff(与 `[project.optional-dependencies].dev` 同源);
3. **README 快速开始**默认安装行改 `pip install -r requirements-dev.txt`(仅跑服务可只装 requirements.txt),并留痕 `pip install -e .` 暂不可用;
4. **执行安装**(本机运行时,E:\services\python310):
   - 安装前快照:fastapi==0.104.0(低于约束)、ruff 缺失,其余 13 项满足约束;
   - `pip install -r requirements.txt` → 升级 fastapi 0.104.0→**0.141.1**、pydantic 2.5.3→**2.13.5**(+pydantic-core)、starlette→1.7.0、anyio→4.15.1、watchfiles/httptools 新装(uvicorn[standard] extras);
   - `pip install -r requirements-dev.txt` → 补装 ruff 0.16.9;
5. 后端重启加载新栈(uvicorn --reload,新任务 beh4gvr3a)。

## 测试验证逻辑(回归判据)

1. **清单一致性**:requirements.txt 14 项与 pyproject.toml dependencies 约束逐一比对一致;requirements-dev.txt 4 项与 dev extras 一致;
2. **安装闭环**:`pip install -r` 两文件全绿无 ERROR;安装后 `pip freeze` 复核全部满足约束;
3. **全量单测**:`python -m pytest -q`(fastapi+pydantic 跨 37/11 个小版本,必须全量)——后台执行中,结果落本文件状态节;
4. **真机复验**:新栈重启后 /health ok + 超管 JWT 重放需求创建 code=0 且 req_branch 匹配 `^feat/[a-z]{1,10}\d{8}$`(复用第 31 轮铸 token 链路),证据追加 `.scratch/R34.F2/verify.md` § R34.F3;
5. 全过 → BUG-062 open→fixed→verified 迁移 ISSUES.md。
