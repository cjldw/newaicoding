# R22.F2 — 修复 BUG-UI-069:四维管理页统一 audit-logs 范式 + 快速创建(收敛 052/053/054/055/059/060/061/062)

> 来源:BUGS.md BUG-UI-069(用户指令 2026-09-23 rd-fix 第 15 轮);并收敛 open 批 BUG-UI-052/053/054/055/059/060/061/062

## 描述(即 bug)

需求/任务/测试/发布四维管理页(`frontend/src/pages/manage/DimensionPage.tsx`)与用户拍板的 audit-logs 范式不符:
- 筛选 select 混在 page-head 的 acts 里,无独立 `.fbar` 筛选区(069/062)
- 无搜索框(053)、无添加按钮(061)、无项目筛选(069)
- 表格列只有通用 5 列,缺各维专属列(059 需求:优先级/需求分支;060 任务:类型/Runner 等)
- 容器结构未与表格区分层(052)

用户指令:四维表格统一 audit-logs 范式(筛选区与表格区分离),各维右上角自有添加按钮(样式对齐 admin/runners 的 `btn btn-pri` + plus icon),添加弹框补关联字段(即 vp `openQuick` 快速创建)。

## 实施轨 + 对应设计稿

- 实施轨:轨 1 — **vp `pageManage`(index.html L1661-1707)+ `openQuick`(L1738-1762)为唯一视觉事实源**(vp-prototype-fidelity 纪律:DOM 照抄 + CSS 原值 + 并排核对)
- 路由与入口:`/manage/requirements`、`/manage/tasks`、`/manage/tests`、`/manage/releases`(共用 DimensionPage)
- 参照页:`admin/AuditLogsPage.tsx`(同为 page wide + page-head + card>scrollx>tbl + card-foot 范式)

## 实现要点(根因 + 修复方案)

**根因**:R22 首轮实现只做了最小通用 5 列,未照抄 vp pageManage 的 fbar/列定义/快速创建结构;BUG-014 修复只补了 key 字段。

**改动清单**:

### 后端 `backend/app/api/dashboard_views.py`(两接口扩展,向后兼容:只加字段/加可选参数)

1. `GET /api/dashboard/requirements` 与 `GET /api/dashboard/tasks/{task_type}` 各加可选参数:`project_id`(项目筛选)、`q`(标题关键字,`title LIKE %q%`;requirement 同时匹配 req_id、task 同时匹配 task_id,大小写不敏感)
2. requirements items 补字段:`req_branch`、`created_by`(`{user_id, nickname, phone}` 摘要,批量查 users 防 N+1)
3. tasks items 补字段:`runner`(runner 名称或短 id,经 runners 表批量映射;无则空)、`created_by` 摘要;`release` 维补 `deploy_port`/`deploy_host`(Task.extended_attributes);`test` 维补 `cases_passed`(`extended_attributes.test_cases` 统计 pass/total,无则 null)
4. 既有断言(dashboard 测试)补新字段回归

### 前端 `DimensionPage.tsx`(照抄 vp pageManage 结构)

1. **page-head**:左 icon+h1+sub 不变(保留 R2.F8 成果);acts 加 `btn btn-pri` 快速创建按钮(plus icon + `{createLabel}`,文案:新建需求 / 新建任务 / 新建测试任务 / 新建发布任务)
2. **card > fbar > scrollx > tbl**:筛选 select 从 page-head 移入 `.card` 内 `.fbar`——项目下拉(全部项目 + 可见项目)、状态下拉(现有 statusOptions)、搜索框(`.input.grow` placeholder"搜索标题,回车确认",回车/失焦提交)、右侧统计文案`共 N 条 · updated_at 倒序 · 20/页`;fbar 样式走 globals.css 既有 `.fbar`(gap 8 / padding 12px 16px,vp L358 原值)
3. **各维列定义照抄 vp L1665-1680**(表头一字不差):
   - requirements:`需求 | 所属项目 | 状态 | 优先级 | 需求分支 | 创建人 | 更新时间`——需求单元格 `<b>{key前8}</b> · {title}`;优先级 bdg(high→b-red 高/medium→b-amber 中/low→b-zinc 低);需求分支 `.chip`(mono);更新时间 `.mono.small.muted.nowrap`
   - tasks(dev):`任务 | 所属项目 | 类型 | 状态 | Runner | 创建人 | 更新时间`——类型 bdg(requirement 打磨-blue/dev 开发-violet/test 测试-amber/release 发布-green,与 TaskDetail 类型色一致);Runner `.mono.small`
   - tests:`测试任务 | 所属项目 | 状态 | 用例通过 | 创建人 | 更新时间`——用例通过 `.mono.small`(pass/total,绿字 var(--green-tx) 语义色;null 显 —)
   - releases:`发布任务 | 所属项目 | 状态 | 部署 URL | 端口 | 创建人 | 更新时间`——部署 URL mono 短链文本(不跳外网,点击进任务工作台),端口 `.mono.small`
   - 列缺失值兜底 `—`(muted);末列 chevron 图标(vp 有,`<td><ChevronRight size={14}/></td>`),行点击行为不变
4. **card-foot** 照抄 vp L1705:`Shield 图标 + "归档 / 软删项目数据不出现;viewer 只读(新建按钮隐藏,API 写操作 403 前后端双重拦截)"`
5. **快速创建对话框**(照抄 vp openQuick 结构,组件用既有 Dialog):项目 select(必选)→ 动态区:
   - requirements:标题 + 描述 → `POST /projects/{pid}/requirements`
   - tasks:需求下拉(该项目 status=approved 的需求,不可选项不显示)+ 描述 → `POST /requirements/{reqId}/tasks {type:'dev', title 取描述首行截断或"开发任务:"+需求标题, description}`
   - tests:需求下拉(status ∈ approved/in_progress/done)+ 提示行 → `POST /requirements/{reqId}/tasks {type:'test'}`
   - releases:需求下拉(status 有通过测试的任务由服务端校验,前端列 approved/done)+ 部署端口输入(10000-10099)→ `POST /requirements/{reqId}/tasks {type:'release', deploy_port}`
   - **与 vp 偏差留痕**:vp 对需求选项做精确前置置灰(需逐需求查任务态),本实现列可选状态需求、前置校验交服务端兜底(create_test_task/create_release_task 已有完整校验与错误码,403/3002 等经统一 ApiError 展示)——避免 N+1 查询;创建成功 toast + 跳对应详情页(需求→`/requirements/{id}`,任务→`/tasks/{id}`,与 vp quickSubmit 跳转一致)
6. `api/dashboard.ts`:DimensionItem 补 `req_branch?/runner?/created_by?/deploy_port?/deploy_host?/cases_passed?`;useDimensionList params 补 `project_id?/q?`;新增可见项目列表复用(已有 projects API)
