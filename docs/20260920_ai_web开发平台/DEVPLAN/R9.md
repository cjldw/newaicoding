## PRD 引用

### 边界定义

- **做什么**:
  - xterm.js + WebSocket + Runner 代理 + docker exec pty
  - 多 Tab(独立 shell session)
  - **Claude CLI 模式**:用户可在终端里直接 `claude` 启动交互式会话
  - **Claude Agent SDK 模式**(任务执行主路径):平台后端跑 SDK,工具调用事件(读/写/执行/git)**结构化推送到工作台"活动流"**;关键命令同时回显到终端(只读,前缀 `[ai]` 高亮)
  - 滚动缓冲 5000 行
- **不做什么**:
  - SSH 直连
  - 终端录制回放(V1)
  - 无任务时的"项目级终端"(容器是任务级的)

### 字段定义

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| session_id | uuid | 是 | auto | 每个 Tab 一个 |
| task_id | ref(R4) | 是 | - | |
| container_id | ref(R8) | 是 | - | |
| shell | string | 是 | /bin/bash | |
| created_by | ref(R1) | 是 | - | |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 打开 Tab | Runner `docker exec` 新 pty,cwd=/workspace/main | 可交互 |
| 任务执行中 | SDK 工具事件流 → 活动流面板;关键命令(git commit、npm install)同时回显终端(只读) | 双通道可见 |
| 用户在终端启动 `claude` | 进入 Claude CLI 交互,**与 SDK 会话相互独立** | 用户主导 |
| 用户在终端 git 操作 | 允许,commit/push 都生效;可能造成与 AI 的冲突,平台不阻止 | |
| 关闭 Tab | kill pty | |

### 异常与边界场景

- 高频输出限流 > 1000 行/秒丢弃中间
- 破坏性命令不拦截,但写审计日志
- 用户在终端 `git reset --hard` 丢失 AI 未 commit 的修改 → 平台不兜底(用户负责)

### 验收标准

1. 终端可正常交互
2. 任务执行时,活动流与终端同时可见 Claude 行为
3. 用户可在终端启动 Claude CLI 独立会话
4. 用户可在终端执行 git 命令介入版本控制

### 接口契约

#### WebSocket 终端频道

- **路径**:`/ws/terminal/{session_id}`
- **鉴权**:JWT(WebSocket 握手时校验)
- **消息协议**(JSON):
  - 前端 → 平台:
    ```json
    {"type": "input", "data": "ls -la\n"}
    {"type": "resize", "cols": 80, "rows": 24}
    ```
  - 平台 → 前端:
    ```json
    {"type": "output", "data": "total 0\ndrwxr-xr-x 2 codespace codespace 4096 ..."}
    {"type": "ai_output", "data": "[ai] git commit -m \"...\"\n"}
    ```

#### 创建终端会话

- **路径**:`POST /api/tasks/{task_id}/terminal-sessions`
- **鉴权**:JWT(项目成员,editor 以上)
- **请求**:
  ```json
  {
    "shell": "/bin/bash"
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "data": {
      "session_id": "uuid",
      "ws_url": "/ws/terminal/{session_id}"
    },
    "message": "ok"
  }
  ```

#### 关闭终端会话

- **路径**:`DELETE /api/terminal-sessions/{session_id}`
- **鉴权**:JWT(创建者)
- **响应**:
  ```json
  {
    "code": 0,
    "message": "已关闭"
  }
  ```

### 服务端行为规格

#### 创建终端会话

1. 校验任务存在且 running
2. 校验用户是项目成员(editor 以上)
3. 生成 `session_id`(uuid)
4. 平台通过 Runner WebSocket 发送:
   ```json
   {
     "type": "exec",
     "container_id": "docker_id",
     "cmd": ["/bin/bash"],
     "pty": true,
     "session_id": "uuid"
   }
   ```
5. Runner 收到后:
   - 调 Docker SDK `exec_create(container_id, cmd=["/bin/bash"], tty=True)` + `exec_start(exec_id)`
   - 维护 `session_id → exec_pid` 映射
   - 回报平台:`{"type": "exec_started", "session_id": "uuid"}`
6. 平台写 `terminal_sessions` 表
7. 返回 `session_id` 与 `ws_url`

#### 终端输入(前端 → 平台 → Runner)

1. 前端发送 `{"type": "input", "data": "ls\n"}`
2. 平台转发给 Runner:
   ```json
   {
     "type": "terminal_input",
     "session_id": "uuid",
     "data": "ls\n"
   }
   ```
3. Runner 写入 pty stdin

#### 终端输出(Runner → 平台 → 前端)

1. Runner 读 pty stdout/stderr
2. **批量缓冲**(每 50ms 或每 8KB 推一次)
3. Runner 发送:
   ```json
   {
     "type": "terminal_output",
     "session_id": "uuid",
     "data": "total 0\n..."
   }
   ```
4. 平台转发到前端

#### pty 会话复用

1. WebSocket 断线重连时,前端带 `session_id`
2. Runner 查找现有 pty(`session_id → exec_pid` 映射)
3. **attach 而非新建**(shell 历史/工作状态不丢)

### 页面结构说明

#### 任务工作台终端区

- **区块结构**:
  1. **Tab 栏**:多个终端 Tab(每个 Tab 独立 shell session)
  2. **终端区**:xterm.js 渲染
  3. **操作栏**:右侧"新建 Tab"按钮

### 页面交互流程

#### 打开终端流程

1. 用户进入任务工作台 → 终端区显示"点击新建终端"
2. 用户点"新建 Tab" → 前端调 `POST /api/tasks/{tid}/terminal-sessions`
3. 成功后前端建立 WebSocket 连接 `/ws/terminal/{session_id}`
4. xterm.js 渲染终端

#### 终端输入流程

1. 用户在 xterm.js 输入命令 → xterm.js 本地回显(用户无感延迟)
2. 前端发送 `{"type": "input", "data": ...}` 到平台
3. 平台转发到 Runner → Runner 写入 pty stdin
4. pty stdout → Runner 批量缓冲 → 平台 → 前端 → xterm.js 渲染

### 控件联动

| xterm.js |  resize | 发送 `{"type": "resize", "cols": ..., "rows": ...}` |
| "新建 Tab" 按钮 | 点击 | 创建新终端会话 |
