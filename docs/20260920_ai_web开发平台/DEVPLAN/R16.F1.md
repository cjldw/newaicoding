# R16.F1 — 修复 BUG-007:Runner 镜像缺 R9/R11 文件

> 来源:BUGS.md BUG-007(rd-ship 发布检查单 §0 阻塞项)
> 状态:✅ fixed(2026-09-22;verified 待部署机首次构建)

## 描述(即 bug)

`docker/runner/Dockerfile` 仅 `COPY main.py container_manager.py /app/`,未包含 R9 新增的 `terminal_manager.py` 与 R11 新增的 `file_watcher.py`;而 `runner/main.py` 顶层 import 二者,镜像启动即:

```
ModuleNotFoundError: No module named 'terminal_manager'
```

影响:Runner 无法部署 → 任务容器(R8)/Web 终端(R9)/文件 watcher(R11)/发布部署(R7)全链路不可用。

## 实现要点(根因 + 修复方案)

- **根因**:R9/R11 为 Runner 新增模块时只更新了 runner/ 目录与平台侧,未同步维护 `docker/runner/Dockerfile` 的 COPY 清单(镜像清单无测试覆盖,回归盲区)。
- **修复方案**(单文件 1 行):COPY 清单补齐 4 个运行时必需文件:
  ```dockerfile
  COPY main.py container_manager.py terminal_manager.py file_watcher.py /app/
  ```
- 同步修订 `DEPLOY.md` §0 阻塞项为已修复(保留 §5 镜像构建步骤不变,build context 为 `runner/` 不变)。

## 测试验证逻辑(修复后按此回归)

1. **构建**:`docker build -t platform/runner:v1 -f docker/runner/Dockerfile runner/` → 成功无报错
2. **冒烟**(核心断言):`docker run --rm --entrypoint python3 platform/runner:v1 -c "import main"` → 零输出退出码 0(等价于验证 main.py 全部 import 可解析,含 TerminalManager/FileWatcher;不实际连平台)
   - 备选(无本机 docker 时):核对镜像内文件清单 `docker run --rm --entrypoint ls platform/runner:v1 /app` → 四个 .py 文件齐全
3. **回填 BUGS.md**:BUG-007 open → fixed(构建+冒烟过)→ verified(迁移 ISSUES.md)
