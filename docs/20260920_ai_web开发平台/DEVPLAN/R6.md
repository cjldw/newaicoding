## PRD 引用

### 边界定义

- **做什么**:
  - **多仓库 clone**:
    - 主仓库(`role=main`)→ `/workspace/main`(被测代码)
    - 所有 `role=test` 仓库 → `/workspace/tests/{repo_slug}`(测试代码)
    - 其他仓库按需挂载到 `/workspace/{role}/{repo_slug}`
  - AI 基于主仓库 PRD 验收标准 + 当前需求分支代码 + **测试仓库现有用例**,生成/更新**测试用例清单**(人可增删改)
  - 人确认后,AI 在容器内执行测试(测试命令由 AI 根据测试仓库结构决定,如 `cd /workspace/tests/xxx && pytest`,或 `npm test`)
  - 产出**测试报告**:`docs/{YYYYMMDD}_{descSlug}_{taskShortId}/report.md` + `cases.json`,**commit 到主仓库**需求分支;若测试脚本本身有改动,也 commit 到**对应测试仓库**的需求分支
  - **失败驳回**:创建新的 dev 任务,携带失败上下文与报告路径
- **不做什么**:
  - 测试用例管理库(V1 用例只存于任务内与 repo)
  - 性能测试/压测
  - 第三方测试平台集成
  - 测试框架强制配置(AI 根据测试仓库结构自动识别 pytest/jest/vitest 等)

### 字段定义

沿用 R4 通用字段;特定字段:
| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| based_on_dev_tasks | json | 是 | - | 关联的 dev task_id 列表 |
| test_cases | json | 是 | - | `[{id, title, steps, expected, status, log}]` |
| report_file_path | string | 是 | `docs/{YYYYMMDD}_{descSlug}_{taskShortId}/report.md` | 报告在主仓库内路径(Q26:YYYYMMDD=测试任务创建日期;descSlug=所属需求标题 slug 截断 32;taskShortId=任务 uuid 前 8 位;**cases.json 与 report.md 同目录**) |
| test_repo_ids | json | 是 | 项目所有 role=test 的 repo_id | 本次任务挂载的测试仓库 |
| rejected_to_dev_task_id | uuid | 否 | null | 驳回产生的新 dev 任务 |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 创建 test 任务 | 校验项目**至少绑定一个 role=test 仓库**(若无则提示先到项目设置添加);AI 读取主仓库 PRD + 当前分支代码 + 测试仓库现有用例 → 生成用例草稿 → status=cases_review | 用户编辑 |
| 项目无 test 仓库 | 允许创建,但 AI 会**在主仓库内新建测试代码**(如 `tests/` 目录);不推荐,UI 给出提示"建议绑定独立测试仓库" | |
| 用户确认用例 | 点击"开始执行" → AI 在容器跑 → status=running | |
| 全部用例通过 | 生成 report.md → commit 到主仓库需求分支 + push(用用户 token)→ status=passed | 需求详情页"创建发布任务"按钮亮起 |
| 有用例失败 | 用户选择:a) 接受失败(填豁免理由)仍 passed;b) 驳回 → 创建新 dev 任务,携带失败上下文与报告路径 | |
| 执行异常 | status=failed,可重试 | |

### 异常与边界场景

- AI 生成的用例人可编辑/删除/新增
- 用例执行**串行**(V1,避免互相干扰)
- 测试任务会写代码(测试脚本),commit 到对应仓库的需求分支
- 测试仓库未拉取成功(token 权限不足):任务 failed,提示检查 token 对该 repo 的权限

### 验收标准

1. AI 能基于 PRD 与测试仓库产出可执行用例
2. 报告能 commit 到主仓库指定路径
3. 测试脚本改动能 commit 到对应测试仓库
4. 驳回能自动创建携带上下文的 dev 任务
5. 项目无测试仓库时给出明确提示

### 接口契约

**接口契约** 总览——**响应结构**统一外层 `{"code": 0, "data": ..., "message": "ok"}`(错误时 `code` 为业务错误码、`message` 为提示文案);字段级结构以下方各接口小节的请求/响应示例为准:

| 接口范围 | 响应结构约定 |
|---|---|
| 本需求点全部接口(下方小节逐一列出) | 统一外层 `{code, data, message}`;分页接口 `data` 含 `{items, total}` |

(沿用 R4 通用接口;特定接口:)

#### 1. 确认用例

- **路径**:`POST /api/tasks/{task_id}/confirm-cases`
- **鉴权**:JWT(owner/editor)
- **请求**:
  ```json
  {
    "test_cases": [
      {"id": "1", "title": "测试登录", "steps": "...", "expected": "...", "status": "pending"}
    ]
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "message": "用例已确认,开始执行"
  }
  ```

#### 2. 接受失败(豁免)

- **路径**:`POST /api/tasks/{task_id}/accept-failure`
- **鉴权**:JWT(owner/editor)
- **请求**:
  ```json
  {
    "reason": "string"
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "message": "已接受失败,任务标记为 passed"
  }
  ```

### 服务端行为规格

#### 创建测试任务

1. 校验需求下至少一个 dev 任务 done
2. 校验项目至少绑定一个 role=test 仓库(若无则提示)
3. 创建任务(type=test),容器内 clone 主仓库 + 所有 role=test 仓库
4. AI 读取主仓库 PRD(`docs/{YYYYMMDD}_{descSlug}_{taskShortId}/PRD.md`)+ 当前分支代码 + 测试仓库现有用例
5. AI 生成测试用例草稿 → 写 `tasks.extended_attributes.test_cases`
6. status=cases_review

#### 确认用例

1. 用户编辑用例(增删改)
2. 点"开始执行" → status=running
3. AI 在容器内执行测试:
   - 根据测试仓库结构决定测试命令(如 `cd /workspace/tests/xxx && pytest`)
   - 串行执行用例
   - 记录每个用例的 status(passed/failed)与 log
4. 全部用例通过 → 生成 report.md + cases.json → commit 到主仓库需求分支 + push → status=passed
5. 有用例失败 → status=failed,等待用户选择(接受失败/驳回)

#### 接受失败(豁免)

1. 用户填豁免理由
2. status=passed(带豁免标记)

#### 驳回

1. 用户点"驳回回开发"
2. 创建新 dev 任务,`extended_attributes.fix_context` 携带失败用例 + 报告路径
3. 原测试任务的 `rejected_to_dev_task_id` 记录新 dev 任务 id

### 页面结构说明

#### 用例审阅页 `/tasks/{task_id}/cases`

- **区块结构**:
  1. **页面标题**:"测试用例审阅"
  2. **用例列表**(Table):
     - 列:用例标题 / 步骤 / 预期结果 / 操作(编辑/删除)
  3. **操作栏**:右侧"新增用例"按钮 + "开始执行"按钮(primary)

#### 测试报告页 `/tasks/{task_id}/report`

- **区块结构**:
  1. **页面标题**:"测试报告"
  2. **统计卡片**:总用例数 / 通过数 / 失败数 / 通过率
  3. **用例列表**(Table):
     - 列:用例标题 / 状态徽章(passed=success/failed=danger)/ 日志(可展开)
  4. **操作栏**(若 failed):
     - "接受失败"按钮(secondary)
     - "驳回回开发"按钮(primary)

### 页面交互流程

#### 用例审阅流程

1. 用户进入任务详情(cases_review 状态)→ 显示用例列表
2. 用户可编辑/删除/新增用例
3. 点"开始执行" → 调 `POST /api/tasks/{tid}/confirm-cases` → status=running

#### 测试报告流程

1. 任务执行完成 → 显示测试报告
2. 全部通过 → 显示"创建发布任务"按钮
3. 有失败 → 显示"接受失败" + "驳回回开发"按钮
