## 实现要点

### 数据模型变更

无新表(D19)。聚合查询直查 `requirements` / `tasks` / `project_members` / `projects`;`IN (成员项目 id 列表)` + `created_by 无关`(注意:**四维菜单与 R21 口径不同**——R22 展示成员项目**全部**数据,不限 created_by;R21 限 created_by=me)。

### 枚举与字典映射

| 枚举/字典 | 值 | 前端文案 | 标签/颜色样式 | 数据来源 |
|---|---|---|---|---|
| 需求 status / priority | 同 R3 | 同 R3 | 同 R3(draft=outline … rejected=danger;priority low/medium/high=outline/secondary/primary) | R3 常量表 |
| 任务 status | 同 R4 | 同 R4 | 同 R4 | R4 常量表 |
| 任务 type | requirement/dev/test/release | 打磨/开发/测试/发布 | outline/primary/warning/success 徽章 | 前端常量 |
| 状态筛选下拉 | 全部 + 各状态全集 | 全部状态 / 草稿 / … | - | 常量表 |

### 接口契约

**接口契约** 总览——**响应结构**统一外层 `{"code": 0, "data": ..., "message": "ok"}`(错误时 `code` 为业务错误码、`message` 为提示文案);字段级结构以下方各接口小节的请求/响应示例为准:

| 接口范围 | 响应结构约定 |
|---|---|
| 本需求点全部接口(下方小节逐一列出) | 统一外层 `{code, data, message}`;分页接口 `data` 含 `{items, total}` |

#### 1. 四维聚合列表(×4 个接口,同构)

- 类型:新建
- 路径与方法:
  - `GET /api/manage/requirements`(需求管理)
  - `GET /api/manage/tasks`(任务管理,全部类型)
  - `GET /api/manage/tests`(测试管理,固定 type=test)
  - `GET /api/manage/releases`(发布管理,固定 type=release)
- 鉴权:登录态;数据范围=成员项目集合(超管=全部 active 项目,R19);显式传 `project_id` 但非成员 → **403 code=21001**(越权,查询结果亦只含成员项目)
- 请求参数(Query,四接口同构):

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| project_id | uuid | 否 | 项目筛选;缺省=全部成员项目 |
| status | string | 否 | 状态筛选(该维度状态全集之一) |
| q | string | 否 | 标题关键字(LIKE %q%,≤64 字) |
| page | int | 否 | 默认 1;<1 按 1(查询域#7) |
| page_size | int | 否 | 默认 20,**上限 100**(防拖库) |

- **排序固定 `updated_at DESC`,不开放排序参数**(查询域#8,防注入)
- 响应结构(通用列 + 特定列):

| 字段 | 类型 | 说明 |
|---|---|---|
| items[].id | uuid | requirement_id 或 task_id |
| items[].title | string | 标题 |
| items[].project | object | `{project_id, name}` |
| items[].status | string | 状态 |
| items[].created_by | object | `{user_id, nickname}` |
| items[].updated_at | datetime | |
| requirements 特有 | - | `priority`, `req_branch` |
| tasks 特有 | - | `type`, `runner: {runner_id, name}(可 null,未分配时)` |
| tests 特有 | - | `cases_passed`, `cases_total`(取自 extended_attributes.test_cases 统计) |
| releases 特有 | - | `deploy_url`(可点击), `deploy_port` |
| total | int | 分页总数 |
- 错误码:`21001` 非成员项目越权(403);401 全局处理
- **响应最小化**:不返回 description/content/test_cases 明细等大字段

#### 2. 快速创建(复用,无新接口)

- 类型:**复用现有**——`POST /api/projects/{pid}/requirements`(R3)、`POST /api/requirements/{rid}/tasks`(R4);project/requirement 由表单选定;**前置校验与项目内完全一致**(同一服务端函数,不因入口放宽)
- 前置校验数据支持:`GET /api/projects/{pid}/requirements?status=approved&size=100`(选 dev 用的需求下拉)、`GET /api/projects/{pid}/requirements`(test 任意需求;release 前端过滤有 passed 测试的需求——**服务端仍最终校验**,前端提示仅为引导)
- 错误码:沿用 R3/R4/R6/R7 各自错误码(如 R4 未绑 token、R7 端口冲突);**新增无**

#### 3. 成员项目下拉数据

- 类型:**复用现有** `GET /api/projects`(R2,当前用户项目列表);前端本地过滤 archived/deleted(服务端该接口已不返回软删项目)

### 权限矩阵

| 角色 | 功能入口 | 按钮/操作 | 数据范围 |
|---|---|---|---|
| owner / editor | 四维菜单 + 快速创建(全部可见) | 查看 + 快速创建 | 成员项目全部数据(不限 created_by) |
| viewer | 四维菜单(可看) | 查看行;**新建按钮隐藏**;写 API 403 | 成员项目全部数据 |
| 超管 | 四维菜单 + 快速创建 | 全部 | **所有 active 项目**(操作经项目内既有接口,审计记 superadmin,R19) |
| 非项目成员 | 菜单可见但空态 | 新建按钮置灰 | 无数据 |

### 服务端行为规格(负向探查结论)

| 行为 | 规格 |
|---|---|
| 数据范围 | `project_id IN (成员项目)` AND `projects.status='active'`(archived/deleted 不出现);超管=全部 active 项目;与 R21 共用集合工具但**不加 created_by 条件**(口径差异:R21=我创建的,R22=成员项目全量) |
| 越权防护 | 显式 `project_id` 非成员 → 403 `21001`;不传时结果集天然过滤;**不因传 id 泄露非成员项目存在性**(统一 403 文案) |
| 分页边界(查询域#7) | page<1 → 按 1;page 超总页 → 返回空 items + 正确 total;page_size≤0 → 按 20;page_size>100 → 截断 100 |
| 排序滥用(查询域#8) | 不开放排序参数,固定 `updated_at DESC`;`q` 参数参数化查询(LIKE 转义 `%`/`_`) |
| 快速创建校验一致 | 走与项目内**同一** service 函数(R3 create / R4 create),校验链:R4 token → R5 需求 approved → R6 存在 dev done → R7 存在 test passed + deploy_port 全平台唯一;任一不满足返回各自既有错误码,**不新增放宽逻辑** |
| 前置校验引导 | 前端在选中项目后拉取需求下拉并按前置过滤/置灰(如"该需求尚无通过的测试任务");服务端校验为唯一事实源,前端提示仅引导 |
| 未绑定 token | 快速创建任务时 R4 校验创建者 token → 未绑定返回 R4 既有错误码 → 前端引导"去个人设置绑定"(与项目内一致) |
| 响应最小化 | 列表不带大字段(见契约);runner 仅 id+name |
| 存量兼容 | 无表变更,不适用 |

### 页面交互流程

- 进入菜单:点击导航二级项 → 拉取项目下拉(复用 `/api/projects`)+ 默认列表第一页 → 渲染
- 筛选:任一筛选控件变化 → page 重置 1 → 重新查询(防抖:仅搜索框 300ms)
- 点击行:需求管理 → `/projects/{pid}/requirements/{rid}`;任务/测试/发布管理 → `/projects/{pid}/tasks/{tid}`(任务工作台);发布管理点部署 URL → 新开 tab 直达部署地址(不进工作台)
- 快速创建-需求:点"新建需求" → 对话框选项目(默认筛选项目)→ 填表 → 点"创建" → 调 R3 接口 → 成功关对话框 → toast"创建成功" → 跳转新需求详情页;失败 → toast 错误(如分支创建失败),对话框不关输入保留
- 快速创建-开发任务:点"新建开发任务" → 选项目 → 需求下拉拉取(仅 approved)→ 选需求填描述 → 点"创建" → 调 R4 接口 → 成功关对话框 → 跳转任务工作台;未绑 token → toast + 引导"去个人设置绑定"(链接跳 `/settings/gitlab`);前置不满足 → 需求下拉该行置灰不可选
- 快速创建-测试/发布任务:同上;发布任务额外填 deploy_port;端口冲突(R7 既有错误码)→ toast"端口已被占用",输入框标红
- 取消/右上角关闭 → 不保存,留在列表页
- 列表刷新时机:进入/筛选/分页时拉取;快速创建成功后**不强制刷新列表**(已跳详情);浏览器返回列表时 react-query 缓存失效重拉
