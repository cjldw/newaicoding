# R31.F3:BUG-049 需求修正——本机快速创建改为 Docker 容器形态(用户指令)

> 状态:✅ 完成(2026-09-24 rd-fix 第 26 轮;真机全链 PASS)
> 模块:M5(backend local_runner_service + runners.py + docker/runner/Dockerfile;R31 核心机制修正)
> 关联:BUG-049;用户指令 2026-09-24(「错了,我说的本机是要在本机上直接运行 docker 容器,不用再复制命令」)

## 需求修正说明

R31 规划期 Q51 以「platform/runner:v1 本机未构建」为由把「容器形态启动」划入"不做什么",选择了 python 子进程形态。用户拍板推翻:**本机快速创建 = 平台直接在本机以 Docker 容器运行 runner**,镜像/env/挂载全自动,零命令复制。子进程形态废弃(存量句柄路径保留兼容,不再新启)。

## 实现要点(local_runner_service.py 重构 + 两个适配点)

1. **spawn_local 重写(容器形态)**:镜像缺失自动构建(`docker build`,Dockerfile 参数化见 3)→ 同名残留容器先清 → `docker run -d`:`--restart unless-stopped` + 挂载 `/var/run/docker.sock`(管理本机任务容器)+ env 四键注入(token 明文只进容器环境)+ `PLATFORM_URL=ws://host.docker.internal:8000/ws/runner`(容器内 127.0.0.1 是容器自身)+ `extra_hosts host-gateway`(Linux 可移植)
2. **容器名确定性**:`qicheng-runner-<runner_id前8>`——平台重启后仍可凭名 stop/rm(替代子进程形态的 PID 句柄,16007 场景大幅收窄)
3. **基础镜像自适应**:Dockerfile `ARG BASE_IMAGE=python:3.12-slim` 参数化;`_ensure_image` 检测本地无 3.12-slim 但有 python:3.10 时自动 `--build-arg` 回退——**docker.io 不可达环境(本机实测拉取超时)零外网依赖**(本地 3.10 镜像 + pypi 直连,R8.F1 已实证 pypi 可达)
4. **停止/删除**:停止=WS 指令优先,降级凭名 `docker stop`;删除链路新增 `remove_local_container`(stop+rm,不存在忽略)
5. **exec cwd 适配(容器形态伴生)**:Runner 容器镜像 WORKDIR=/app,任务终端的 `/workspace/main` 约定不存在——shell-sessions exec 消息显式带 `"cwd":"/app"`,runner 侧 main.py exec 分支透传消息 cwd(缺省仍 /workspace/main,R9 任务终端零变化)
6. 存量兼容:旧子进程句柄(`_local_processes`)路径保留;preflight 三检查维持(依赖探测对容器形态已无意义,保留为兼容旧测试,V2 清理)
