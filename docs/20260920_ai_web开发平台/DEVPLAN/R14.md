## PRD 引用

### 边界定义

- **做什么**:
  - 归档页:时间线视图,展示从需求到发布的全过程关键节点(数据来自 GitLab commit + 任务历史 + 部署记录)
  - AI 生成**归档总结** `docs/{YYYYMMDD}_{descSlug}_archive/summary.md`,**commit 到 master**(此时需求分支已 merge);**归档目录无任务**(系统生成),YYYYMMDD=归档当天日期,descSlug=需求标题 slug 截断 32(Q26)
  - AI 提取**知识条目**:可复用代码片段 / 通用模式 / 工具用法,入库
  - 知识库**项目内 + 平台级**两级,支持搜索
- **不做什么**:
  - 知识条目版本管理
  - 知识条目权限细分(V1 项目内成员可见项目库,平台库全员可见)
  - 知识推荐(仅搜索)

### 字段定义

(KnowledgeEntry 表)

|---|---|---|---|---|

| req_id | ref(R3) | 是 | - | 来源需求 |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 需求 done | 自动生成归档页 + AI 起草总结 commit 到 master `docs/{YYYYMMDD}_{descSlug}_archive/summary.md` | 项目成员可编辑(通过新任务) |
| AI 提取知识 | 默认进**项目级**知识库;owner 可"提升到平台级" | |
| 用户手动新增知识 | 项目内任意成员可建 | |
| 搜索 | 全文 + tag 过滤,项目内 / 平台级 Tab 切换 | |

### 异常与边界场景

- AI 提取的知识默认 **draft 状态**,人审后才 publish
- 归档后需求不可再打开任务(只读)
- 归档总结需修改 → 创建一个新的 dev 任务专门改文档

### 验收标准

1. 需求 done 后归档页可见,summary.md 已 commit 到 master
2. 知识库可搜索到归档的条目
3. 平台级知识需 owner 提升

| 接口范围 | 响应结构约定 |

  ```json
    "tags": ["string"],
  ```


#### 7. 提升到平台级

- **鉴权**:JWT(owner)


### 服务端行为规格

#### 归档(需求 done 后自动触发)

1. 需求下所有发布任务 deployed → 需求 status=done
2. 平台触发归档:
   - AI 读取需求全流程数据(PRD/任务历史/GitLab commits/部署记录)
   - AI 生成归档总结 `docs/{YYYYMMDD}_{descSlug}_archive/summary.md`
   - AI 提取知识条目(代码片段/通用模式/踩坑)
3. 平台 commit summary.md 到 master(用 bot token)
4. 平台写 `knowledge_entries` 表(status=draft)
5. 需求 status=archived

#### 搜索

- MySQL FULLTEXT 全文索引:`MATCH(title, content) AGAINST('{keyword}' IN NATURAL LANGUAGE MODE)`
- 标签过滤:`JSON_CONTAINS(tags, '"{tag}"')`

### 页面结构说明

#### 归档页 `/requirements/{req_id}/archive`

- **区块结构**:
  1. **页面标题**:"需求归档"
  2. **需求信息卡片**:标题 / 状态徽章(archived)/ 创建人 / 创建时间
  3. **时间线视图**:
     - 垂直时间线,每个节点显示:类型图标 + 描述 + 时间戳 + 操作人
  4. **归档总结卡片**:
     - Markdown 渲染 `summary.md` 内容
  5. **关联知识条目列表**(Table):
     - 列:类型徽章 / 标题 / 标签 / 状态徽章(draft=outline/published=success)/ 操作(查看/发布)

#### 知识库页 `/projects/{project_id}/knowledge` 或 `/knowledge`

- **区块结构**:
  1. **页面标题**:"知识库"(项目级)或"平台知识库"
  2. **操作栏**:
     - 左侧:搜索框(placeholder="搜索知识条目...")+ 类型过滤 Select + 标签过滤 Select
     - 右侧:"新建条目"按钮(primary)
  3. **Tab 导航**(仅项目级):项目知识库 / 平台知识库
  4. **知识条目列表**(卡片网格):
     - 每个卡片:类型徽章 + 标题 + 描述(前 100 字)+ 标签徽章 + 状态徽章 + 创建时间
  5. **分页器**:底部居中

### 页面交互流程

#### 归档流程

1. 需求下所有发布任务 deployed → 需求 status=done → 自动触发归档
2. 用户在需求详情页点"查看归档" → 跳转归档页
3. 归档页显示时间线 + 归档总结 + 关联知识条目

#### 搜索知识条目流程

1. 用户在知识库页输入关键词 → 前端防抖 300ms → 调 `GET /api/projects/{pid}/knowledge?q=...`
2. 显示搜索结果

#### 发布知识条目流程

1. 用户在知识条目详情页点"发布"
2. 调 `POST /api/knowledge/{entry_id}/publish`
3. 成功 → 状态变为 published
