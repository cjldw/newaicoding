## PRD 引用

### 边界定义(摘录)

- **做什么**:① 权限判定修复——bot access_level 取 **max(project_access, group_access)**,仍要求 ≥ Maintainer(40);② 失败提示细分五类:「仓库不存在」/「平台 bot 无访问权限」/「bot 权限不足(需 Maintainer)」/「URL 格式非法」/「GitLab 连接失败」,附自助排查指引;追加绑定仓库(add_repo)同口径
- **不做什么**:不做多 GitLab 实例(URL host 不参与查询);不做绑定时分支/commit 校验;不改 auto 建仓流程

### 根因(摘录)

- 平台 gitlab_url(gitlab.zhanqirsj.com)与用户粘贴 IP(47.111.69.64)同一实例;parse_repo_path 仅取 path,帖 IP 无影响
- 缺陷:project_service.py:258 调 `bot_check_repo_permission`(gitlab_service.py:221-228)只读 `permissions.project_access`,bot 靠 group 继承时该值为 null → 误判无权限
- 五条失败路径折叠为同一 2002 文案,排障困难
- 报错文案推定"仓库 URL 无效或无权限"(Q39,rd-dev 修复后以真实地址复现验证)

### 异常与边界场景(摘录 + 挖掘)

- 群组继承多层嵌套:以 GitLab API 返回 permissions 为准(project_access/group_access 两字段),不自行递归
- 修复回归:auto 建仓、追加绑定、需求建分支不受影响
- (挖掘·引用)bot_check_repo_permission 同时服务 create_project(manual)与 add_repo——两处同口径一次修
- (挖掘·安全)错误信息不泄露内部值:bot token/内部 path 不出现在 message;401/403 归并为权限类文案(不区分,防枚举)

### 验收标准(摘录)

1. 帖 `http://47.111.69.64/monorepo/sjzs.git`(实际存在)可成功创建;group 继承权限判定正确
2. 五类错误按实际原因正确区分
3. auto 建仓与追加绑定回归通过
4. 真实失败原因可按提示自行排查
