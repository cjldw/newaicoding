## 根因(双层)

活体取证(铸 superadmin token 直查真实数据):**全部 4 个存活任务 base_branch == work_branch(自指基线)**:

1. **D1 创建链**:`task_service.create_task` L389 `base_branch=base_branch or requirement.req_branch` → 基线=工作分支自己 → `git diff 自己 -- .` 恒空(AI 已 commit 的工作全部不可见)→「变更文件没有对比效果」
2. **D2 端点链**:diff 端点 `base_branch=Query(default="")`(空=只对比未提交,`|| HEAD` 兜底永不触发);changes 端点硬编码 `"master"`——任务记录的 base_branch 两端点都没用

正确基线在项目上就有:`Project.default_branch`(「所有仓库的需求分支从这里切」,requirement_service L216 创建需求分支即从它切出)。

## 修复(F1 治本 + F2 存量自愈,零 runner/零前端改动)

- **F1** `task_service.create_task`:`base_branch or project.default_branch`(新任务生而正确;work_branch 仍=req_branch)
- **F2** `file_service.resolve_task_base_branch(db, container, task_id, explicit)`:显式参 > task.base_branch(非自指时) > 项目默认分支;`task_git_diff`/`task_git_changes` 均接入;changes 端点默认 "master"→""(进入解析)——**存量自指任务展示层即时自愈,无需数据迁移**
- **决策留痕**:test/release 任务创建链的自指(L1249/L1378)不动(创建语义面大),由 F2 运行时回退在 Diff/变更展示自愈;打磨任务(reqCenter)无 Diff Tab 不受此 bug 影响
