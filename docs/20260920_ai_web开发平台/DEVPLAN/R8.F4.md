# R8.F4 — 修复 BUG-036:容器 env 补 LLM_URL 别名 + 平台自定义变量全量注入

> 来源:BUGS.md BUG-036(用户指令 2026-09-23 rd-fix 第 15 轮)
> 状态:✅ fixed(2026-09-23,pytest 13 例 + 真实容器 env 实证)

## 描述(即 bug)

用户要求两点:
1. **容器初始化注入 `LLM_URL` / `LLM_MODEL`**——现状 env 已有 `LLM_BASE_URL`/`LLM_MODEL`(BUG-034 后另有 ANTHROPIC_* 三件套),但容器内脚本/CLI 按 `LLM_URL` 取名取不到;
2. **「平台设置」支持添加多个自定义变量,容器启动后全部注入**——平台级 KV 环境变量(如代理、私有 registry 凭证名等),容器内直接使用。

## 实施轨 + 对应设计稿

- 实施轨:轨 1 — 平台设置页沿用 R24 左导航 4 组结构,**增第 5 组「自定义变量」**(vp 无此原型,组内交互自拟,外壳/按钮/输入类沿用 `.card/.input/.btn` token)
- 入口:`/admin/platform-settings`(PlatformSettings.tsx);容器 env 构建:`task_service` 两处

## 实现要点(根因 + 修复方案)

**现状核实**(分析一手):
- env 构建点仅两处:`task_service.create_polish_task` L89-105、`task_service.start_task` L346-361(均含 GITLAB_TOKEN/GITLAB_INSTANCE_URL/LLM_BASE_URL/LLM_API_KEY/LLM_MODEL/ANTHROPIC_*/TASK_ID/PROJECT_ID/REQ_ID[/PRD_FILE_PATH])
- 平台设置键值体系:`platform_settings_service.SETTING_KEYS` 白名单(str/int/url/domain/secret 四型),`update_settings` 整批校验 UPSERT;GET `get_all_masked` 敏感打码
- Runner→容器 env 透传链已实证可用(BUG-034 修复轮:"新容器 env 三件套+ANTHROPIC_MODEL 齐备"),本点只扩 env 字典,零碰 runner

**改动清单**:

1. **`LLM_URL` 别名**(task_service 两处):env 增加 `"LLM_URL": llm_service.container_base_url(llm_config["base_url"])`,与 `LLM_BASE_URL` 同值(用户指令取名词;保留旧键防回归)
2. **新配置键 `custom_env_vars`**(platform_settings_service):
   - `SETTING_KEYS["custom_env_vars"] = ("envmap", None)`;新 vtype 校验:必须为 `dict[str, str]`;空 dict 合法(=清空);键名匹配 `^[A-Za-z_][A-Za-z0-9_]*$`,键数 ≤ 50,值长度 ≤ 2048;非法 → 2007(文案含违规键名,不含值)
   - **保留名拒写**:与系统注入键冲突(`GITLAB_TOKEN/GITLAB_INSTANCE_URL/LLM_BASE_URL/LLM_API_KEY/LLM_MODEL/LLM_URL/LLM_API_KEY/ANTHROPIC_BASE_URL/ANTHROPIC_API_KEY/ANTHROPIC_MODEL/TASK_ID/PROJECT_ID/REQ_ID/PRD_FILE_PATH` 全集,定义 `RESERVED_ENV_KEYS` 常量于 platform_settings_service)→ 2007"变量名 {k} 为系统保留"
   - 非敏感(不进 SENSITIVE_KEYS):GET 原样回显、容器需要明文、超管设置页可见,密文场景不适用(留痕);审计沿用 `platform_settings.update`(R25 模式 C,detail 只记键列表——沿用"不落值"决策)
3. **注入**(task_service 两处):env 组装改为 `env = { **(await get_setting(db, "custom_env_vars") or {}), "GITLAB_TOKEN": ..., ... }`——自定义变量铺底、系统键后置覆盖(双保险:保存已拒冲突,注入再保序);读取失败/未配置视为 `{}`(不阻断容器启动)
4. **前端 PlatformSettings.tsx 第 5 组「自定义变量」**(`{ key: 'vars', label: '自定义变量', icon: Braces }`):
   - 行编辑 KV 表:`.input` 键 + `.input` 值 + 行删除按钮;底部"添加变量"btn;保存走既有分组 PUT(`custom_env_vars` 单键)
   - 客户端预检:键名正则 + 保留名提示(文案与后端 2007 同口径,防提交后才报错);未编辑敏感性问题不适用(本组无敏感值)
   - 组切换丢弃未保存修改:沿用 R24 useForm reset 机制

## 接口契约

- `PUT /api/admin/platform-settings`:payload 可含 `custom_env_vars: {"KEY":"VALUE",...}`;非法键名/保留名/超限 → 2007;响应沿用 `updated` 键列表(R23 决策)
- `GET /api/admin/platform-settings`:`custom_env_vars` 原样回显(不打码)
- 容器 env 契约新增:`LLM_URL`(= LLM_BASE_URL 同值)+ 全部自定义变量

## 服务端行为规格

| 行为 | 规格 |
|---|---|
| 变量生效时机 | 容器**启动时**读取(每次 start_task/create_polish_task 实时查表),改设置只影响新任务,存量容器不追注 |
