# R2.F9 — 修复 BUG-038:平台设置单键解密失败打挂整页(逐键容错)

> 来源:BUGS.md BUG-038(用户实测 2026-09-23:GET /api/admin/platform-settings 500;rd-fix 第 16 轮)
> 状态:✅ verified(2026-09-23;红测 9 failed→11/11 绿,全量 333/1s/0;真实环境重启后 GET 200 + 3 失效键未配置降级;BUG-038 迁移 ISSUES.md。运维重录项见 ISSUES 条目)
> 分析底稿:.scratch/fix-analysis.md(失效 key 清单/时间线证据链/爆炸半径/回归步骤)

## 描述(即 bug)

超管打开平台设置页,`GET /api/admin/platform-settings` 返回 500(`{"code":500,"message":"服务器内部错误"}`),设置页整体不可用。后端 traceback:`platform_settings_service.get_all_masked → _decode_stored(platform_settings_service.py:183)→ decrypt_token(encryption.py:38)` 抛 `cryptography.exceptions.InvalidTag`,未捕获。

**复现步骤**:超管登录 → GET /api/admin/platform-settings。**期望**:200 + 全部键掩码回显。**实际**(2026-09-23 20:38 基线实证):500。

## 实现要点(根因 + 修复方案)

**根因**:.env 的 PLATFORM_SECRET_KEY 于 09-22 23:03 被轮换(K1→K2),长驻 uvicorn(无 --reload)未重启仍持 K1 写库(直至 09-23 14:45 的 llm_api_key 写入);09-23 20:33 重启加载 K2 后,存量密文全部解不开。只读探查实证:platform_settings 加密行 3/3 失败(gitlab_webhook_secret / gitlab_bot_token / llm_api_key),邻接 users.gitlab_token_encrypted 1 条、model_configs.api_key_encrypted 2 条同根因失效;K1 已不可恢复,失效密文无法解出,只能重录。

**方案(最小侵入,单文件)**:`platform_settings_service._decode_stored` 逐键容错——单键解密失败(InvalidTag 等)视为「已失效需重置」,折叠为 None 并打 warning 日志(键名+失效事实,**不落明文/密文**),不再向 GET 抛异常;消费方经既有 None 语义自然降级为干净业务码(未配置 2001 / 模型配置 13005),不 500。GET 响应形态不变(失效键 = 未配置形态),0 前端改动。范围外:users/model_configs 失效密文属运维重录(重新绑定 GitLab / 重建模型配置),不进本修复点。

## 测试验证逻辑(修复后按此回归)

1. **红测(先失败)**:pytest 新增用例——fixture 用非当前密钥的密文插入 platform_settings 加密行 → GET 断言 200 且该键为未配置形态、其余键正常;解密失败的消费方路径(resolve_config 等)断言干净业务码而非 500。
2. **存量回归**:platform_settings 相关既有测试全绿;后端全量 pytest 无回退(基线 303+1s + 增量3 各点新增)。
3. **真实环境回归**:重启 uvicorn(载当前密钥)→ 超管 token GET /api/admin/platform-settings 断言 HTTP 200;gitlab_webhook_secret/gitlab_bot_token/llm_api_key 三键呈未配置形态;前端设置页可打开(用户侧重录三键后回显正常掩码)。
