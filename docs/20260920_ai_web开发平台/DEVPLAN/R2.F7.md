# R2.F7 — 修复 BUG-UI-063:详情页面包屑补全上级链

> 来源:BUGS.md BUG-UI-063(用户指令 2026-09-23:所有详情页面导航面包屑都带上上级)
> 状态:✅ fixed(2026-09-23;静态核对 9 页 ✅ + 门禁过,verified 待浏览器实渲染;实体名覆盖已接 RequirementDetail,TaskDetail/KBView 兜底增强留痕 ui-check)

## 描述(即 bug)

面包屑组件(`components/Breadcrumb.tsx`,EXACT_MAP 静态路由机制)只覆盖静态列表/管理页;**动态详情路由**(`/requirements/:reqId`、`/tasks/:taskId`、知识库视图、归档、任务子页等)要么无面包屑(仅返回按钮),要么缺上级链。用户要求:详情页导航必须带上级。

## 实现要点(方案)

1. **盘点**:Grep router.tsx 全部含 `:id/:reqId/:taskId/:kbId` 的动态路由 + 各详情页组件当前是否渲染 `<Breadcrumb>`(现状清单,写进 ui-check)
2. **机制扩展**:Breadcrumb 支持动态段——推荐 `crumbs` props 直配(详情页自己传上级链)或组件内 pattern 匹配(前缀段映射);**实体名用页面已加载数据**(requirement.title / task.title / kb.name),无数据时用类型标签(如「需求详情」)兜底,不为此新增 API 调用
3. **各详情页链路**(对齐 vp crumb 链语义):
   - 需求详情 = 项目管理(/projects) / {项目名或「项目」} / {需求名}
   - 任务工作台/子页 = 项目管理 / {项目名或「项目」} / {需求名或「需求」} / 任务 {标题或 id}
   - 归档页 = {上级需求链} / 归档
   - 知识库视图 = 知识条目(/knowledge) / {库名或「知识库」}
   - 项目详情本身 = 项目管理(/projects) / {项目名}(若已有则核对补全)
4. **样式**:沿用现有 Breadcrumb 渲染(父级 `<a>` 可点击、末级 `<b>`,对齐 R19.F3 定稿规则);不动路由/数据流/业务逻辑
