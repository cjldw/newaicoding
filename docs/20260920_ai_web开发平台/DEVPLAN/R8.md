## PRD 引用

### 边界定义

- **做什么**:
  - 镜像 `platform/devbox:v1`(基于 `mcr.microsoft.com/devcontainer/universal:linux` + Claude CLI + 高频包预装,详见 ARCH D10)
  - 启动时 `git clone {gitlab_repo_url} /workspace/{path}`(用 R1 的用户 token,通过环境变量注入)+ `git checkout {base_branch}` + `git checkout -b {work_branch}`(若 ≠ base)
  - 端口约定:前端 dev server **5173**、后端服务 **8000**;Runner 上映射到**随机宿主机端口**(网关转发用)
  - 任务结束(成功/失败/取消/超时)**Runner 销毁容器**
  - **例外**:R7 发布任务 deployed 后容器**保持运行**(在**专用 deploy Runner** 上),直到用户下线
- **不做什么**:
  - 自定义镜像(V1 统一镜像)
  - docker-compose 多容器
  - SSH 直连
  - 宿主机挂载(V1 数据全走 GitLab,容器是纯计算资源)
  - 内嵌 MySQL/Redis(若需要,引导用户在容器内自行 `apt install` 或 docker 多容器,V2 再议)

| created_at / destroyed_at | datetime | - | - | |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 拉起 | 调度器选 Runner(最少负载)→ Runner 收到指令 → `docker run -p {随机}:5173 -p {随机}:8000 -e ...` + git clone + checkout → 上报容器 id 与端口映射到平台 | running |
| 任务结束 | 销毁前**强制 push 未 push 的 commit** → Runner `docker stop + rm` | destroyed |
| 崩溃 | Runner 自动 restart ≤ 3 次 → failed,任务标记 failed,Runner 清理 | destroyed |
| 项目删除/归档 | 该项目所有容器 stop + rm(跨所有 Runner) | destroyed |
| 部署中容器 | 任务 done 后容器**保留运行**在 **deploy Runner** 上,直到用户"下线"或"项目归档" | running |
| Runner offline | Runner 上的容器**继续跑**(Runner 是薄代理),平台标记容器"Runner offline";Runner 恢复后重新上报状态 | - |

### 异常与边界场景

- 单用户**同时运行容器 ≤ 5**(含部署中)
- 平台总容器数上限(平台配置,默认 50,跨所有 Runner)
- git clone 失败(token 失效)→ 容器创建失败,引导重新绑定 R1
- 容器销毁前 push 失败(GitLab 不可用)→ Runner 保留容器 30 分钟,平台重试 push;仍失败则告警 + 销毁(代码丢失)
- **Runner 负载不均衡**:调度器每次选最少负载 Runner;若所有 Runner 负载相同,随机选
- **部署任务固定在 deploy Runner**(R16 标记 `role=deploy` 的 Runner)

### 验收标准

1. 任务创建后容器 30s 内在某个 Runner 上拉起
2. 任务结束后容器被销毁
3. 部署中的容器不被销毁,且在 deploy Runner 上
4. 销毁前未 push 的 commit 被强制 push
5. Runner offline 时容器继续跑,Runner 恢复后状态同步正确

### 服务端行为规格

#### 启动容器(平台 → Runner)

1. 平台调度器选 Runner(最少负载 + role 匹配)
2. 平台通过 WebSocket 发送消息给 Runner:
   ```json
   {
     "type": "start_container",
     "task_id": "uuid",
     "image": "platform/devbox:v1",
     "env": {
       "LLM_BASE_URL": "...",
       "LLM_API_KEY": "...",
       "GITLAB_TOKEN": "...",
       "GIT_USER_NAME": "...",
       "GIT_USER_EMAIL": "...",
       "TASK_ID": "...",
       "PROJECT_ID": "...",
       "REQ_ID": "..."
     },
     "ports": [5173, 8000],
     "cpu_limit": "2c",
     "mem_limit": "4g",
     "disk_limit": "10g",
     "repos": [
       {"url": "https://gitlab.example.com/group/main.git", "path": "/workspace/main", "branch": "req-123"},
       {"url": "https://gitlab.example.com/group/test.git", "path": "/workspace/tests/test", "branch": "req-123"}
     ]
   }
   ```
3. Runner 收到消息后:
   - 分配随机宿主机端口(范围 20000-29999)
   - 调 Docker SDK `docker run -p {random1}:5173 -p {random2}:8000 -e ...`
   - 容器启动后执行:`git clone` + `git checkout` + `git checkout -b`(若需要)
   - 配置 Nginx 本地代理(把宿主机端口转发到容器端口)
   - 回报平台:
     ```json
     {
       "type": "container_started",
       "task_id": "uuid",
       "container_id": "docker_id",
       "ports": {
         "5173": 20001,
         "8000": 20002
       }
     }
     ```
4. 平台更新 `containers` 表(status=running, runner_host_port_*)

#### 停止容器(平台 → Runner)

1. 平台通过 WebSocket 发送消息:
   ```json
   {
     "type": "stop_container",
     "container_id": "docker_id"
   }
   ```
2. Runner 收到消息后:
   - 销毁前**强制 push 未 push 的 commit**(进入容器执行 `git push`)
   - 调 Docker SDK `docker stop + docker rm`
   - 清理 Nginx 配置
   - 回报平台:
     ```json
     {
       "type": "container_stopped",
       "container_id": "docker_id"
     }
     ```
3. 平台更新 `containers` 表(status=destroyed, destroyed_at=now())

#### 容器事件监听(Runner → 平台)

1. Runner 监听本地 Docker events:
   ```python
   import docker
   client = docker.from_env()
   for event in client.events():
       if event['Type'] == 'container' and event['Action'] in ['start', 'die', 'oom']:
           # 回报平台
   ```
2. Runner 回报平台:
   ```json
   {
     "type": "container_event",
     "event": "die",
     "container_id": "docker_id",
     "exit_code": 1
   }
   ```
3. 平台更新 `containers` 表(status=failed)

## 完成判据

### 功能

1. ✅ 任务创建时,平台调度器选 Runner(最少负载 + role 匹配)
2. ✅ Runner 收到启动指令后,能拉起容器(`docker run` + `git clone` + `git checkout`)
3. ✅ Runner 能分配随机宿主机端口,并配置 Nginx 本地代理
4. ✅ Runner 能回报容器 id 与端口映射到平台
5. ✅ 任务结束时,Runner 能销毁容器(`docker stop + rm`)
6. ✅ 销毁前能强制 push 未 push 的 commit
7. ✅ Runner 能监听容器事件(start/die/OOM)并回报平台
8. ✅ 部署任务固定在 deploy Runner 上
9. ✅ 部署中的容器不被销毁

### 异常场景

1. ✅ git clone 失败(token 失效):容器创建失败,任务标记 failed
2. ✅ 容器崩溃:Runner 自动 restart ≤ 3 次,仍失败则标记 failed
3. ✅ Runner offline:容器继续跑,平台标记"Runner offline"
4. ✅ Runner 恢复:重新上报容器状态,平台对账
