## PRD 引用

### 边界定义

- **做什么**:
  - **任务内模式**:
    - 文件树(增删改查/重命名/拖拽)
    - Monaco(语法高亮/查找替换/多光标/minimap)
    - 文件保存即写入容器(500ms 防抖)
    - **AI 修改实时刷新**(文件 watcher + 编辑器平滑更新)
    - **任务级 Diff 视图**:列出本任务 git diff 涉及文件,逐文件 diff,可"接受/拒绝"(拒绝=回滚该文件)
  - **项目模式**:
    - 通过 GitLab API 浏览任意分支的文件树与文件内容
    - 只读,不可编辑;不可创建/删除/重命名
- **不做什么**:
  - 多人实时协同(光标共享/CRDT)—— V1 假设任务**单执行者**,人审阅 AI 而非与人协同
  - LSP/智能补全/跳转定义
  - Git 可视化操作面板(stage/commit/push 走终端)
  - 二进制预览(图片除外)
  - 大文件编辑(> 2MB 只读)

### 字段定义

沿用文件树常规字段(path/type/size/mtime),无需持久化(任务模式读容器,项目模式读 GitLab API)

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 项目模式打开文件 | 调 GitLab API `GET /projects/:id/repository/files/:path?ref={branch}` → 显示 | 只读 |
| 任务模式打开文件 | 从容器读 → 显示 | 可编辑 |
| AI 修改了打开的文件 | watcher 触发 → 编辑器更新 + toast"AI 修改了此文件" | |
| 用户编辑与 AI 修改冲突 | **以容器为准**,提示"AI 已修改,已为你重新加载" | |
| 任务结束 → Diff 视图 | 列出本任务 git diff 文件,逐文件 accept/reject | reject = `git checkout HEAD@{task_start} -- {file}` |
| 文件被外部删除 | 编辑器标记,可另存 | |

### 异常与边界场景

- 多人打开同一文件:不冲突(各自编辑,后保存覆盖前者;V1 接受)
- GitLab API 超时 → 显示"无法加载,请稍后重试"
- 文件 watcher 失效 → 手动刷新按钮

### 验收标准

1. 项目模式能从 GitLab API 浏览任意分支文件
2. 任务模式 AI 修改的文件实时刷新可见
3. Diff 视图能列出任务所有改动并可单独回滚
4. 项目模式只读,任何写操作被禁

## 实现要点

### 数据模型变更

(无需持久化,文件树/内容实时读容器或 GitLab API)

### 接口契约

#### 1. 项目模式:文件树

- **路径**:`GET /api/projects/{project_id}/files`
- **鉴权**:JWT(项目成员)
- **请求**:
  - Query 参数:`branch`(默认 master),`path`(默认 /)
- **响应**:
  ```json
  {
    "code": 0,
    "data": {
      "items": [
        {
          "path": "src/main.py",
          "type": "file",
          "size": 1234,
          "mtime": "datetime"
        }
      ]
    },
    "message": "ok"
  }
  ```

#### 2. 项目模式:文件内容

- **路径**:`GET /api/projects/{project_id}/files/content`
- **鉴权**:JWT(项目成员)
- **请求**:
  - Query 参数:`branch`,`path`
- **响应**:
  ```json
  {
    "code": 0,
    "data": {
      "path": "src/main.py",
      "content": "print('hello')",
      "encoding": "utf-8"
    },
    "message": "ok"
  }
  ```

#### 3. 任务模式:文件树

- **路径**:`GET /api/tasks/{task_id}/files`
- **鉴权**:JWT(项目成员)
- **请求**:
  - Query 参数:`path`(默认 /workspace/main)
- **响应**:同项目模式

#### 4. 任务模式:文件内容(读)

- **路径**:`GET /api/tasks/{task_id}/files/content`
- **鉴权**:JWT(项目成员)
- **请求**:
  - Query 参数:`path`
- **响应**:同项目模式

#### 5. 任务模式:文件内容(写)

- **路径**:`PUT /api/tasks/{task_id}/files/content`
- **鉴权**:JWT(editor 以上)
- **请求**:
  ```json
  {
    "path": "src/main.py",
    "content": "print('hello world')"
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "message": "保存成功"
  }
  ```

#### 6. 任务模式:文件操作(增删改)

- **路径**:`POST /api/tasks/{task_id}/files/operations`
- **鉴权**:JWT(editor 以上)
- **请求**:
  ```json
  {
    "operation": "create|delete|rename",
    "path": "src/main.py",
    "new_path": "src/main2.py"
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "message": "操作成功"
  }
  ```

#### 7. 任务模式:Diff 视图

- **路径**:`GET /api/tasks/{task_id}/files/diff`
- **鉴权**:JWT(项目成员)
- **响应**:
  ```json
  {
    "code": 0,
    "data": {
      "files": [
        {
          "path": "src/main.py",
          "status": "modified",
          "diff": "@@ -1,1 +1,1 @@\n-print('hello')\n+print('hello world')"
        }
      ]
    },
    "message": "ok"
  }
  ```

#### WebSocket 文件 watcher 频道

- **路径**:`/ws/tasks/{task_id}/files`
- **鉴权**:JWT(项目成员)
- **消息协议**:
  - Runner → 平台 → 前端:
    ```json
    {"type": "file_changed", "path": "src/main.py", "content": "..."}
    {"type": "file_deleted", "path": "src/main.py"}
    ```

### 权限矩阵

| 操作 | owner | editor | viewer |
|---|---|---|---|
| 项目模式查看文件 | ✅ | ✅ | ✅ |
| 任务模式查看文件 | ✅ | ✅ | ✅ |
| 任务模式编辑文件 | ✅ | ✅ | ❌ |
| 任务模式文件操作(增删改) | ✅ | ✅ | ❌ |

### 服务端行为规格

#### 项目模式:文件树/内容

1. 平台调 GitLab API:`GET /api/v4/projects/{repo_id}/repository/tree?ref={branch}&path={path}`
2. 返回文件树

#### 任务模式:文件树/内容(读)

1. 平台通过 Runner WebSocket 发送:
   ```json
   {
     "type": "read_file",
     "container_id": "docker_id",
     "path": "/workspace/main/src/main.py"
   }
   ```
2. Runner 读容器文件 → 回报平台 → 平台返回前端

#### 任务模式:文件内容(写)

1. 平台通过 Runner WebSocket 发送:
   ```json
   {
     "type": "write_file",
     "container_id": "docker_id",
     "path": "/workspace/main/src/main.py",
     "content": "..."
   }
   ```
2. Runner 写容器文件 → 回报平台 → 平台返回前端

#### 文件 watcher

1. Runner 用 `watchdog` 监听容器内 `/workspace` 目录
2. 文件变更 → Runner 发送:
   ```json
   {
     "type": "file_changed",
     "container_id": "docker_id",
     "path": "/workspace/main/src/main.py"
   }
   ```
3. 平台转发到前端(通过 `/ws/tasks/{tid}/files` 频道)

  3. **顶部分支选择器**:Select(默认 master)

### 页面交互流程

#### 任务模式:打开文件流程

1. 用户在文件树点击文件 → 前端调 `GET /api/tasks/{tid}/files/content?path=...`
2. 成功后 Monaco 显示文件内容
3. 用户编辑 → 500ms 防抖 → 调 `PUT /api/tasks/{tid}/files/content`
4. AI 修改了打开的文件 → 文件 watcher 触发 → 前端收到 `file_changed` 消息 → 编辑器平滑更新 + toast"AI 修改了此文件"

#### 任务模式:Diff 视图流程

1. 任务结束后,用户点"查看 Diff"
2. 前端调 `GET /api/tasks/{tid}/files/diff`
3. 显示 Diff 视图(逐文件 diff)
4. 用户点"接受" → 无操作(已 commit)
5. 用户点"拒绝" → 调 `POST /api/tasks/{tid}/files/operations`(operation=revert,path=...)→ Runner 在容器内执行 `git checkout HEAD@{task_start} -- {file}`
