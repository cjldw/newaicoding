## 服务端行为规格(含负向探查结论)

| 行为 | 规格 |
|---|---|
| 接入模式 A | service 函数有 db + operator(User):`await audit_write(db, operator, action_type, ...)` 在 flush 前调用(同事务,失败不阻塞——audit_write 已吞异常) |
| 接入模式 B | 无事务上下文(登录分支/WS handler):`spawn_audit_write(session_factory, {"user_id","role"}, ...)`,独立会话 + 3 次重试 |
| 接入模式 C | operator 仅有 str user_id(平台设置/Runner service):**在 API 层**用 current_user 调 audit_write(service 签名不改);reset_token/disable/delete 无 operator 参数的,同样上移 API 层 |
| 登录失败·用户不存在 | AuditLog.user_id 非空约束 → 用全零占位 uuid + detail.reason="user_not_found";或列为可空(alermigration,避免则用占位)——**rd-dev 二选一,默认占位**(不改表) |
| 系统事件 | sweep_offline / sweep_timeouts:operator 占位全零 uuid,operator_role="system",detail 带 reason;不记 ip |
| ip 获取 | API 层从 request.client.host(或现有依赖)取;spawn 场景作为参数传入 |
| detail 脱敏 | 手机号 mask_phone(前3+****+后4);**不记** api_key/token/密码/邀请 token 明文(invitation.create 只记 invited_phone 与有效期天数) |
| 事务影响 | audit_write 异常吞掉不回滚业务(现状);spawn 失败重试后告警(现状)——本点回归断言其不被破坏 |
| 响应最小化 | 审计查询响应不含用户密码/token 等字段(现状);detail 原样展示给超管(内含值已脱敏) |
| 幂等 | 登录失败审计随每次失败各记一条(非去重)——审计口径,允许重复 |
| 不适用 | 状态机/删除保护/取消补偿/时效/频控/快照(纯追加写,无业务状态) |
