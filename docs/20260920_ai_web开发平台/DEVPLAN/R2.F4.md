# R2.F4 修复:平台设置"测试连接"结果误标成功(BUG-010)

> 状态:✅(2026-09-22 rd-fix 第 4 轮完成:tsc 零错误;运行时实测失败场景渲染为失败样式,截图 fix-test-connection.png;verified 迁移 ISSUES.md)

## 描述(bug)

用户报告"接口 /api/admin/platform-settings/test-connection 提示 401,有 token 也 401"。

**实测澄清(2026-09-22)**:平台接口本身 HTTP 200 + code=0,鉴权正常。401 来自 **GitLab 侧**——接口用 DB **已保存**的 gitlab_url + bot_token 调 GitLab `GET /api/v4/version`,token 无效时透传 `"GitLab 返回 401,请检查 token 与地址"`(data.ok=false)。

**前端真 bug**:`PlatformSettings.tsx` handleTestConnection 把响应 `ok` 硬编码为 `true`,GitLab 连通失败也按成功样式渲染,误导用户以为平台鉴权出了问题。

## 实现要点

`frontend/src/pages/admin/PlatformSettings.tsx` handleTestConnection:

```tsx
const res = await api.post<{ ok: boolean; message: string }>('/admin/platform-settings/test-connection')
// 修复:以接口返回的 ok 为准(GitLab 连通失败时 data.ok=false,不得误标成功)
setTestResult({ ok: res.data?.ok === true, message: res.data?.message ?? (res.data?.ok ? '连接成功' : '测试失败') })
```

- catch 分支(HTTP/网络错误)不动
- 接口契约不动(POST 无 body,测已保存配置——R2 分片既定)

## 测试验证逻辑(修复后回归)

1. `npx tsc --noEmit` 零错误
2. 运行时(Playwright 或 curl):当前已保存 token 被 GitLab 拒(401)→ 页面点击"测试连接"渲染**失败样式**(ok=false + "GitLab 返回 401…"文案)
3. 平台接口自身行为不变:curl 带 token 仍 HTTP 200 + code=0
