# R19.F3 修复:admin 面包屑统一两级且父级可点击(BUG-UI-001 重开)

## 状态:⬜

## 描述(bug)

BUG-UI-001(重开,用户拍板推翻此前"不修"结论):页面面包屑要保持一致——"Runner 管理"页面包屑只有一级(其余 admin 页均为两级),且所有 admin 页父级"平台管理"渲染为 `<b>` 不可点击,与 /manage/* 页(父级 `<a>` 可点击)不一致。

**运行时证据(2026-09-22 Playwright)**:
- /admin/runners topbar crumb = `Runner 管理`(仅 1 级)
- /admin/users topbar crumb = `平台管理 / 用户管理`,父级为 `<b>` 不可点击
- 正确示范 /manage/requirements = `<a href="/">工作台</a> / <a href="/projects">项目管理</a> / <b>需求管理</b>`

**用户决策**:统一为 /manage/* 模式——父级一律 `<a>` 可点击,当前页(末级)`<b>`。此决策优先于 vp 原型(vp 中 admin 页父级本为 `<b>`)。

## 实现要点(根因 + 修复方案)

**根因**:`frontend/src/components/layout/Breadcrumb.tsx` EXACT_MAP 中:
1. `'/admin/runners'` 条目只有 `[{ label: 'Runner 管理' }]`,缺父级;
2. 其余 4 个 admin 路由的"平台管理"对象无 `href` 字段,渲染逻辑(`item.href && !isLast ? <Link> : <b>`)走 `<b>` 分支。

**修复**(只改 EXACT_MAP 数据,渲染逻辑不动):
```tsx
'/admin/runners': [{ label: '平台管理', href: '/admin/platform-settings' }, { label: 'Runner 管理' }],
'/admin/users': [{ label: '平台管理', href: '/admin/platform-settings' }, { label: '用户管理' }],
'/admin/audit-logs': [{ label: '平台管理', href: '/admin/platform-settings' }, { label: '审计日志' }],
'/admin/platform-settings': [{ label: '平台管理', href: '/admin/platform-settings' }, { label: '平台设置' }],
'/admin/skills': [{ label: '平台管理', href: '/admin/platform-settings' }, { label: 'Skills 管理' }],
```
父级 href 统一指向 `/admin/platform-settings`(平台管理组落地页);platform-settings 页自身的父级 crumb 指向本页属可接受的边界情况。

## 测试验证逻辑(修复后按此回归)

Playwright 断言 5 个 admin 路由(含 /admin/runners):
1. `.crumb a` 首个元素文本 = `平台管理`,href = `/admin/platform-settings`
2. `.crumb b` 末级文本 = 各页标题(不可点击)
3. `.crumb .sep` = `/`
4. 对照组:/projects 仍为单级 `<b>项目列表</b>`(不受影响)

## 实施轨 + 对应设计稿

## 渲染核对期望(修复重点:BUG-UI-001 面包屑一致性与 Runner 管理层级)

| crumb 父级 | 标签/文本/href | `<a>平台管理</a>` → /admin/platform-settings | 全部 5 个 admin 路由 |
