## PRD 引用

### 边界定义

- **做什么**:
  - 登录后默认首页(`/`);左侧导航第一项"工作台"
  - 展示与当前用户**相关的**(**created_by=本人**,Q21)需求/开发任务/测试任务/发布任务四类数据的**统计卡片**(按状态分布)+ 每类**最近 5 条**列表(Q24),点击进入详情

  | 卡片 | 统计维度 | 数据来源 |
  |---|---|---|
  | 需求 | 按 R3 status 分布 | requirements where created_by=me |
  | 开发任务 | 按 R4 status 分布 | tasks(type=dev) where created_by=me |
  | 测试任务 | 按 R4 status 分布 | tasks(type=test) where created_by=me |
  | 发布任务 | 按 R4 status 分布 | tasks(type=release) where created_by=me |

  - 注:打磨任务(type=requirement)不单列,其进展随需求维度体现
  - 每类"最近 5 条"列表:标题 / 所属项目 / 状态 / 更新时间,按 updated_at 倒序;点击行跳转项目内详情页
  - 空态:无数据显示引导文案;无项目时引导"创建项目或等待邀请"
- **不做什么**:
  - 不做实时自动刷新(进入页面拉取一次;变更感知走 R18 toast/站内信)
  - 不做卡片自定义 / 拖拽布局 / 趋势图表
  - 不做"指派给我的"(V1 无指派概念,范围外)

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 登录成功 | 跳转 Dashboard(R1 已改) | 工作台 `/` |
| 点击卡片 | 跳转对应四维管理菜单(R22) | R22 对应菜单 |
| 点击列表行 | 跳转项目内需求详情 / 任务工作台 | 详情 |
| 用户被移出项目 | 该项目历史数据不再出现(按成员资格过滤) | |

### 异常与边界场景

- 成员资格变更即时影响可见范围(下次拉取生效)
- 统计与列表允许毫秒级不一致(同窗口查询,不做事务绑定)
- (挖掘)created_by=me 但项目 archived/deleted:数据**不出现**(与 R22"归档/软删项目数据不出现"口径一致)

### 验收标准

1. 登录后默认进入 Dashboard
2. 卡片数字与四维菜单按"我创建的"口径统计一致
3. 每类最近 5 条可点击进入正确详情页
4. 空数据/无项目空态引导正确

## 实现要点

### 数据模型变更

无新表(D19:无新表聚合查询)。聚合 SQL 直查 `requirements` / `tasks` / `project_members` / `projects`。

### 枚举与字典映射

| 枚举/字典 | 值(节选) | 前端文案 | 标签/颜色样式 | 数据来源 |
|---|---|---|---|---|
| 需求 status | draft/polishing/reviewing/approved/in_progress/done/archived/rejected | 草稿/打磨中/评审中/已批准/进行中/已完成/已归档/已取消 | outline/warning/warning/primary/primary/success/outline/danger | R3 常量表(复用) |
| 任务 status | pending/running/cases_review/passed/failed/deploying/deployed/cancelled | 待执行/执行中/用例评审/通过/失败/部署中/已部署/已取消 | outline/primary/warning/success/danger/primary/success/outline | R4 常量表(复用) |

### 接口契约

**接口契约** 总览——**响应结构**统一外层 `{"code": 0, "data": ..., "message": "ok"}`(错误时 `code` 为业务错误码、`message` 为提示文案);字段级结构以下方各接口小节的请求/响应示例为准:

| 接口范围 | 响应结构约定 |
|---|---|
| 本需求点全部接口(下方小节逐一列出) | 统一外层 `{code, data, message}`;分页接口 `data` 含 `{items, total}` |

#### 1. 工作台汇总

- 类型:新建
- 路径与方法:`GET /api/dashboard/summary`
- 鉴权:登录态(JWT);数据范围自动过滤(成员项目;超管=全部 active 项目,R19)
- 请求参数:无
- 响应结构:

| 字段 | 类型 | 说明 |
|---|---|---|
| requirements | object | `{total, by_status: {draft: n, polishing: n, ...}(R3 状态全集,0 也返回), recent: [≤5]}` |
| dev_tasks / test_tasks / release_tasks | object | 同构;`by_status` 为 R4 状态全集(按 type 过滤后的分布);recent ≤5 |
| recent[] | object | `{id, title, project: {project_id, name}, status, updated_at}`(按 updated_at 倒序,固定 5 条,无分页参数) |

- 示例:
  ```json
  {
    "code": 0,
    "data": {
      "requirements": {
        "total": 12,
        "by_status": {"draft": 2, "polishing": 1, "reviewing": 0, "approved": 3, "in_progress": 4, "done": 1, "archived": 1, "rejected": 0},
        "recent": [
          {"id": "uuid", "title": "用户登录优化", "project": {"project_id": "uuid", "name": "主站"}, "status": "in_progress", "updated_at": "2026-09-21T10:00:00"}
        ]
      },
      "dev_tasks": {"total": 8, "by_status": {"pending": 1, "running": 2, "cases_review": 0, "passed": 2, "failed": 1, "deploying": 0, "deployed": 2, "cancelled": 0}, "recent": ["...≤5 条同构"]},
      "test_tasks": {"total": 3, "by_status": {"...": 0}, "recent": []},
      "release_tasks": {"total": 2, "by_status": {"...": 0}, "recent": ["..."]}
    },
    "message": "ok"
  }
  ```
- 过滤口径(服务端):`created_by = 当前用户` **且** `project_id ∈ 成员项目集合` **且** `projects.status = 'active'`(archived/deleted 项目数据不出现)
- 错误码:401 未登录(全局处理);无业务错误码
- **负向探查(查询域)**:固定 recent 5 条、无分页参数 → 分页边界不适用;无排序入参(固定 updated_at DESC)→ 排序滥用不适用
- **响应最小化**:recent 仅返回列表必需字段,不携带 description/acceptance_criteria 等大字段

### 权限矩阵

| 角色 | 功能入口 | 按钮/操作 | 数据范围 |
|---|---|---|---|
| 任意登录用户 | `/` 工作台 | 只读(卡片点击/行点击跳转) | created_by=me 且成员项目;超管=created_by=me 且全部 active 项目(**超管 Dashboard 仍按"我创建的"口径,不放大**,Q21) |

### 服务端行为规格(负向探查结论)

| 行为 | 规格 |
|---|---|
| 数据范围 | `created_by=me` AND `project_id IN (成员项目)` AND `projects.status='active'`;成员资格变更后**下次拉取生效**(无推送) |
| 口径一致性 | 与 R22 四维菜单同一"成员项目 + 状态过滤"工具函数,保证"卡片数字与四维菜单口径一致"(验收 2);单条 SQL 窗口内完成,统计与 recent 允许毫秒级不一致(PRD) |
| by_status 完整性 | 返回状态全集(值为 0 也返回),前端不处理缺键(枚举完整性) |
| 性能 | 单次请求 ≤ 8 条聚合 SQL(4 类 × 统计+recent);单用户 ≤50 项目,量级可控(D19) |

### 页面结构说明

#### Dashboard `/`

- **区块结构**(从上到下):
  1. **页头**:问候语"工作台"(text-2xl/600)
  2. **统计卡片区**(grid 4 列,gap 16px):每卡片=图标 + 类别名 + total(text-3xl/600)+ 状态分布(横向 mini 徽章组,仅显示值>0 的状态,格式"状态文案 ×N");点击卡片整体可点(跳 R22 对应菜单,hover `bg-surface-strong`)
  3. **四组列表区**(grid 2 列,gap 16px,每格一个 `.card`):卡片头=类别名 + "查看全部"链接(跳 R22 对应菜单);列表 ≤5 行,每行=标题(溢出省略)+ 项目名(text-muted)+ 状态徽章 + 更新时间(相对时间,如"3 小时前");行 hover `bg-surface-strong`,点击跳详情
  4. **空态**:某类无数据 → 该卡片列表区显示引导文案("暂无需求,去创建第一个需求");用户无任何项目 → 页面级空态(插图 + "创建项目或等待邀请" + "新建项目"按钮跳 `/projects/new`)
- **本需求点改动范围**:全新页面;`/` 路由从无到有

### 页面交互流程

- 登录成功 → 跳 `/` → 拉取 `GET /api/dashboard/summary`(react-query,一次性)→ 渲染
- 点击需求卡片 → 跳 `/manage/requirements`(R22);点击开发/测试/发布卡片 → 跳 `/manage/tasks|tests|releases`(R22)
- 点击需求行 → 跳 `/projects/{pid}/requirements/{rid}`;点击任务行 → 跳 `/projects/{pid}/tasks/{tid}`(任务工作台)
- 点击"查看全部" → 同卡片目标
- 无项目用户 → 页面级空态 → 点"新建项目" → `/projects/new`(R2)
- 401(会话过期)→ 全局拦截跳登录(与 R1 一致)
