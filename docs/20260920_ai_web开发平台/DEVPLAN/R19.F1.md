# R19.F1 修复:超管角色字段传递与前端恢复(BUG-001)

## 状态:⬜

## 描述(bug)

BUG-001:用户是 superadmin(DB `aicoding.users` role='superadmin' 已核实),登录后左侧导航看不到「平台管理」分组(平台设置 / Runner 管理 / 用户管理 / 审计日志),即看不到平台设置等超管可以设置的信息。

**根因(双层缺陷,证据见 `.scratch/fix-analysis.md`)**:
1. **主因(后端序列化边界丢 role)**:`LoginUserInfo`(`backend/app/schemas/auth.py`)与 `UserProfileResponse`(`backend/app/schemas/user.py`)未声明 `role` 字段 → FastAPI 序列化丢弃 → 前端 `user?.role === 'superadmin'`(`frontend/src/components/layout/MainLayout.tsx:83`)永远 false → 导航分组永不渲染。
2. **次因(前端 user 不恢复)**:`frontend/src/stores/authStore.ts` 的 `user` 仅存内存,localStorage 只存 token;app init 不调 `usersApi.getMe()` → 刷新页面 user=null。

## 实现要点(根因 + 修复方案)

### 后端(2 个 schema + 2 个构建处)
1. `backend/app/schemas/auth.py` `LoginUserInfo` 补 `role: str = "user"`(平台角色 superadmin/user)
2. `backend/app/services/auth_service.py` 构造 `LoginUserInfo(...)` 时传 `role=user.role`
3. `backend/app/schemas/user.py` `UserProfileResponse` 补 `role: str = "user"`
4. `backend/app/api/users.py` `GET /users/me` 构造处传 `role=current_user.role`
5. 顺带对齐:`UserProfileResponse` 前端类型声明了 `is_active`/`created_at` 而后端不返回——以后端为准,前端 `UserInfo` 类型移除不存在的字段或在后端补齐(择一,保持类型诚实;改动最小优先)

### 前端(恢复 user)
1. app init:有 token 且 user 为 null 时调 `usersApi.getMe()` 恢复 user(挂在已登录外壳/守卫层的 useEffect);401 时登出跳登录页
2. `frontend/src/api/auth.ts` `UserInfo` 类型与后端实际响应对齐(role 必有;清掉后端不返回的字段)
3. MainLayout 渲染条件 `user?.role === 'superadmin'` 不动(本身正确)

### 约束
- 最小改动,不动 `require_superadmin` Guard 与任何权限逻辑(后端 Guard 层工作正常)
- 遵循代码纪律:复杂逻辑留注释;if/else 尽量早 return
