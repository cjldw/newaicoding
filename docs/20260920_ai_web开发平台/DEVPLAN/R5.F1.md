# R5.F1 — 修复 BUG-032/033:对话链路 Runner 连接稳定性(掉线根治 + 快速失败)

> 来源:rd-fix 第 14 轮 | BUG:BUG-032(主,对话不可用)、BUG-033(次,files/changes 间歇 500,并入修复)
> 状态:⬜ 进行中
> 分析底稿:`.scratch/fix-analysis.md`(一手时间线与掉线机制链)

## 描述(即 BUG)

任务工作台"对话"不可用:发送后卡"发送中"最长 10 分钟、消息不入库、平台报 9001 "Runner offline"(runner 实际 online);伴随 `GET /files/changes` 间歇 500。用户报障原话"对话部分没有用"。

## 根因(四层,详见 fix-analysis.md)

1. **事件循环阻塞**:runner `exec_tool` 处理(main.py:259)同步调 `claude_prompt`(container_manager.py:362 阻塞 docker exec,minute 级)→ ping/pong 饿死 → uvicorn 服务端杀连接(RST);heartbeat 同理饿死 → DB 心跳过期 → `sweep_offline`(runner_service.py:317)把活连接从内存注销 → dispatch 9001
2. **并发 send 无锁**:runner 5 路 send(heartbeat/event/prober/receive_loop 回包/两条 `run_coroutine_threadsafe` 线程泵)直接 `ws.send()`,websockets 不允许并发 → 帧交错 → 服务端 RST
3. **平台死等**:`request_runner`(runner_service.py:128-139)在死连接上 send 静默成功(本地缓冲),future 永不结算 → 600s 超时兜底 → 用户侧"发送中"卡 10 分钟
4. **先落库后校验**:`send_message`(task_service.py:395-411)先 flush user 消息再查 runner,失败 BizError 回滚 → 消息不入库

## 实现要点

### runner/main.py
- [ ] 模块级 `_send_lock = asyncio.Lock()`(惰性创建于主循环);`send()` 内 `async with _send_lock` 串行化——全部 5 路 send 收敛到这一把锁
- [ ] `exec_tool` 的 `claude_prompt` 改 `await asyncio.to_thread(...)` —— 循环不再被阻塞,ping/heartbeat 持续
- [ ] `exec_tool` 成功/失败两处 `send_result` 包 try/except(死 ws 记日志,不炸 receive_loop)

### backend/app/services/runner_service.py
- [ ] `request_runner`:`await send_to_runner(...)` 包 try/except Exception → `raise TimeoutError(f"Runner 连接不可用: {e}")` —— 复用两端点既有 `except TimeoutError` 路径,秒级失败替代裸 500/600s 死等

### backend/app/services/task_service.py
- [ ] `send_message`:容器 + runner 校验(现 :401-411)提前到 user 消息落库(:395)之前 —— 校验失败时不产生半截事务(上轮分析 P0,本轮落地)
