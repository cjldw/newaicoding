# R16.F3:修复 BUG-042 删除 Runner 被孤儿容器行卡死(16001 拦截收窄为"任务进行中")

> 状态:✅(fixed;pytest 11/11 + 编译零错;后端已重启;真机删除复验待用户——不可逆动作不代执行)
> 模块:M5(Runner 管理)
> 依赖:无(后端单文件 + 测试)

## 描述(即 BUG-042)

用户实测:DELETE runner 返回 `{"code":16001,"message":"Runner 上有运行中的容器,不可删除"}`,但这些容器关联的**任务已非进行中**(cancelled/done 等)。期望口径(**用户拍板**):**任务不是进行中 → 可以删除**。

根因:`runner_service.delete_runner`(runner_service.py:249-256)拦截条件只看 `containers.status IN ('creating','running')`,**不联查任务状态**。任务取消/完成后容器行状态未同步置 stopped(取消链路缺容器状态回写,既有缺陷源),孤儿容器行把 runner 删除永久卡死,只能手工改库。

## 实现要点(根因 + 修复方案)

- **修复**(`runner_service.delete_runner`):拦截条件收窄为——容器(creating/running)**且关联任务 status='running'**:
  ```python
  select(func.count(Container.id)).join(Task, Task.task_id == Container.task_id).where(
      Container.runner_id == runner_id,
      Container.status.in_(["creating", "running"]),
      Task.status == "running",
  )
  ```
- **口径依据**:项目对"任务进行中"的既有统一口径 = `Task.status == "running"`(users_admin 禁用用户取消任务、task_service 超时清扫、container_service 同款);pending 无容器,无需纳入。
- **边界**:Container.task_id 可空(R7 部署容器)——join 不上的行(task_id NULL)**放行**,符合用户口径"任务不是进行中可以删除";部署容器随 runner 删除一并失去宿主,属显式管理动作的预期后果。
- **不扩 scope**:任务取消链路补容器状态回写(治本)是独立缺陷,登记 ISSUES.md 留痕不混入本轮;删除 runner 时不做 best-effort 停容器(runner 都要删了,无意义)。
