# R2.F6 修复:私有 group 内建 internal 仓库被拒——建仓可见性未按组降级(BUG-013)

> 状态:✅(2026-09-22 rd-fix 第 5 轮完成:pytest gitlab+project 段 66/66;冒烟创建项目 auto 建仓成功(GitLab repo 680)、clone/push 全通;verified 迁移 ISSUES.md,连带 BUG-009 终验通过)
> 来源:BUG-012(鉴权头)修复后的 BUG-009 冒烟复验

## 描述(bug)

curl 实证(group 100 为 private 组):`POST /api/v4/projects {visibility:"internal", namespace_id:100}` → 400 `{"visibility_level":["internal is not allowed in a private group."]}`。平台 `bot_create_repo` 原样透传平台侧选择的 visibility → 私有 group 下所有建项目请求 2002 失败。

## 实现要点

`backend/app/services/gitlab_service.py` `bot_create_repo`:
- 建仓前 `GET /api/v4/groups/{namespace_id}` 读组可见性(private<internal<public);
- 请求 visibility 超出组可见性 → 自动降级为组可见性(logger.info 留痕);
- 读取失败不阻断(按原 visibility 建仓,由建仓报错兜底);
- client 生命周期调整:GET 与 POST 共用一个 client,finally aclose 移至最外层。

## 测试验证逻辑

1. `pytest -k "gitlab"` 全绿(18 存量 + 若 mock transport 需补 groups GET 响应则同步修)
2. 端到端冒烟:创建项目(visibility=internal)→ 期望 code=0 + project_id + main_repo 建成(GitLab 实际落为 private)
