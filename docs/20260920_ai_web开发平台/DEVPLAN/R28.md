## PRD 引用

### 边界定义(摘录)

- **做什么**:① 昵称修改(1-32字符,不唯一,可为空);② 头像本地上传(选择文件 → 本地预览 → 上传到平台 → 返回 avatar_url → 即时更新);③ 头像移除(恢复默认头像);④ 头像访问 URL 公开可访问
- **不做什么**:不做头像裁剪(V1 仅预览);不做第三方头像集成(Gravatar/微信/QQ);不改手机号;不做头像审核

### 异常与边界场景(摘录 + 挖掘)

- 上传过程中网络中断:提示重试,不产生脏数据
- 重复上传:新文件覆盖旧文件,旧文件可异步清理(V1 可不做)
- 头像文件被删除但 avatar_url 仍存在:前端加载失败时回退到默认头像
- 昵称清空:回显手机号(对齐 R1 默认值逻辑)
- (挖掘·安全)头像文件访问权限:公开可访问但不可枚举(随机文件名)
- (挖掘·数据)存量行:users 表 avatar_url 已有外部 URL 值,新增 avatar_file_path 字段默认 NULL,代码兼容读

### 验收标准(摘录)

1. 昵称修改保存后即时生效,长度校验正确
2. 头像本地上传成功,预览 → 上传 → 显示闭环
3. 头像移除后显示默认头像
4. 格式/大小限制前端校验正确
5. 头像 URL 公开可访问(无需登录)

## 接口契约

**接口契约** 总览——响应结构统一外层 `{"code": 0, "data": ..., "message": "ok"}`:

| 接口 | 类型 | 响应结构(data 内容) | 备注 |
|---|---|---|---|
| POST /api/users/me/avatar | **新建** | `{avatar_url: string}` | multipart/form-data 上传 |
| GET /api/files/avatars/{filename} | **新建** | 二进制图片文件 | 公开可访问(无需登录) |
| PATCH /api/users/me | 复用现有 | 现有结构 | 增加 avatar_url 可传 null(移除头像) |

### 接口 1:上传头像(新建)

- 类型:**新建** `POST /api/users/me/avatar`
- 路径文件:`backend/app/api/users.py`
- 鉴权:JWT(登录用户)
- 请求:multipart/form-data,字段名 `file`,文件内容
- 服务端校验:
  - 文件格式:Content-Type 必须为 image/jpeg / image/png / image/webp
  - 文件大小:≤ 2MB
  - 文件名:随机生成(防枚举),如 `{uuid4}.{ext}`
- 存储路径:`./data/avatars/{user_id}/{filename}`(user_id 为当前用户 UUID)
- 响应:
  ```json
  {"code": 0, "data": {"avatar_url": "/api/files/avatars/{filename}"}, "message": "ok"}
  ```
- 错误码:
  - `4001` 文件格式不支持(仅支持 JPG/PNG/WebP)
  - `4002` 文件大小超过 2MB

### 接口 2:访问头像文件(新建)

- 类型:**新建** `GET /api/files/avatars/{filename}`
- 路径文件:`backend/app/api/files.py` 或 `backend/app/main.py` 挂载 StaticFiles
- 鉴权:**无需登录**(公开可访问)
- 响应:二进制图片文件,Content-Type 根据扩展名自动判断
- 安全性:文件名随机(UUID),不可枚举;路径遍历防护(仅允许访问 ./data/avatars/ 目录下文件)

### 接口 3:更新个人信息(扩展)

- 类型:**复用现有** `PATCH /api/users/me`(`backend/app/api/users.py:51`)
- 变更:请求体 `avatar_url` 字段允许传 `null`(表示移除头像),服务端同时清空 `avatar_file_path`

## 服务端行为规格

| 行为 | 规格 |
|---|---|
| 文件存储 | 保存到 `./data/avatars/{user_id}/{filename}`,目录自动创建 |
| 文件名生成 | uuid4 随机生成,扩展名保留原始后缀(小写) |
| 重复上传 | 新文件生成新文件名(不覆盖),旧文件保留(V1 不做清理) |
| 头像移除 | 清空 avatar_url 和 avatar_file_path;文件保留(V1 不删除) |
| 并发上传 | 多文件同时上传各自生成独立文件名,无冲突 |
| 存量兼容 | avatar_file_path 默认 NULL,代码读取时 null 容错 |
| 响应最小化 | 响应仅返回 avatar_url,不返回文件路径/内部存储细节 |

## 实现要点

### 后端

1. **模型**:users 表加 `avatar_file_path` 字段(String(255), nullable)
2. **迁移**:alembic 迁移脚本
3. **接口**:
   - `POST /api/users/me/avatar`:接收 multipart 文件,校验格式/大小,保存到 `./data/avatars/{user_id}/{uuid}.{ext}`,更新 user.avatar_url 和 avatar_file_path,返回 `{avatar_url}`
   - `GET /api/files/avatars/{filename}`:从 `./data/avatars/` 目录读取文件返回(公开访问)
   - `PATCH /api/users/me`:扩展支持 avatar_url 传 null(移除头像)
4. **配置**:config.py 加 `AVATAR_UPLOAD_DIR: str = "./data/avatars"`

### 前端

1. **ProfileSettings.tsx 扩展**:
   - 头像上传区域:当前头像显示(img 或首字母回退)→ 选择文件按钮 → 本地预览 → 上传按钮 → 移除头像按钮
   - 文件选择:`<input type="file" accept="image/jpeg,image/png,image/webp">`
   - 本地预览:FileReader 读取为 dataURL,即时显示
   - 校验:选择时校验格式和大小(≤2MB),不合规提示
2. **MainLayout.tsx 头像显示改造**:
   - 有 avatar_url 时渲染 `<img src={avatar_url}>` 圆形裁剪(28px, border-radius: 999px)
   - 无 avatar_url 或加载失败时回退到首字母+颜色
3. **API 扩展**:frontend/src/api/users.ts 加 `uploadAvatar(file: File)` 方法

## 页面交互流程

- **上传头像**:个人资料页点头像区域"选择文件" → 文件选择器打开 → 选择图片 → 本地预览显示 → 点击"上传" → 上传成功 → 头像更新为最新图片,提示"头像已更新"
- **移除头像**:个人资料页点击"移除头像" → 确认弹窗("确定移除头像?")→ 确认 → 头像恢复为默认首字母显示
- **上传失败**:格式不支持 → 提示"仅支持 JPG/PNG/WebP";大小超限 → 提示"图片不能超过 2MB";网络失败 → 提示"上传失败,请重试"
