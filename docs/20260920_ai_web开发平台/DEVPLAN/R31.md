## PRD 引用(R31 增量5,Q51–Q57 已确认)

### 边界定义(摘录)

- **做什么**:① 快速创建=平台 spawn 本机 `python runner/main.py` 子进程(自动注入 PLATFORM_URL/RUNNER_TOKEN/RUNNER_ROLE/RUNNER_ID),最小弹窗(名称默认 `local-<runner_id前8位>` + max_containers 默认 10),token 对用户不可见;② `is_local` 标记区分启动方式;③ **停止=指令式**(WS 下发 `runner_shutdown`,runner 回报 result 后自行退出进程,不杀容器);④ 重启=停止+重新 spawn;⑤ **删除代停(仅本机 runner)**:先停全部 creating/running 容器(复用 R4 stop 强制 push 链)→ 停进程 → 删记录,任一容器停失败整删中止;⑥ 环境校验点击时逐项 + 细分文案;⑦ 上限 3 个(超出拒绝)
- **不做什么**:不做远程 runner 进程管理 / 不做机器重启后自动重拉(runner WS 无限重连已覆盖平台重启场景)/ 不做 Docker 容器形态启动 / 不做 deploy 角色(本入口恒 worker)/ 上限固定值不入平台设置

### 异常与边界场景(摘录 + 挖掘)

- spawn 成功但 10s 未注册完成:记录保留(offline),提示"Runner 已启动但未完成注册…",**不自动回滚删除**(可停止/重启/删除排障)
- runner 进程崩溃:平台不自动重拉(V1);心跳超时标 offline,可点「启动」重拉
- online/启动中重复点「启动」:幂等返回"已在运行",in-flight 锁防连点
- 停止指令 5s 无回执:有句柄强杀;无句柄(平台重启后的孤儿)返回错误提示手动处理——**绝不按 PID 盲杀**
- 代停中某容器 stop 超时/失败:整删中止指明容器,runner 记录保留
- 名称冲突:16005(既有 POST /api/admin/runners 的 name 唯一仅 DB 约束兜底,本端点显式校验;原端点不改——登记 ISSUES 候选)
- 安全:spawn 子进程继承平台环境(可读 backend/.env)——V1 单机单管理员信任模型,分片与页面注释标注
- (挖掘·一致性)删除代停=异步多步(30s×N 容器),接口同步等待全部完成;**超时保护**:整体 60s 未完成 → 中止返回"容器停止超时,请重试"(容器已停的不回滚,重试幂等——已 destroyed 容器不再入列)
- (挖掘·状态机)disabled 的本机 runner 不允许启动/重启(先启用?——V1 无启用端点,disabled 只能删除或重置 token 后重建;文案明确)
- (挖掘·契约)runner 侧旧版本(未实现 runner_shutdown)收停止 → 无 result 回执 → 走 5s 强杀路径(有句柄)或超时提示(无句柄),向后兼容
- (挖掘·旅程)平台重启后:runner 进程存活自动重连回 online;此时「停止」走指令式(不依赖句柄)仍可用;「重启」在无句柄时 = 指令停止 + 重新 spawn(新句柄),可用

### 接口:本机快速创建(含启动)
- 类型:**新建**
- 路径与方法:`POST /api/admin/runners/local`
- 请求体:`{ name?: string(1-64,缺省自动生成), max_containers?: int(1-100,默认 10) }`
- 响应结构:`data = { runner_id, name, status: "online"|"offline", token_hidden: true, launch_command: { argv: [..], env_keys: ["PLATFORM_URL","RUNNER_TOKEN","RUNNER_ROLE","RUNNER_ID"] } }`(**任何字段不含 token 值**)
- 时序:校验(上限 16003 → 环境 16002)→ 生成 runner_id → 落库(is_local=true,status=offline)→ spawn → 轮询等 register ≤10s → online 返回;超时仍 200 返回 status=offline + message"Runner 已启动但未完成注册,可在列表查看状态或重试启动"
- 错误码:

| code | 场景 | message(一字不差交付) |
|---|---|---|
| 16002 / sub=code_missing | `runner/main.py` 不存在 | 当前部署未包含 Runner 代码(runner/main.py),快速创建仅支持平台源码方式部署 |
| 16002 / sub=deps_missing | import docker/websockets 探测失败 | Runner 依赖未安装,请在平台运行环境执行 pip install -r runner/requirements.txt |
| 16002 / sub=docker_down | Docker daemon 不可连 | 本机 Docker 不可用,请先启动 Docker 后重试 |
| 16002 / sub=spawn_failed | Popen 抛错/退出码非 0(1s 内) | Runner 启动失败:{原因摘要}(≤120 字符,不含路径外的敏感值) |
| 16003 | is_local 计数 ≥3 | 本机快速创建的 Runner 已达上限(3 个),请先删除闲置 Runner |
| 16005 | name 冲突 | Runner 名称已存在,请更换 |

### 接口:启动已有本机 runner
- 类型:**新建** `POST /api/admin/runners/{runner_id}/start`
- 语义:行存在且 `is_local=true` 否则 404"仅本机快速创建的 Runner 支持启动";`disabled` → 16006"已禁用的 Runner 不可启动,请删除后重建";`online`/starting(内存锁)→ **幂等 200**"Runner 已在运行";offline → 复用环境校验 + spawn(同 token,更新 launch 记录)
- 响应:`data = { runner_id, status }`;错误码同上族(16002/16005 不适用/16006)

### 接口:停止本机 runner
- 类型:**新建** `POST /api/admin/runners/{runner_id}/stop`
- 语义:`is_local=false` → 16006"远程 Runner 请在其宿主机上手动停止";`offline` → 幂等 200"Runner 已处于停止状态";online → WS `request_runner(conn, {"type":"runner_shutdown"}, timeout=5)`;回执/断连 → 标 offline;无 WS 连接或有句柄超时 → `Popen.terminate()`,**无句柄且无连接 → 16007"无法连接该 Runner 进程且无本地句柄(平台重启后),请在任务机手动结束 runner 进程"**
- 响应:`data = { runner_id, status: "offline" }`

### 接口:重启本机 runner
- 类型:**新建** `POST /api/admin/runners/{runner_id}/restart` = stop 流程 + start 流程串联;任一失败返回对应错误码,不落半成品(停成功但起失败 → 200 + status=offline + message 提示"已停止,启动失败:{原因}")

### 接口:删除 Runner(改造 `DELETE /api/admin/runners/{runner_id}`,向后兼容)
- 变更:`is_local=true` 走**代停流程**(见服务端行为规格「删除代停状态机」),同步等待,整体预算 60s;`is_local=false` 逻辑零改动(有容器 16001)
- 新错误码:`16004`(代停中容器停止失败/超时)"Runner 上有容器未能停止({container_id 短码}),Runner 已保留,请先处理该容器后重试";token 型 runner 永不可见此码

### 错误码族总表(response.py 16xx 段顺延)

| 常量 | 值 | 含义 |
|---|---|---|
| RUNNER_HAS_CONTAINERS | 16001(既有) | 远程 runner 有容器不可删(不变) |
| RUNNER_LOCAL_ENV | 16002 | 本机环境校验失败(message 细分,sub 仅日志/detail) |
| RUNNER_LOCAL_LIMIT | 16003 | 本机 runner 上限(3) |
| RUNNER_LOCAL_STOP_FAILED | 16004 | 删除代停容器失败 |
| RUNNER_NAME_EXISTS | 16005 | 名称冲突(本端点显式校验) |
| RUNNER_NOT_LOCAL / 状态不允许 | 16006 | 非本机 runner 调 start/stop,或 disabled 启动 |
| RUNNER_NO_PROCESS_HANDLE | 16007 | 停止时既无 WS 连接也无句柄 |

## 服务端行为规格

| 行为 | 规格 |
|---|---|
| 环境校验顺序 | 上限(16003,查库计数)→ 代码存在 → 依赖 import 探测(subprocess 一次性 `python -c "import docker,websockets"` 5s 超时)→ Docker 可用(runner 语义校验:探测失败=启动后必注册超时,前置拦截)→ spawn;任一失败**不落库** |
| spawn 契约 | `sys.executable runner/main.py`,cwd=runner/,env 注入:`PLATFORM_URL=ws://{request 的 host 来源:srv 监听或配置 BACKEND_WS_URL,默认 ws://127.0.0.1:8000/ws/runner}`、`RUNNER_TOKEN=明文(仅传子进程)`、`RUNNER_ROLE=worker`、`RUNNER_ID={runner_id}`;**stdout/stderr → 日志文件 `data/logs/runner-{runner_id前8}.log`**(排障落盘);DETACHED_PROCESS(Windows)/start_new_session(POSIX) 脱离平台控制台 |
| 注册等待 | spawn 后轮询 DB `status=online` 或 runner_registry 命中,500ms×20 次=10s;超时不回滚(见异常) |
| 停止状态机 | online→(shutdown 回执/连接断)→offline;offline→幂等;disabled→仅可删除;终态×操作:offline 再停止=200 幂等;disabled 启动=16006;不存在=404 |
| 删除代停状态机 | 快照 creating/running 容器 → 逐容器 `request_stop`(既有,**Runner 侧销毁前强制 push**)→ 每容器等 `container_stopped/die` 回报(轮询 containers.status=destroyed,30s/个,整体预算 60s)→ 全部 destroyed → 停进程(在线走指令,否则 terminate)→ 删 runners 行;任一失败 → **中止,runner 记录保留**,已销毁容器不回滚(重试天然幂等:已停的不进快照)。push 失败由 Runner 的 stop 失败回报/超时呈现为 16004 |
| 事务 | 记录创建+落库先于 spawn(DB 先行,进程失败保留行可排障);删除代停跨多 session 循环(WS 等待不能持业务事务),最终删行单事务 |
| 并发/幂等 | per-runner_id in-flight 锁(set):start/stop/restart/delete 同 id 并发 → 后到返回 16008 沿用"操作进行中"?——**决策:锁冲突复用幂等**(start 撞 start → "已在运行");name 重复以 16005+DB 唯一双保险 |
| 时效 | 停止 5s / 注册 10s / 单容器 30s / 删除整体 60s——**确认:照此**(常量集中 `LOCAL_*_TIMEOUT`) |
| 存量兼容 | is_local 默认 0;既有远程 runner 行为零变化(回归判据 7) |
| 响应最小化 | 全部响应与审计 detail **禁含 token 值/明文**;env 注入仅进程环境;日志文件不含 token(runner 自身日志不打印 token——实现核查点) |
| runner 侧协议扩展 | runner/main.py handle_message 新增 `runner_shutdown` 分支:`await report({"type":"result",req_id,ok:True})`(复用既有 result 回包机制)→ 取消重连循环 → `sys.exit(0)`;旧版 runner 无此分支 → 平台走超时路径(向后兼容) |
| 审计(R25 模式) | 新事件:`runner.create_local`、`runner.start`、`runner.stop`、`runner.restart`;`runner.delete` 既有事件复用(本机删除时 detail 加 `代停容器数`);detail 一律不含 token/env 值 |

1. **local_runner_service**:`preflight()`(校验链→返回错误码/文案)、`spawn_local(runner, token_plain)`(Popen+日志重定向+句柄表)、`wait_online(runner_id, 10s)`、`shutdown_local(runner)`(指令→句柄强杀→16007 三级)、`stop_all_containers_and_wait(runner)`(代停编排)
2. 端点组装 create_local:preflight → 上限 → create_runner(name 冲突 16005)置 is_local → spawn → wait_online → 审计;全程 token 明文只进子进程 env 与栈内,审计/响应无值
3. runner/main.py shutdown 分支 ≤10 行;回报用既有 result 机制
4. 前端:操作列 `r.is_local` 分支渲染 启动/停止/重启;快速创建 Dialog(名称+最大容器数,名称留空占位提示"留空自动生成");16002 系列 message 直接展示;成功 invalidate 列表查询(既有轮询自然刷 online)
5. Windows/POSIX 双平台 spawn 参数(creationflags/start_new_session 分支);路径全用 `pathlib` 相对仓库根解析(定位 runner/ 目录:优先 `Path(__file__)` 上溯,失败=code_missing)

## 页面交互流程

- 快速创建:点「快速创建(本机)」→ Dialog(名称/最大容器数)→ 点「创建并启动」→ pending(按钮禁用+loading,预期 ≤10s)→ 成功:关 Dialog,列表刷新,新行 online(启动方式=本机 chip);失败:Dialog 不关,内嵌 Alert 展示 message,输入保留
- 停止:行内「停止」→ 确认?——**不停确认直接执行**(秒级;确认成本>收益,留痕),≤5s 行状态 offline,按钮组变「启动/删除」
- 启动:offline 行「启动」→ pending → online;失败 Alert toast message 原文
- 重启:online 行「重启」→ pending(≤15s)→ 新 online(spawn 新行句柄);停成起败:行 offline + message 提示
- 删除(本机):既有二次确认 Dialog 文案改「本机 Runner 将先停止其全部任务容器再删除,确认?」→ 确认 → 长 pending(≤60s,按钮 loading 文案"停止容器中…")→ 成功:行移除;失败:留在列表 + 16004 文案指明容器
- 401/403/500 统一行为沿用既有 ApiError 链路
