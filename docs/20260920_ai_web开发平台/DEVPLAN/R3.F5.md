## 描述(即 BUG-076)

打磨任务容器**异常退出后重新启动**后的首次会话,不会自动重发 `/rd-prd` 进入 PRD 打磨——因为 `TaskChat.tsx:249-256` 的 isNewSession 只看 `task_messages` 是否有过有效 AI 回复(DB 里有历史回复→判定非新会话),不看容器实例是否已换成新的。新容器里的 claude 是全新会话,却没人告诉它进入打磨模式。

已实现且无需动的部分:写入路径三方一致(req.prd_file_path = 容器 env = slash 参数);任务详情读取走 `GET /requirements/{req_id}/prd-content` 降级链(db→容器→none)。

## 实现要点(方案 A:容器代数判定)

1. **后端**:`GET /tasks/{task_id}/messages` 响应附带 `container_generation`(整数)——容器启动代数:同 task 每次容器创建/重启自增(可由 containers 表该 task 的行数/最大 created_at 序号派生,或 Task 模型加代数;实现取最小改动,注意旧数据回填口径);旧前端兼容:字段可选
2. **前端**(`TaskChat.tsx`):
   - 本地记住上次见到的 generation(ref,初值 = 首次拉到的值,不触发重发)
   - 后续拉取发现 generation **变化** → 视为容器换新,即使 DB 有历史 AI 回复也重发 `/rd-prd <prd_file_path>`
   - `sentRef: boolean` 升级 `sentGenerationRef: string | number | null`(每个 generation 只发一次;StrictMode 双挂载防重语义保留)
   - isNewSession 原「无有效 AI 回复」判定保留(全新任务场景不变)
3. **dev DB 迁移补跑**(部署步,主会话执行):`alembic upgrade head` 应用 `30088c854a08_prd_content.py`,恢复 PRD 持久化链(此前被 try/except 静默吞)

## 测试验证逻辑(修复后回归)

1. **单测(Red→Green)**:`tests/test_task_chat_auto_prd.py`(或既有自动 prd 测试文件追加)——构造「已有有效 AI 回复 + container_generation 变化」→ 断言前端判定需重发(前端逻辑若无可直接测的纯函数,则测后端 generation 派生正确性 + 前端以静态断言/重构出纯函数测之,由实现者定,但必须有自动化覆盖);后端 messages 响应含 container_generation 且代数随容器行增长
2. **触碰面回归**:task messages / chat 域既有 pytest 全绿(串行)
3. **部署验证**:alembic upgrade 后 aicoding 库 task_requirements(或对应表)prd_content 列存在;messages API 返回 container_generation;真机「重启后自动重发」E2E 归用户下次打磨容器重启自然复验(或择可弃打磨任务演练)

## 风险与口径

- generation 派生若用 containers 行数,retry 建新容器也计代——语义正确(新实例=新会话)
- 旧任务(containers 行多但从未用过该字段)首拉不重发(初值即当前代),仅「拉取后发生变化」才触发——口径已在实现要点 2
