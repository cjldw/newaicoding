# R37.F7:修复 BUG-080 打磨完成后支持再次打磨(reviewing/approved 解锁)

> 编号:R37.F7 | 模块:M3(需求状态机 + 需求详情页)
> 来源:BUG-080(2026-10-08 用户指令「页面需求打磨完成后,还支持再次打磨(任务可以再次开启)」)
> 状态:✅ 已完成(2026-10-08 rd-fix 收口;后端 4 新用例 Red→Green + R37 全量 20/20,tsc/build 零错;verified 待用户浏览器复验)

## 描述

R35.F1 的「重新打磨」只覆盖 `status=polishing` + 打磨任务终态场景。需求一旦提交评审(reviewing)或评审通过(approved),后端 start_polish 落 else → 3001,前端按钮也不再渲染——打磨成果无法返工重磨,唯一出路是评审驳回(需评审人操作)。本分片把「再次打磨」解锁到 reviewing/approved:打磨任务终态(或缺失)即允许重启打磨,状态回 polishing、polish_task_id 换新任务。

## 实现要点

**后端** `backend/app/services/requirement_service.py` `start_polish`:
- 状态门:`elif req.status == "polishing" and req.polish_task_id:` → `elif req.status in ("polishing", "reviewing", "approved"):`
- 放行条件:polish_task_id 缺失直接放行(顺带修 polishing+None 孤儿态 3001 死角);存在则查任务状态,终态集(`cancelled/failed/timeout/done`,与 R35.F1 口径一致)或任务行缺失 → 清 polish_task_id 重建;active → 3001 不变
- 放行后 `req.status = "polishing"`(既有赋值不变,天然把 reviewing/approved 拉回打磨态)
- in_progress/done/archived/rejected 落 else → 3001 不变(开发中/完结/归档/已取消不重磨)

**前端** `frontend/src/pages/requirements/RequirementDetail.tsx`(:256):
- 「重新打磨」按钮状态门 `requirement.status === 'polishing'` → `['polishing', 'reviewing', 'approved'].includes(requirement.status)`;`polish_task_id` 存在 + 任务终态要求不变

## 测试验证逻辑

1. **Red(Green 前 3001)**:`reviewing` + 打磨任务 `done` 调 start_polish → 放行;`approved` + `cancelled` 同;断言 `req.status == "polishing"`、`polish_task_id` 换新
2. **守卫回归**:`in_progress`/`done` 状态 → 仍 3001;`reviewing` + 打磨任务 `running` → 仍 3001
3. **R35.F1 既有回归**:test_r35_flow_fixes.py F1 三用例(polishing+终态放行/polishing+active 3001/build_detail 透传)全绿
4. **前端**:tsc --noEmit 零错 + vite build 通过
5. **手工**:打磨完成 → 提交评审(status=reviewing)→ 详情页出现「重新打磨」→ 点击 → 跳新打磨任务,需求状态回「打磨中」

## 范围外

- 任务页 done 态「重试」按钮(R37.F3 retry 仅 failed/cancelled/timeout)——「再次开启」由重新打磨(新建任务)承接,同任务重启不在本分片
- rejected(取消)需求的再打磨(取消语义为终态,30 天清理归 R14)
