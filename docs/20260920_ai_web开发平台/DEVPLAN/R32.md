# R32: 多 Runner 负载调度优化

> 状态: 待实施 | 创建日期: 2026-09-27

## 背景

当前系统支持多个 Runner 节点，但负载调度机制较简单，需要优化以确保任务合理分配到各 Runner。

## 当前机制

### 1. 负载调度算法（已实现）

位置：`backend/app/services/runner_service.py:pick_runner_db`

```python
# 筛选条件
- status = "online"
- current_containers < max_containers
- role 匹配（worker/deploy）

# 排序策略
- 按 current_containers 升序（最少连接数优先）
- 并列时取前 5 个，随机选择

# 标签匹配（R32 新增）
- task_tag 非空时，只选择 tags 为空或包含该 tag 的 Runner
```

### 2. 负载计数维护

位置：`backend/app/services/container_service.py`

- 容器启动成功：`current_containers += 1`
- 容器停止：`current_containers -= 1`
- 下限为 0

## 待优化点

### 1. 负载指标单一

**问题**：仅按容器数量调度，未考虑：
- Runner 机器性能差异（CPU/内存）
- 容器实际资源占用（有的容器跑重任务，有的跑轻任务）
- 网络延迟（Runner 与平台的距离）

**改进方向**：
- 引入权重机制：Runner 上报机器性能，调度时按权重计算
- 动态负载：Runner 定期上报 CPU/内存使用率，平台按实际负载调度

### 2. 缺乏亲和性调度

**问题**：同一项目的多个任务可能分散到不同 Runner，导致：
- Git 仓库重复 clone
- 无法利用本地缓存

**改进方向**：
- 项目亲和性：同一项目的任务优先调度到同一 Runner
- 可配置：通过平台设置开启/关闭

### 3. 故障转移不完善

**问题**：
- Runner 离线时，其上的容器状态未同步更新
- 任务重试时可能又调度到故障 Runner

**改进方向**：
- Runner 离线时，将其容器标记为 `suspended`
- 任务重试时，临时黑名单该 Runner（一段时间内不再调度）
- 提供手动迁移接口：将容器从故障 Runner 迁移到其他 Runner

### 4. 缺乏调度策略配置

**问题**：调度策略硬编码，无法根据场景调整

**改进方向**：
- 平台设置新增调度策略配置：
  - `least_connections`（当前默认）
  - `round_robin`（轮询）
  - `resource_aware`（资源感知，需 Runner 上报资源使用）
  - `affinity_first`（亲和性优先）

### 5. 监控与可视化不足

**问题**：
- 无法直观看到各 Runner 的负载分布
- 缺少调度决策日志

**改进方向**：
- Runner 管理页增加负载分布图表
- 调度时记录决策日志（为什么选择这个 Runner）
- 提供调度历史查询

## 实施计划

### Phase 1: 基础优化（优先级高）

1. **调度决策日志**
   - 记录每次调度的候选 Runner 列表、选择原因
   - 便于排查调度问题

2. **Runner 健康检查增强**
   - 除了心跳，增加资源使用率上报（CPU/内存/磁盘）
   - 平台展示 Runner 实时负载

3. **故障 Runner 临时黑名单**
   - Runner 离线后，30 分钟内不再调度新任务到该 Runner
   - 避免任务重试时又遇到故障节点

### Phase 2: 高级调度（优先级中）

4. **权重调度**
   - Runner 表新增 `weight` 字段（默认 1.0）
   - 调度时按 `current_containers / weight` 排序
   - 高性能机器可设置更高权重

5. **项目亲和性**
   - 查询项目历史任务主要运行的 Runner
   - 优先调度到该 Runner（可配置开关）

### Phase 3: 智能调度（优先级低）

6. **资源感知调度**
   - Runner 定期上报 CPU/内存使用率
   - 平台按实际负载而非容器数量调度

7. **动态权重调整**
   - 根据 Runner 历史任务完成率、响应时间动态调整权重

## 验收标准

- [ ] 调度决策日志可查询
- [ ] Runner 管理页展示 CPU/内存使用率
- [ ] 故障 Runner 30 分钟内不被调度
- [ ] 支持权重配置，高权重机器接收更多任务
- [ ] 项目亲和性开关可配置
