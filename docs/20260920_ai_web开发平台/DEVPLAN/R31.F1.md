# R31.F1:修复 BUG-043 本机/非容器 Runner 无终端可用(宿主 shell 通道)

> 状态:✅(fixed→verified 迁移 ISSUES.md;runner 单测 6/6 + 后端 11/11;真机 code=0 实证;浏览器交互归 rd-test)
> 模块:M5(波及 R26 Runner 终端 / R31 本机 Runner)
> 依赖:R26(exec 协议)、R31(is_local 本机 runner)

## 描述(即 BUG-043)

用户第三次报障同一面墙:R31 本机快速创建的 runner(1495a9d0,Windows 裸跑子进程)开终端返回 6003「该 Runner 未运行在容器中(非容器化部署),无法打开 Runner 终端」(BUG-041 文案修正后的准确提示)。R31 把本机裸跑 runner 变成平台一级能力后,「本机 runner 无终端」成为明确能力缺口——**用户诉求:本机 runner 也要能用终端**。

本质:R26 终端 = exec 进 Runner 自身容器;非容器 runner 无自身容器,通道根本不存在。6003 拦截正确,但没有替代通道。

## 实现要点(方案:宿主 shell 降级通道)

| 层 | 改动 |
|---|---|
| `runner/terminal_manager.py` | 新增 `HostSession`(subprocess.Popen)+ `create_host_shell(session_id, on_output, shell_cmd=None)`——Windows 用 `cmd.exe`,Linux 用 `bash`(按 sys.platform,忽略外部 cmd);输出泵复用批量缓冲语义(50ms/8KB);`write_input/kill` 分流查 host_sessions;`resize` 对 host 会话 no-op(无 pty) |
| `runner/main.py` | `exec` handler:`container_id == "__host__"` 哨兵 → `create_host_shell`;`terminal_input/terminal_close` 经 TerminalManager 分流自动生效 |
| `backend/app/api/admin/runners.py` | shell-sessions 第 4 段:`self_container_id` 键**缺失** → 6003 版本过旧(保留);**空串**(非容器)→ 不再拒绝,建 `container_id="__host__"` 会话,审计 detail `session_kind="runner_host"` |
| 前端 | 零改动(Dialog 直显 message;终端 WS 转发链路按台账 session_id 工作,host 会话台账存在即通) |

**安全留痕**:宿主 shell = 超管在 runner 宿主机执行命令的能力。入口仅超管(Runner 管理页);`runner.terminal_open` 审计 + `session_kind=runner_host` 可区分;能注册为 runner 的机器本就是管理员授权的执行资源(R31 平台已在该机 spawn 进程)。与 R31 权责一致,风险可接受。

**已知降级**:Windows 无 pty,host shell 为管道模式——不支持 resize/无真 TTY(交互式程序体验打折),排障场景够用;留痕接受。

## 测试验证逻辑

1. **runner 单测**(backend tests 内 runner 面):`create_host_shell` 注入轻量 shell 命令(python -c echo 型)→ 输出回调收到回显;write_input → 进程 stdin 收到;kill → 进程终止。Windows 本机可真跑。
2. **后端 pytest**(test_r26_runner_shell.py):更新空串用例语义——machine_info `self_container_id: ""` → **code=0** 且台账 container_id="__host__"(Red:当前实现 6003);键缺失用例保持 6003「版本过旧」。
3. 回归:test_r26_runner_shell.py + test_runner_admin.py 全绿。
4. **真机**:重启后端 + 重启本机 runner(R31 stop/start 接口)→ 开 shell-sessions code=0;浏览器终端可交互(留用户)。
