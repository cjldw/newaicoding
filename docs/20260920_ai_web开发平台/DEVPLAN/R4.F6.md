## 描述(用户复验打回的两个残留症状)

第 37 轮 F1/F2/F3 只修了「目录图标/点击分支」表层(type 归一化让 FileTree 能识别目录),但两个更深的断裂未动:

1. **点文件 → 编辑器打开但内容空**:
   - `TaskDetail.tsx:171` `useTaskFileContent(taskId, selectedPath)` —— selectedPath 来自 FileTree onSelectFile,是 runner list_dir 返回的**相对路径**(`%P` 相对于查询目录,如 `README.md`)
   - runner `read_file_bytes`(`container_manager.py:330-337`)`base64 -w0 {path}` 直接拼 shell——相对路径在容器 exec 默认 cwd(镜像 WORKDIR,非 /workspace/main)下解析 → **读取必失败**,错误被静默吞掉(fileData undefined → 编辑器渲染空串)
   - 保存(L232-233/377-378)同样把相对路径发给 write_file → `mkdir -p $(dirname 相对)` **写错位置**
2. **目录展开无子项**:
   - runner `list_dir`(`container_manager.py:351-356`)`find {path} -maxdepth 1 -mindepth 1` **单层列表**(docstring 自述"find 单层"),返回条目无嵌套信息
   - `FileTree.tsx:97-103` 点击目录只 `setExpanded(!expanded)` **零懒加载**;children 来自 buildTree 按 `/` 切分扁平列表——单层数据下目录节点 children 恒空 → **展开必空**

**复现步骤**:
1. 任务工作台(dev/打磨)→ 左树展开任意目录 → 无子项
2. 点击任意文件 → 中栏切到编辑器 → 内容区空(无错误提示)

**期望 vs 实际**:
- 期望:目录点击按需拉取该目录子级(懒加载树);点击文件编辑器加载真实内容;失败有可见错误
- 实际:目录展开空;文件编辑器空

## 实现要点(根因 + 完整文件树管理方案)

**路径语义契约(本轮核心)**:UI 树与全部文件 API 统一使用**容器绝对路径**(`/workspace/main/...`);树内展示用 basename;runner list_dir 返回的相对路径在前端入口处拼 rootPath 归一。

- **F1 FileTree 懒加载树模型重写**(frontend/src/components/FileTree.tsx):
  - 新 props:`rootPath`(默认 '/workspace/main')、`loadDir(dirFullPath) => Promise<FileItem[]>`、`refreshNonce`(外部刷新令牌)
  - 内部状态:`expanded: Set<fullPath>` / `dirChildren: Record<fullPath, FileItem[]>` / `loading` / `errors`
  - 目录点击 → 切 expanded;effect 保证「已展开目录必有数据」:无数据即调 loadDir(单一代码路径,展开/刷新/重试共用)
  - 子级三态行:加载中「加载中…」/ 失败「加载失败:xxx(点击重试)」/ 空数组「空目录」
  - 根子级 = `files` prop(相对路径 → 拼 rootPath 归一为绝对);保留 mode='project' 的旧 buildTree 扁平回退(该模式当前无消费方,防未来复用踩坑)
  - 右键菜单(新建/重命名/删除)path 改用绝对路径(修复 file_op 同源的相对路径错位)
  - 变更文件 Tab(git changes)不动(git 相对路径语义独立,消费方 diff API 自洽)
- **F2 TaskDetail 接线**(frontend/src/pages/tasks/TaskDetail.tsx):
  - `loadDir` = queryClient.fetchQuery(`['task-files', taskId, dir]`)按目录缓存;`onRefresh` = refetchFiles + refetchChanges + invalidate `['task-files', taskId]` 全前缀 + bump refreshNonce(FileTree 清缓存,已展开目录自动重拉)
  - 两处 FileTree 调用点(打磨「工作区」~L461 / 开发「全部文件」~L643)统一传 rootPath/loadDir/refreshNonce
  - `useTaskFileContent` 解构 isLoading/isError/refetch:编辑器 pane 增「加载中…」态与红色错误条(失败原因 + 重试按钮)——**错误不再静默**
  - selectedPath 升级为绝对路径后,读/存(写)全链路自动对齐(read_file/write_file 均绝对路径语义)
- **F3 后端测试补用例**(backend/tests/test_files_api.py):
  - `task_file_list` 对自定义 path(如 `/workspace/main/src`)的透传断言(懒加载 API 契约钉死);既有归一化用例回归

**并行/环境边界**:零 runner 改动(不依赖镜像重建;旧 runner "tree" 由已生效的 F2 归一化兜底);零后端运行时改动(无需重启后端);纯前端改动 vite HMR 即时生效。第 36 轮已收敛改动(runner 流式段/TaskChat)零接触。

## 决策留痕

- **不做 runner 递归 find**:node_modules 类目录递归列全会拖垮列表;懒加载(点一层拉一层)是标准模型,后端 path 参数现成支持
- **UI 树统一绝对路径**:read/write/file_op 在 runner 侧都是裸 shell 拼路径,绝对路径是唯一安全语义;git diff/changes 的相对路径是另一套消费方(diff API),不混用
- **错误可见性**:此前 read 失败被 useQuery error 静默吞掉渲染空串,用户无从分辨「空文件」与「加载失败」——编辑器三态(加载中/错误/内容)补齐
- 第 37 轮 R4.F5 的 type 归一化与本轮不冲突:它解决「目录被当文件」,本轮解决「目录没内容可展开 + 文件没内容可显示」——同一 bug 的两层
