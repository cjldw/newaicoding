# R9.F3 — 修复 BUG-071:任务终端 claude 秒退落裸 bash(first-run setup 连通性检查 403)

> 来源:rd-fix 第 39 轮(2026-09-29)用户实测报障
> 关联 BUG:BUG-071(症状②主修;症状①定性非 bug;附带发现 ensure_claude_session 竞态登记)
> 分析底稿:../.scratch/fix-analysis.md § 第 39 轮

## 描述(即 bug)

任务工作台唤起终端:claude 没有自动起动,落回裸 bash;用户同时误以为模型参数/自定义变量未注入。根因:devbox:v2 镜像 `/home/node/.claude.json`(构建期 headless claude 写入)缺 `hasCompletedOnboarding` 键 → 交互式 claude TUI 触发 first-run setup → 其连通性检查**固定直连 api.anthropic.com**(官方 network-config 文档确认,不走 ANTHROPIC_BASE_URL)→ 403 地域封锁 → exit 1;wrapper 兜底 `|| claude` 同样秒退 → `exec /bin/bash`。headless 对话链路(-p)跳过 first-run setup,故不受影响。

**容器内 A/B 实证**(suspicious_benz):修复前 `script -qec "claude --session-id <sid>"` 约 4 秒 RC=1(TUI 打出 Welcome 后 403 退出);`hasCompletedOnboarding:true` 补键后同探针 **RC=124**(timeout 15s 杀,TUI 常驻并渲染文件夹信任提示)。

## 实现要点(修复方案)

- **F2 平台兜底(主修,存量容器立即生效)**:`backend/app/api/terminal.py` `create_terminal_session` 的 `auto_claude_cmd`——在 `command -v claude >/dev/null 2>&1 &&` 守卫**内**、claude 启动前插入幂等补写:
  ```bash
  export CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1; grep -q hasCompletedOnboarding ~/.claude.json 2>/dev/null || node -e "<读改写 JSON 补 hasCompletedOnboarding=true,文件不存在则建最小对象>"
  ```
  - 语义:每次建终端先确保 onboarding 完成态,claude 直接进入正常 TUI;幂等(已有键零开销);容器无 node 时补写失败仅影响本次 claude 自启,守卫语义不变(不破坏无 claude 容器落 bash 的既有行为)
  - 顺带 `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`:消 qwen3.7-plus 模型目录 stderr 警告(BUG-065 已知不拦截,纯降噪,留痕)
- **F1 镜像治本(防御纵深)**:`docker/devbox/Dockerfile` 构建尾确保 `/home/node/.claude.json` 含 `"hasCompletedOnboarding": true`(构建期若由 headless claude 生成该文件,则在其后追加该键;注意与既有 MCP/skills 配置段合并而非覆盖)。⚠ 镜像重建+推送归发布动作(涉及 registry 凭据),本轮落 Dockerfile 改动留痕;F2 已覆盖存量与新建容器,不阻塞
- **登记不修**(本分片范围外,留痕):① ensure_claude_session 并发首开竞态(1 秒并发 5 终端 → 5 个 sid,last-writer-wins;修法 SELECT FOR UPDATE/唯一约束重试);② 平台设置 custom_env_vars 变更不回填存量容器的 UX 提示(PlatformSettings 保存 toast)

## 测试验证逻辑

1. **单测(backend)**:cmd 组装断言——auto_claude_cmd 含 `hasCompletedOnboarding` 补写片段、位于 `command -v claude` 守卫内且先于 claude 启动;含 `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`;无 claude 容器分支(cmd 以 `|| exec /bin/bash` 收尾)行为不变;shlex/引号安全(sid 单引号包裹语义不变)
2. **Dockerfile 静态核对**:构建指令产出 `/home/node/.claude.json` 含该键(与既有配置段合并);bash 语法校验(RUN 段 `bash -n` 或逐行 review)
3. **真机判据**:
   - 判据 A(复现路径):suspicious_benz 补键**回滚**(删 hasCompletedOnboarding)→ 走平台 POST /tasks/{id}/terminal-sessions 建新终端 → 容器内 ps 应出现 claude 子进程(TUI 活着),而非 wrapper 直落 /bin/bash
   - 判据 B:容器内 `script` pty 探针 claude TUI 常驻(RC=124)不秒退(RC=1)
   - 判据 C:对话链路回归——POST /api/tasks/{id}/messages 短消息 code=0 + assistant content 非空落库(headless 行为不受影响)
   - 判据 D(用户终验):浏览器任务工作台新建终端,自动出现 claude TUI
4. **门禁**:py_compile + backend 触碰面 pytest + 前端零改动则 tsc 不强制(若做 F3 需 tsc+build)
