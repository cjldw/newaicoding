## 描述(bug)

需求创建 `POST /api/projects/{pid}/requirements` 返回 `{"code":500,"data":null,"message":"服务器内部错误"}`,创建不落库。后端 traceback 实锤:

```

  branch = req_data.get("req_branch") or default_req_branch(req_data.get("title") or "")

  return f"feat/{gen_req_branch_slug(title)}{day}"
requirement_service.py:146  gen_req_branch_slug

ModuleNotFoundError: No module named 'pypinyin'
```

## 实现要点(根因 + 修复方案)

- **根因**:R34.F1(commit 93242f9「需求分支默认策略 feat/{需求名首拼≤10}{日期}+接线」)已把 `pypinyin>=0.50,<1.0` 写进 `pyproject.toml`(L21,uv.lock 锁 0.55.0)并在 `create_requirement` 接线 `default_req_branch`;但本机运行时(E:\services\python310 system env,`backend/venv` 为空壳)自该提交后从未执行依赖安装。函数内延迟 import 掩盖到首个请求才炸。
- **修复方案**(零代码改动,纯环境修复):
  1. 在 `backend/` 执行 `pip install -e .`——按 pyproject 清单幂等补装缺失依赖(pypinyin→0.55.0),已满足项不动;直连 PyPI 失败则切清华镜像(`-i https://pypi.tuna.tsinghua.edu.cn/simple`,ISSUES.md 有 TLS 失败留痕);
  2. 验证 `python -c "from pypinyin import Style, lazy_pinyin"` 导入成功;
  3. 后端 uvicorn `--reload` 无需重启(函数内 import 在调用时解析)。
- **防御性建议(不在本分片范围,交用户决策)**:`gen_req_branch_slug` 可加 try/except ImportError 回退 `req-{id8}`,使环境漂移不再 500 主链路;本轮不做,保持最小修复。
