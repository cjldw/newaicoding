## 描述(即用户指令)

需求打磨页面(type='requirement' 任务工作台):检测 AI 会话是否是新的(第一次开/失败后重开),是则自动以用户身份发送第一条消息 `/rd-prd <PRD文件路径>`(路径取需求详情存的 `prd_file_path`)。目的:①确保打磨 AI 进入 prd 模式(rd-flow 插件斜杠技能);②PRD.md 落盘位置与需求详情一致,PRD 预览可找到文件。

## 实现要点(方案,纯前端,后端零改动)

- **取数**:TaskDetail.tsx:299 已挂 `useRequirementDetail(task.req_id)`,`req.prd_file_path` 直接可用;PRD 草稿预览(TaskDetail:308 `useTaskFileContent(taskId, req.prd_file_path)`)与首消息同源同字段——路径一致性天然保证
- **判定口径**(isNewSession):该任务 messages 已加载 && 不存在 `role==='assistant' && content 非空 && content !== '[AI 回复执行中断,未获取到回复内容,请重试]'` 的行 → 新/失败会话。占位行不计(失败后重开语义:占位存在仍重发)
- **自动发送**:TaskChat.tsx 新增 useEffect——条件齐备(taskType==='requirement' && messages 已加载 && isNewSession && prd_file_path 非空 && 未在发送中)→ `sendMut.mutate({content: '/rd-prd ' + prdFilePath})`
- **防重发**:①判定口径幂等(AI 有效回复落库后条件自然不成立);②组件级 `sentRef` 兜底(一次挂载只发一次,防 StrictMode 双挂载/3s 轮询期间重复);③发送中(pendingUser/mutate pending)不重入
- **边界**:dev/test/release 任务不触发;prd_file_path 为空(老数据)不触发;首消息失败出现占位行 → 重开组件重新满足条件自动重发(符合「失败后重开」);自动消息与手打消息无差别(普通 POST /messages,`/rd-prd` 由容器内 claude 会话解析,R33 探针已证 headless slash 支持)

## 测试验证逻辑

1. `npx tsc --noEmit` 零错误 + `npx vite build` 通过
