# R2.F1 — 修复 BUG-008/BUG-009:gitlab_bot_group_id 类型校验拒绝(连带 bot 配置不可用)

> 来源:BUGS.md BUG-008 + BUG-009(用户实测 2026-09-22;分析见 .scratch/fix-analysis.md)
> 状态:✅(2026-09-22 rd-fix 第 3 轮补登记——前轮中断会话已实施:后端 int 分支宽容接受数字字符串 + R2.F1 专用 pytest 用例落地;前端保留 group_id 字符串透传与后端宽容兼容,zod schema 维持 z.string(),与原方案"前端 coerce"的偏差已留痕。BUG-008 待本轮 pytest 回归确认 fixed;BUG-009 verified 待用户真实 GitLab 环境复验建仓/clone)

## 描述(即 bug)

- **BUG-008**:`PUT /api/admin/platform-settings` 中 `gitlab_bot_group_id` 前端(zod `z.string()` + 普通 Input)提交字符串,后端以 `isinstance(value, int)` 严格校验且无 str→int 强转 → 保存报"要整形",平台设置无法完成录入。
- **BUG-009**:连带——group_id 一直没存进库 → `get_gitlab_bot_config` 拿不到完整 bot 配置 → 项目创建 auto 建仓失败/拉码 403"无权限"。

## 实现要点(根因 + 修复方案)

- **后端**(平台设置白名单校验处):`gitlab_bot_group_id` 接受 `int` **或可转 int 的数字字符串**(strip 后 `int()` 成功即收,存库统一转 int);非数字字符串维持拒绝(复用现有错误码与文案格式)。
- **前端**(`pages/admin/PlatformSettings.tsx` + 表单 schema):group_id 提交前转 number(`z.coerce.number()` 或等价),空串按未填写处理。
- **两端同修理由**:后端放宽保证 API 契约宽容(超管可能手工调 API),前端收紧保证 UI 提交即合法类型。
- **BUG-009 预期**:随 BUG-008 修复自然恢复(group_id 成功入库 → bot 配置完整);GitLab 侧真实建仓/clone 验证需用户环境复验(见测试验证逻辑 3)。

## 测试验证逻辑(修复后按此回归)
