## PRD 引用

### 边界定义

- **做什么**:
  - 需求 CRUD + 状态机
  - 创建需求时**自动在 GitLab 建分支 `req-{reqId}`**(从项目默认分支切出)
  - 打磨任务:AI 与用户对话,产出 PRD 草稿(写入容器,未 commit)
  - 评审:owner/editor 在平台上点击"评审通过/驳回";通过则 PRD commit 到 `req-{reqId}` 分支;驳回填理由,回到打磨
  - 需求下可看到所有关联任务
- **不做什么**:
  - 评审会议/通知(V1 仅平台内点击)
  - 需求优先级看板/排期(V2)
  - 需求变更版本对比(改内容 → 驳回重审)

### 字段定义

| 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
|---|---|---|---|---|---|
| req_id | uuid | 是 | auto | - | |
| project_id | ref(R2) | 是 | - | - | |
| title | string(128) | 是 | - | - | |
| background | text | 否 | - | Markdown | 为什么做 |
| description | text | 是 | - | Markdown | 做什么(初始草稿) |

| status | enum | 是 | draft | draft/polishing/reviewing/approved/in_progress/done/archived/rejected | |

### 交互规则(状态机)

| 当前状态 | 触发 | 目标状态 | 规则 |
|---|---|---|---|
| (创建) | 用户填 title/description | draft | 后台异步建 GitLab 分支 `req-{reqId}` |
| draft | 点击"开始打磨" | polishing | 启动打磨任务(拉起容器 + Claude 会话) |
| polishing | 用户点击"提交评审" | reviewing | PRD 草稿已写入容器,未 commit |
| reviewing | 评审通过(owner/editor) | approved | **PRD commit + push 到 req-{reqId} 分支,使用评审通过操作人的个人 GitLab token**,容器销毁 |
| reviewing | 驳回(owner/editor) | polishing | 填 reject_reason,重新打磨 |
| approved | 第一个开发任务启动 | in_progress | 自动 |
| in_progress | 所有发布任务 deployed | done | 自动 |
| done | 归档完成 | archived | 自动(R14) |
| 任意非 archived/done | 取消 | rejected | owner 操作,填理由;GitLab 分支保留(只读) |

### 异常与边界场景

- 打磨任务同一时间一个需求**只能有一个**
- 评审中需求不可编辑 title/description(避免评审过程中改需求)
- 驳回后可继续打磨,再次提交评审;reviewed_by/reject_reason 保留历史
- 需求已有任务进行中(approved 之后),不可驳回,只能"取消"
- 取消需求后,GitLab 分支**保留 30 天**,到期平台自动删除(避免误删代码)

### 验收标准

1. 创建需求后 GitLab 上能看到对应分支
2. 打磨任务能在容器内启动 AI 会话
3. 评审通过后 PRD 出现在 `req-{reqId}` 分支的 `docs/{YYYYMMDD}_{descSlug}_{taskShortId}/PRD.md`
4. 评审通过前无法创建开发任务

### 服务端行为规格

#### 创建需求

1. 校验用户是 owner/editor
2. 生成 `req_id`(uuid)
3. 生成 `req_branch`(默认 `req-{reqId}`,可自定义)
4. 调 GitLab API 建分支:`POST /api/v4/projects/{repo_id}/repository/branches`,body `{"branch": req_branch, "ref": default_branch}`
5. **在所有绑定 repo 上建同名分支**(遍历 `project_repos` 表)
6. 写 `requirements` 表
7. 返回需求详情

#### 开始打磨

1. 校验需求 status=draft
2. 校验无进行中的打磨任务
3. 创建任务(type=requirement):
   - 拉起容器(R8)
   - clone 主仓库到 `/workspace/main`,checkout 到 `req_branch`
   - 启动 Claude 会话
4. 更新 `requirements` 表(status=polishing, polish_task_id=task_id)
5. 返回 task_id

#### 提交评审

1. 校验需求 status=polishing
2. 更新 status=reviewing

#### 评审通过

1. 校验需求 status=reviewing
2. 校验用户是 owner/editor 且已绑定 GitLab token
3. 平台**用评审操作人的个人 token** 把 PRD commit + push 到 `req_branch` 分支:
   - 进入容器(打磨任务的容器)
   - `git add docs/{YYYYMMDD}_{descSlug}_{taskShortId}/PRD.md`
   - `git commit -m "[ai:req] {title}"`
   - `git push origin {req_branch}`
4. 更新 `requirements` 表(status=approved, reviewed_by=当前用户, reviewed_at=now())
5. 销毁打磨任务的容器(R8)

#### 评审驳回

1. 校验需求 status=reviewing
2. 校验用户是 owner/editor
3. 更新 `requirements` 表(status=polishing, reviewed_by=当前用户, reviewed_at=now(), reject_reason)
4. 打磨任务继续(容器不销毁)

### 页面交互流程

#### 创建需求流程

1. 用户点"新建需求" → 打开对话框
2. 填表 → 点"创建"
3. 调 `POST /api/projects/{pid}/requirements`
4. 成功 → 关闭对话框 → 跳转 `/requirements/{req_id}`
5. 失败 → 显示错误提示

#### 打磨流程

1. 用户在需求详情页点"开始打磨"
2. 调 `POST /api/requirements/{req_id}/polish`
3. 成功 → 跳转任务详情页 `/tasks/{task_id}`(打磨任务)
4. 用户与 AI 对话打磨需求 → AI 产出 PRD 草稿
5. 用户点"提交评审" → 调 `POST /api/requirements/{req_id}/submit-review`
6. 需求状态变为 reviewing

#### 评审流程

1. 用户在需求详情页(reviewing 状态)点"评审通过"或"驳回"
2. 驳回时填理由
3. 调 `POST /api/requirements/{req_id}/review`
4. 通过 → 需求状态变为 approved,PRD commit 到需求分支
5. 驳回 → 需求状态变为 polishing,继续打磨
