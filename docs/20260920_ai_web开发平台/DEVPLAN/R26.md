## PRD 引用

### 边界定义(摘录)

- **做什么**:online Runner 行加"终端"按钮 → 打开 Runner 宿主机 shell(runner 容器内);复用终端 WS 通道与限流;破坏性命令审计;非 online 置灰
- **不做什么**:不做进任务容器 exec(工作台已覆盖);不做多 Tab/会话恢复/录制回放/文件上传

### 异常与边界场景(摘录 + 挖掘)

- runner 容器重启 → 会话断开,重新点击重开(不自动重连)
- Runner 失联 → WS 断开提示"Runner 连接中断"
- shell 权限 = runner 容器内权限(非宿主机 root),V1 接受
- (挖掘·契约)旧版 Runner 未上报自身容器 ID → 创建会话报错"Runner 版本过旧,请升级 Runner 镜像后使用终端"——规格见行为规格
- (挖掘·安全)非 online/disabled Runner 直接调创建会话 API → 拒绝;非超管 → 403
- (挖掘·并发)同一 Runner 并发会话上限 = 1(已确认):已有活跃会话时再次打开返回错误提示"该 Runner 已有终端会话,请先关闭"
- (已确认)打开会话本身记审计 runner.terminal_open

### 验收标准(摘录)

1. online Runner 可打开终端并交互执行 docker ps 等,输出实时回显
2. 非 online 按钮置灰,API 拒绝
3. 非超管无入口且 API 403
4. 破坏性命令写入审计日志
5. 关闭页面会话销毁,无残留 pty

## 接口契约

**接口契约** 总览——响应结构统一外层 `{"code": 0, "data": ..., "message": "ok"}`:

| 接口 | 类型 | 响应结构(data 内容) | 备注 |
|---|---|---|---|
| POST /api/admin/runners/{runner_id}/shell-sessions | **新建** | `{session_id, ws_url}` | 错误码 6001/6002/6003 |
| WS /ws/terminal/{session_id} | 复用现有 | input/output/resize 协议 | 零改动 |
| WS /ws/runner: exec 消息 | 复用现有 | pty 建立 | 协议零新增 type |

### 接口 1:创建 Runner shell 会话(新建)

- 类型:**新建** `POST /api/admin/runners/{runner_id}/shell-sessions`
- 文件:backend/app/api/admin/runners.py
- 鉴权:require_superadmin
- 前置校验顺序:Runner 存在(404)→ status=online(新错误码 `6001 RUNNER_NOT_ONLINE`,ErrCode 6xxx 段顺延,文案"Runner 不在线")→ 无该 Runner 活跃 shell 会话(`6002 RUNNER_SESSION_EXISTS`,文案"该 Runner 已有终端会话,请先关闭")→ Runner 上报了 self_container_id(`6003 RUNNER_TOO_OLD`,文案"Runner 版本过旧,请升级 Runner 镜像后使用终端")
- 响应:
  ```json
  {"code": 0, "data": {"session_id": "uuid", "ws_url": "/ws/terminal/{session_id}?token=<jwt>"}, "message": "ok"}
  ```
  (ws_url 由前端 buildWsUrl 补全 host,与 api/terminal.ts 现状一致)
- 下发:复用既有 `{"type":"exec","container_id":<self>,"cmd":["/bin/bash"],"pty":true,"session_id"}`(runner_ws.py 协议零新增 type)

### 接口 2:关闭会话(复用现有链路)

- 类型:**复用现有** WS close → terminal_close → Runner kill pty(terminal.py 现有);无新端点
- 断开清理:平台 WS 断开回调按 session_id 发 terminal_close(现有);会话表记录关闭(复用任务终端关闭链路)

## 服务端行为规格(含负向探查结论)

| 行为 | 规格 |
|---|---|
| 自我识别 | Runner 启动时读 `HOSTNAME`(容器短 id,12 位)写入 register.machine_info.self_container_id;docker exec_create 接受短 id(Runner 侧 terminal_manager.create_pty 零改动,container_id 本就参数传入) |
| task_id 解耦 | terminal_service.TerminalConnection.task_id 改 Optional(默认 None);会话注册表/转发循环按 session_id 工作,不依赖 task_id(逐行核对现有引用点) |
| 并发上限 | 平台侧:terminal 注册表内按 runner_id 查活跃 runner 会话(shell 标记行)→ 有则 6002;会话关闭(pop)后可再开 |
| 生命周期 | 会话不落 DB 持久任务关联;平台重启 → 注册表清空(Runner 侧 pty 随 docker exec 进程存活,下次 terminal_close 不可达 → Runner 收新 exec 前旧 pty 自然存在;V1 接受,Runner 重启时按 D11 要点 4 清理残留 pty) |
| 限流 | 复用 check_rate_limit(terminal_service),零改动 |
| 审计 | 打开会话:runner.terminal_open(operator=超管,detail={"runner_name"});破坏性命令:terminal.destructive_command(R25 已接,detail 加 target 标记 runner shell 会话) |
| 响应最小化 | shell-sessions 响应不含 token_hash/machine_info 全量;WS 鉴权沿用 ?token= 校验(现有) |
| 幂等 | 重复 POST 在已有会话时返回 6002(非幂等创建,允许) |
| 不适用 | 状态机/删除保护/取消补偿/时效(会话即开即毁);软删×唯一(无软删) |

## 实现要点

- runner/main.py register 处:`os.getenv("HOSTNAME")` → machine_info.self_container_id(重启 Runner 生效;本地 runner 进程为裸跑时 HOSTNAME 是主机名 → 平台拿到非容器 id,exec_create 失败 → 6003 同口径兜底:创建会话时可先 exec `true` 探活,失败回 6003 文案改"Runner 终端不可用(未在容器内运行)")
- TerminalConnection.task_id: Optional[str] = None;terminal.py 建 runner 会话分支:不查任务容器,直接下发 exec(self_container_id);session 行 task_id="__runner_shell__"
- RunnerManagement.tsx:操作列加"终端"按钮(online 才可点);点击 setState 打开嵌 TerminalPanel 的 Dialog/抽屉(title=`Runner 终端 · {name}`);关闭 Dialog → TerminalPanel onClose 链路销毁会话
- 审计两事件随 R25 模式接入(本点只保证调用)

## 页面交互流程

- 打开:Runner 列表行"终端"(online)→ Dialog 弹出 → 自动 POST shell-sessions → 成功渲染 xterm(显示 shell 提示符);失败 → Dialog 内错误文案(6001/6002/6003 对应文案)+ "关闭"按钮
