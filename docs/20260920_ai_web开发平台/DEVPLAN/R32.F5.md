# R32.F5:修复 BUG-056 AI 流式对话内容混入 docker 帧头 + 末行丢失

> 状态:✅(verified 2026-09-27,用户三项复验通过,迁移 ISSUES.md)
> 模块:M5(runner container_manager;R32.F3 流式特性缺陷延续)
> 关联:BUG-056

## 描述

AI 对话两段故障:① `ContainerManager has no attribute 'claude_prompt_stream'`——
R8.F5 热更只拷 main.py,容器内 container_manager.py 为旧镜像版(全量热更后通);
② 修通后 assistant 内容带 docker 帧头前缀(`\x01\x00\x00\x00\x00\x00\x06\x03`)。

## 根因(双层)

`claude_prompt_stream` 以 `exec_start(socket=True, demux=False)` 裸读:
1. 不剥 8 字节帧头(stream 1B + 填充 3B + 长度 4B 大端)→ 帧头混入行流污染内容
2. `len(buf)<8` 判定把 EOF 前残 chunk(实测 4 字节,含 result 行尾部 \n)永久扣留 → 末行/result 丢失

## 修复

双缓冲(原始 buf / 已剥帧 line_buf):剥帧校验(stream∈{0,1,2}+填充恒零,只取 stdout 帧;
stderr/stdin 不入对话行流)+ EOF 残字节冲刷 + 行处理抽 `_drain_line_buf` 闭包复用。

## 测试验证逻辑

- 新增 2 用例(7 字节切块跨帧头分片 / stderr 帧隔离),runner 全量 43/43
- 真机:热更重启后对话 3.2s 返 `pong` 干净落库(tokens_out=14)
