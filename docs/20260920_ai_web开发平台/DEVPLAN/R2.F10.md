# R2.F10 — 修复 BUG-049:项目卡片需求数/成员数为硬编码演示数据

> 状态:✅ verified(2026-09-24;pytest 26/26 绿含新增计数断言;真机 API 三项目 req/members 与 DB 逐项一致;tsc 零错误;已迁移 ISSUES.md)
> 来源:BUGS.md BUG-049(用户实测 2026-09-24,rd-fix 第 16 轮)
> 模块:M1 项目管理(后端 list_projects + 前端 ProjectList 卡片)

## 描述(即 bug)

项目列表卡片(pcard)的统计与成员展示是 **R1 期硬编码演示数据**:
- meta 区需求数恒为 `0 个需求`(前端写死);
- foot 头像栈写死「罗/王/张」三个假头像(假颜色);
- 后端 `GET /api/projects` 列表项只返回 `repo_count`,**从未提供** req_count / member_count。

用户实测:有需求、有成员的项目,卡片显示 0 个需求与无关成员。

## 实现要点(根因 + 修复方案)

**根因**:R1 期按 vp 静态演示数据实现卡片,后续未接真;后端列表接口从未聚合需求数/成员数。

**修复**:
1. 后端 `project_service.list_projects`:批量补两组计数(pid_list 分组查询,防 N+1,与既有 repo_counts 同模式):
   - `req_count` = Requirement 按 project_id 计数(全部状态——vp 同口径为项目全部需求);
   - `member_count` = ProjectMember 按 project_id 计数 **+ 1(owner;R12 虚拟 owner 不落成员行,卡片口径含 owner)**;
   - items 增 `req_count` / `member_count` 两键(向后兼容,纯新增)。
2. 前端 `ProjectList.tsx`:
   - meta 区:`{item.req_count} 个需求` 替换硬编码 0;
   - foot 头像栈:owner 真实头像(`getInitial`/`getAvColor`,utils/avatar 既有)+ `+N` 角标(member_count-1>0 时),替换罗/王/张;
3. `api/projects.ts`:`ProjectListItem` 增 `req_count: number; member_count: number`。

## 测试验证逻辑(回归)

1. pytest(test_projects_api):列表断言补 req_count/member_count 键存在与数值正确(直插需求/成员 → 计数正确;member_count=成员行+owner);
2. 真机 API:GET /api/projects 对比 DB 实际行数一致;
3. 前端 tsc 零错误;卡片数据正确性走查归 rd-test(API 断言已覆盖数值)。
