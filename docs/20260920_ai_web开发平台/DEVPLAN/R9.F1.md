# R9.F1 — 任务页终端自动进入 claude,与对话同一会话(修复 BUG-037)

> 类型:功能增强(用户指令)| 状态:⬜ 进行中
> 关联:BUG-037 | 母需求点:R9(Web 终端)、R5(开发任务对话)| 分析:`../.scratch/fix-analysis.md`

## 描述

用户指令:任务页面可以开启终端,自动进入到 claude,和对话同一个会话中。

现状(一手证据):
- 对话面板每条消息 = 容器内独立 `claude -p <prompt> --output-format json` 一次性调用(`backend/app/services/claude_service.py:60`),**无 --session-id/--resume**,对话自身都没有上下文延续
- 任务页"新建终端"下发 `cmd=["/bin/bash"]` 裸 shell(`backend/app/api/terminal.py:103-109`),与对话无关联
- Runner 侧 `claude_prompt` 自行拼 cmd(`runner/container_manager.py:350,360`;Runner 独立进程,不能 import 后端 claude_service)

## 实现要点

核心机制:**任务级 claude 会话 ID**(uuid4)持久化 + CLI 会话参数接线。

1. **DB**:`tasks` 表新增 `claude_session_id CHAR(36) NULL`(注释"任务级 claude CLI 会话 ID,懒生成;对话与终端共用")。迁移方式**跟随仓库现行机制**(核对 main.py 启动迁移/ALTER 模式,参照近期 R23/R25 加列先例),存量任务行保持 NULL 即可。
2. **后端 task_service**:`ensure_claude_session(db, task) -> tuple[str, bool]` — `claude_session_id` 为空时生成 uuid4 落库,返回 `(sid, created_now)`。对话与终端共用同一生成器,先到先建(竞态窗口可接受)。
3. **claude_service.run_prompt** 增参 `session_id: str | None = None, resume: bool = False`,写入 `exec_tool` args(不传时维持原样,兼容)。
4. **task_service.send_message**(task_service.py:394/435):ensure → `run_prompt(..., session_id=sid, resume=not created_now)`。
5. **Runner**:
   - `main.py` exec_tool 分支把 `args.session_id` / `args.resume` 透传 `manager.claude_prompt(...)`
   - `container_manager.claude_prompt(container_id, prompt, workdir, session_id=None, resume=False)` 拼 cmd:
     - `resume=True` → `claude -p <q> --output-format json --resume <sid>`
     - `session_id 且 resume=False` → `claude -p <q> --output-format json --session-id <sid>`
     - 都不传 → 维持原 cmd(兼容)
6. **终端自动进入 claude**(`backend/app/api/terminal.py` create_terminal_session):
   - ensure → 构造 cmd:
     ```
     ["/bin/bash", "-lc",
      "cd /workspace/main 2>/dev/null; "
      + ("claude --resume '<sid>' || claude" if not created_now else "claude --session-id '<sid>' || claude")
      + "; exec /bin/bash"]
     ```
   - 语义:优先固定/续接会话;失败(transcript 缺失等)兜底裸 claude;`exec /bin/bash` 让用户退出 claude 后落回 shell
   - **claude 二进制不存在**(如非 devbox 容器):前置 `command -v claude >/dev/null 2>&1 &&` 守卫,直接落 bash,行为与现状一致
   - **范围硬约束**:只改任务级 `/tasks/{task_id}/terminal-sessions`;R26 超管 Runner 管理终端(宿主机 shell)是独立链路,**不得波及**——实施时核对 R26 端点未被本改动触及
7. **语义安全性**(规避 CLI 版本差异):`--session-id` 只在 created_now 时使用(该 UUID 从未被任何 claude 进程用过),后续一律 `--resume`——对"复用 --session-id 是否报错"的版本差异免疫。

## 测试验证逻辑

- **backend pytest**(新增用例):
  - `ensure_claude_session`:首调生成并落库;二调返回同一 sid 且 created_now=False
  - `run_prompt` args:无参 → 不含 session 字段;`session_id+resume=False` → `--session-id` 语义字段;`resume=True` → resume 字段(mock runner_service.request_runner 断言 message)
  - `send_message` 组装链:mock 下断言 args 携带会话参数
- **runner pytest**:`claude_prompt` cmd 三分支拼接断言(现有 runner/tests 跑绿不回退)
- **回归硬门禁**:backend 全量 pytest + runner 全量 pytest(参照 R25 轮基线 293+ 全绿)
- **E2E(需环境:Runner 在线 + 任务容器 running)**:
  1. 任务工作台 → 新建终端 → 终端自动出现 claude TUI(非裸 bash prompt)
  2. 终端内发一句话(建立会话)→ 退出 claude 落回 bash
  3. 对话面板发消息 → 容器内 claude 以 `--resume <sid>` 执行(任务日志/容器进程可证)
  4. 再次新建终端 → claude resume 出现**同一会话上下文**(可见对话面板历史)
  - 环境不可用时:静态核对 + 单测通过置 fixed,标注 "verified 待浏览器/容器实测"(沿 BUGS.md 现行惯例)
- **复现步骤对照(BUGS.md)**:修复前终端=bash、对话无会话;修复后按上述 E2E 四步全部成立即符合期望值
