# R26.F2:BUG-047 Runner 终端 6002 提供强制关闭并新建(用户指令)

> 状态:✅ 完成(2026-09-24 第 24 轮;真机 API 级全链实证)
> 模块:M5(Runner 终端;后端 runners.py + 前端 Dialog/terminal.ts);R26.F1 之后顺延
> 关联:BUG-047;用户指令 2026-09-24(rd-fix 第 24 轮:「该 Runner 已有终端会话,请先关闭 提供强制关闭再新建功能」)

## 描述

- **现状**:6002 并发上限=1 拦截后,若旧会话是异常残留(浏览器被踢/会话未正常关闭),超管只能去 DB 或等——无自助手段
- **用户指令**:6002 时提供「强制关闭并新建」一键能力

## 实现要点

1. **后端** `POST /api/admin/runners/{runner_id}/shell-sessions?force=true`(runners.py):
   - 6002 判定处:force=true 时不拒绝,改为遍历该 Runner 全部活跃 shell 会话,逐一复用 terminal.py 关闭语义(通知 Runner `terminal_close` kill pty;WS 连接不在时跳过 + 台账置 `closed_at`)
   - 不带 force 行为零变化(向后兼容,既有 6002 测试不动)
2. **前端** `createRunnerShellSession(runnerId, force=false)`(api/terminal.ts)+ RunnerManagement Dialog:
   - openShell 记录失败业务码 shellErrCode;错误分支 `shellErrCode === 6002` 时渲染「强制关闭并新建」主按钮 → `openShell(r, true)`

## 测试验证逻辑(回归判据)

| # | 判据 | 结果 |
|---|---|---|
| 1 | Red→Green:新用例(6002 场景 force=true → 旧会话收 terminal_close + closed_at 置值 + 新会话 open;无 force 维持 6002) | ✅ test_shell_session_force_recreates_when_session_exists;test_r26_runner_shell.py 12/12 |
| 2 | 真机 API 三步链 | ✅ 创建 A(code=0)→ 再建无 force(6002 原文)→ force=true(code=0);runner 日志实证「宿主 shell 已关闭 A」→「已创建 NEW」;DB: A closed_at 置值 / NEW open |
| 3 | 前端 | ✅ tsc 0 错;6002 错误分支渲染强制按钮(浏览器可视化确认归用户一瞥/下轮,因两会话超管互踢无法稳定驻留 UI) |

## 决策留痕

- 关闭语义与 DELETE /api/terminal-sessions/{sid} 完全一致(通知 runner + 置 closed_at),不新增协议 type
- 强制关闭不额外记审计(与既有 close 路径同等对待;新建时的 runner.terminal_open 照常落审计)
- 6002 文案与错误码不变,前端按钮按 code 精确匹配(非文案匹配)
