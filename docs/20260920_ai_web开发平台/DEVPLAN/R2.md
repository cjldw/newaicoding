## PRD 引用

### 边界定义

- **做什么**:
  - 项目创建时**必须绑定一个"主代码仓库"**(role=main,唯一);创建后可在项目设置中**追加绑定其他仓库**(role=test/docs/other,可多个)
  - 每个仓库两种绑定方式:
    - a) **平台自动建 repo**:用管理员配置的 GitLab bot token,在指定 group 下创建 `{slug}` / `{slug}-{suffix}` 仓库
    - b) **绑定已有 repo**:用户提供 repo URL,平台用 **bot token** 验证 repo 存在且 bot 有 read/write/merge/webhook 权限
  - 项目列表/详情/重命名/归档/删除(软删 7 天)
  - **项目级默认分支**配置(默认 `master`,可改 `main`/`develop` 等),所有仓库共享此默认分支名
  - **项目创建后,平台 bot 把项目创建者加为所有绑定 repo 的 Maintainer**(后续邀请的成员加为 Developer)
- **不做什么**:
  - 多 GitLab 实例(V1 只支持一个平台配置的 GitLab)
  - GitHub / Gitee 等其他 Git 托管
  - 项目模板市场
  - 项目级 GitLab token(统一走平台 bot + 用户个人 token)
  - 仓库级权限细分(所有绑定 repo 的权限跟随项目成员)
  - main repo 换绑(V1 只能删项目重建)

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| auto 创建项目 | 平台 bot 建 main repo + 初始化默认分支 + README + 把创建者加为 Maintainer | 进入项目详情 |
| manual 绑定 main repo | 平台 bot 验证 repo 存在且 bot 有权限 + 把创建者加为 Maintainer(若已是成员则跳过) | 失败拒绝 |
| 追加绑定 test/docs/other repo | 在项目设置 → 仓库 Tab → "添加仓库";同 manual 流程;role 必填;同一 repo 不可重复绑定到同一项目 | |
| 解绑仓库 | **仅 role ≠ main 可解绑**;main 不可解绑;解绑后**不动 GitLab repo**(仅断关联) | |
| 邀请成员到项目(R12) | 平台 bot 把该用户加到**所有绑定 repo**为 Developer | 成员可用个人 token 访问所有 repo |
| 移除项目成员 | 平台 bot 把该用户从**所有绑定 repo**移除 | |
| 删除项目 | 软删 7 天,7 天后**不动 GitLab repo**(只删平台记录/容器/部署) | 列表隐藏 |
| 归档项目 | 容器停止、部署下线、只读 | 列表灰显 |
| 平台 bot token 失效 / 未配置 | 项目创建/分支管理/merge/成员同步全部失败 → **项目创建入口禁用**,超管到"平台管理 → 平台设置"配置(R19 迁移) | 超管告警 |
| 用户个人 token 失效 | 该用户创建的任务 failed,引导重新绑定(R1) | 不影响其他用户 |

### 异常与边界场景

- 平台 GitLab 实例地址 + bot token + webhook secret 在**平台管理 → 平台设置**(超管,R19;原"用户中心"入口已迁移)配置;**未配置时项目创建入口禁用**
- slug 冲突自动加后缀 `-xxxx`
- 单用户项目数 ≤ 50
- 成员在 GitLab 上的 username 与平台 username 可能不同:以 GitLab username 为准(用户绑定时已拉取)
- 成员被移除后,其 GitLab repo 权限也被移除,但**该用户已提交的 commit 历史保留**(Git 天然特性)
- 平台 bot token 配置变更:即时生效,无需重启
- 追加绑定的 repo 若已存在分支 `req-{reqId}`(历史遗留),平台**复用**该分支,不报错

### 验收标准

1. auto 模式建项目后,GitLab 上能看到对应 repo 与默认分支,创建者是 Maintainer
2. 追加绑定 test repo 后,项目详情可见两个 repo
3. main repo 不可解绑;test/docs 可解绑
4. 平台 bot token 失效/未配置时项目创建失败并告警
5. 邀请成员后,该成员能用个人 token clone 所有绑定仓库
6. 移除成员后,该成员 token 无法访问仓库
7. 创建需求时,所有绑定 repo 上都建了 `req-{reqId}` 分支

**接口契约** 总览——**响应结构**统一外层 `{"code": 0, "data": ..., "message": "ok"}`(错误时 `code` 为业务错误码、`message` 为提示文案);字段级结构以下方各接口小节的请求/响应示例为准:

| 接口范围 | 响应结构约定 |
|---|---|
| 本需求点全部接口(下方小节逐一列出) | 统一外层 `{code, data, message}`;分页接口 `data` 含 `{items, total}` |

      "page": 1,

**接口契约**:

- 类型:新建
- 路径与方法:`GET / PUT /api/admin/platform-settings`
- 鉴权:`require_superadmin`(R19;403 code=19002)
- GET 响应结构:全部配置项键值;`gitlab_bot_token` / `gitlab_webhook_secret` 以打码形式回显(`glpat-••••••••9x2f`),**不回显明文**
- PUT 请求体:部分更新 `{key: value, ...}`;仅白名单 key 可写
- 响应结构:`{code: 0, data: {updated: [key...]}, message: "ok"}`
- 错误码:`2007` 非法配置值(域名格式非法/数值越界);`19002` 非超管
- 审计:每次 PUT 记 `platform_settings.update`(R19 action_type)
- **服务端行为**:
  1. key 白名单校验;value 类型与格式校验(域名=合法主机名;数值=范围内整数)
  2. UPSERT `platform_settings`;敏感项加密落盘
  3. **变更即时生效**(bot token / 两个根域名在读取处实时查表),无需重启
  4. `gitlab_url` / `gitlab_bot_token` 未配置时:项目创建入口禁用(2001 引导超管)
- 前端:平台管理 → 平台设置页(表单三分区:**GitLab 集成** / **域名(Q28)** / **全局参数**)+ "测试连接"按钮(调 GitLab `GET /api/v4/version` 验证 bot token)

### 服务端行为规格

#### 创建项目(auto 模式)

1. 校验平台 GitLab bot token 已配置(从 `platform_settings` 表读)
2. 生成 slug:从 `name` 生成(kebab-case),冲突加后缀 `-xxxx`
3. 调 GitLab API 建 repo:`POST /api/v4/projects`,body `{"name": slug, "namespace_id": bot_group_id, "default_branch": default_branch}`
4. 初始化 repo:创建 README.md,commit 到默认分支
5. 把创建者加为 Maintainer:`POST /api/v4/projects/{repo_id}/members`,body `{"user_id": creator_gitlab_user_id, "access_level": 40}`(40=Maintainer)
6. 写 `projects` 表 + `project_repos` 表
7. 返回项目详情

#### 创建项目(manual 模式)

1. 校验平台 GitLab bot token 已配置
2. 用户提供 `gitlab_repo_url`,解析出 `gitlab_repo_id`(调 `GET /api/v4/projects?search={url}`)
3. 校验 bot 对该 repo 有 read+write+merge+webhook 权限(调 `GET /api/v4/projects/{id}` + `GET /api/v4/projects/{id}/members/{bot_user_id}`)
4. 把创建者加为 Maintainer(若已是成员则跳过)
5. 写 `projects` 表 + `project_repos` 表

#### 追加绑定仓库

1. 校验 `role != 'main'`(main 唯一)
2. 校验同一 repo 未绑定到该项目(`project_repos` 表查重)
3. 校验单项目绑定 repo 数 ≤ 10
4. 校验 bot 对该 repo 有权限(同 manual 模式)
5. 把项目所有成员加为该 repo 的 Developer(遍历 `project_members` 表,调 GitLab API)
6. 写 `project_repos` 表

#### 解绑仓库

1. 校验 `role != 'main'`(main 不可解绑)
2. 删除 `project_repos` 表记录
3. **不动 GitLab repo**(仅断关联)

#### 删除项目

1. 软删:`projects.status = 'deleted'`,`deleted_at = now()`
2. 7 天后物理删除(定时任务):
   - 删除 `projects` / `project_repos` / `requirements` / `tasks` / `containers` / `routes` 等相关表记录
   - **不动 GitLab repo**(只删平台记录)

### 页面交互流程

#### 创建项目流程

1. 用户点击"新建项目" → 打开对话框
2. 用户填表 → 选择绑定方式(auto/manual)
3. manual 时输入仓库 URL
4. 点"创建" → 前端校验(zod schema)
5. 调 `POST /api/projects`
6. 成功 → 关闭对话框 → 跳转 `/projects/{project_id}`
7. 失败 → 显示错误提示(bot token 未配置/repo URL 无效)

#### 追加绑定仓库流程

1. 用户进入项目设置 → 仓库 Tab
2. 点"添加仓库" → 打开对话框
3. 选择角色(test/docs/other)+ 输入仓库 URL
4. 点"绑定" → 调 `POST /api/projects/{pid}/repos`
5. 成功 → 关闭对话框 → 刷新仓库列表
6. 失败 → 显示错误提示

#### 解绑仓库流程

1. 用户在仓库列表点"解绑"(非 main repo)
2. 弹出确认对话框:"确定解绑该仓库吗?解绑后不影响 GitLab 上的仓库"
3. 点"确定" → 调 `DELETE /api/projects/{pid}/repos/{repo_id}`
4. 成功 → 刷新仓库列表
