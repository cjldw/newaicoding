# R35:AI 对话真流式与思考过程展示(模块 M4/M5)

- **状态**:✅(用户拍板标记,2026-09-29;未走 rd-dev 闭环,实现核验留待需要时回溯)
- **PRD 引用**(边界定义 + 异常/边界 + 验收标准摘录,下游不读 PRD 全文):
  - **做什么**:① runner/平台捕获 `stream_event/content_block_delta/thinking_delta` → 新增广播事件 `{"type":"chat_thinking","text":...}`;② 前端流式气泡上方新增可折叠「思考过程」区(默认收起,入口显示「已深度思考」),展开实时追加思考文本;③ 思考文本随消息持久化(**落点 rd-plan 定:新增 `task_messages.thinking_content` 列**,不复用 tool_calls——理由:tool_calls 语义为工具调用数组、多消费方,混入思考文本有污染风险;独立列零歧义,见数据模型变更);④ 答案文本流式沿用既有 chat_delta(打字机平滑器在真流式下自动直通,R32.F7 既有行为)
  - **不做什么**:不做思考过程实时逐字渲染的开关配置;不做用户级 thinking 开关(V1,推理模型默认行为);不做思考内容编辑/复制导出
  - **调研前提(一手实测,2026-09-27)**:网关已加 `proxy_buffering off` 真流式生效;claude CLI(--include-partial-messages)把模型思考以 `thinking_delta` 增量转发进 stream-json;**平台现有管线丢弃该事件**(`_stream_event_to_chat` 仅映射 text_delta)
  - **异常与边界场景**:
    - 模型不产出思考(非推理模型/网关不支持):折叠区整体不出现,回退纯答案流式
    - thinking 文本过长:前端折叠区滚动展示,不截断;持久化全量
    - 思考中途断连:已到达部分随消息落库,无思考则隐藏折叠区
  - **验收标准**:
    1. 发送消息后,答案以增量逐字渲染(增量到达间隔 < 1s,不再整段瞬现)
    2. 答案上方出现「思考过程」折叠入口;展开可见思考文本且流式追加
    3. 刷新页面后历史消息仍带可展开的思考过程
    4. 网关回退非流式时,平滑器兜底整段呈现(不报错)

- **页面交互流程**:
  - 流式观看:发送消息 → 加载气泡(R36 计时)→ thinking 增量到达 → 答案气泡出现,顶部折叠区(默认收起)入口可见 → 点展开 → 思考文本实时滚动追加 → 答案流式完成 → chat_done → 真消息接管
  - 历史回看:刷新页面 → 消息列表加载 → 有 thinking_content 的 AI 消息带折叠区(默认收起)→ 点击展开查看全文
  - 中途停止:流式期点「停止生成」→ 真取消(并行流 R34.F1 链)→ 流式气泡与折叠区消失,无思考残留(取消轮不落库)
  - 不看思考:全程收起,仅入口行存在;无思考消息无折叠区
- **错误处理行**:
  - 执行失败(chat_done{ok:false})→ 已到达思考随 err 消息落库,前端渲染 err 消息的折叠区(有值时);无思考则无折叠区
  - **用户取消(停止生成)**→ 展示层立即中止(stoppedRef 丢增量 + 清流式态,并行流既有)+ 后端真取消 → 无消息落库、thinking 丢弃,折叠区随气泡消失,无残留
  - 事件断连(events WS 断)→ 流式气泡停在最后增量,既有行为不变;thinking 部分同停
  - thinking_content 缺失(存量/非推理)→ 折叠区不渲染,零报错
