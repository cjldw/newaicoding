# R35:流程断点修复包(打磨可重启 / 取消需求收尾 / retry 拉起 / 死代码清理)

> 编号:R35 | 模块:M3(任务/需求状态机)
> 来源:rd-prd 流程分析(2026-09-26,用户反馈「需求打磨任务取消后没有再开启的地方」+ 代码实证 8 项断点)
> 状态:已确认(用户指令「做成需求点后开发实现」)

## 描述

「需求打磨→开发→测试→发布→归档」状态机存在 6 类断点,本包统一修复:

| # | 断点 | 证据 |
|---|---|---|
| 1 | 停止打磨任务 → 需求卡 polishing + polish_task_id 悬挂,start_polish 双条件永假(3001),无重启入口 | requirement_service.py:261-264 / task_service.finish_task 不碰 requirement |
| 2 | 取消需求 = rejected 终态零出口,且不停打磨任务/容器(孤儿泄漏) | requirement_service.py:407-420 无 task/container 引用 |
| 3 | retry_task 只改 pending 无人拉起;前端 useRetryTask 零调用(死代码) | task_service.py:714-722 / api/tasks.py:282-298 / TaskDetail 无重试按钮 |
| 4 | requirement.status 无 in_progress 赋值点 → 前端「创建测试/发布任务」按钮永假(死 UI) | RequirementDetail.tsx:268/274 |
| 5 | sweep_timeouts 60 分钟超时清扫未被调度(死代码) | task_service.py:725-754 / main.py 无调度 |
| 6 | running 的 test/release 任务无停止按钮(acts 覆盖非追加) | TaskDetail.tsx:268/284 |

## 实现要点(按子项)

### R35.F1 打磨可重启(主断点)
- `start_polish`(requirement_service.py:261-264)前置放宽:
  - `status=="draft"`(原路径,不变)
  - 或 `status=="polishing"` 且 `polish_task_id` 指向的 task 已终态(cancelled/failed/timeout/done)→ 清空 polish_task_id 后走原创建链路(create_polish_task 复用,不新增端点)
  - polishing 且关联 task 仍 active(running/pending)→ 维持 3001 报错
- 前端 RequirementDetail:`status==='polishing'` 且关联打磨 task 已终态时显示「重新打磨」按钮(数据:polish_task_id 查 task 状态,复用 useTaskDetail 或后端 detail 补 polish_task_status 字段——**取后者,一次请求**)

### R35.F2 取消需求收尾(孤儿容器)
- `cancel_requirement` 增加:若 polish_task_id 存在且 task 未终态 → 调 finish_task(cancelled)(复用既有停止+容器销毁链);失败不阻塞需求取消(留 warning)
- 不动 rejected 终态语义(恢复需求入口属新能力,另行立项)

### R35.F3 retry 补齐拉起 + 前端入口
- `retry_task` 置 pending 后直接调 `start_task`(dev/test/release 通用;test 型 start_task 已有 cases_review 分支自然落位;release 型走原 start_task 容器链)
- 前端 TaskDetail:task.status ∈ {failed,cancelled,timeout} 时 acts 区显示「重试」按钮(接已有 useRetryTask hook,死代码激活)

### R35.F4 in_progress 死 UI 清理(选纯前端方案)
- RequirementDetail 两按钮条件从 `status==='in_progress'` 改为按任务态:
  - 「创建测试任务」:`status==='approved'` 且存在 done 的 dev 任务(hasDevTaskDone 已有)
  - 「创建发布任务」:`status==='approved'` 且存在 passed 的 test 任务(hasTestTaskPassed 已有)
- 后端 `_TYPE_REQ_STATUS` 已允许 approved 建 test/release,零后端改动

### R35.F5 sweep_timeouts 挂调度
- main.py 后台任务区新增 asyncio task:每 60s 调 sweep_timeouts(与 runner 离线扫描同模式,独立 session,异常吞掉记 warning)

### R35.F6 test/release running 停止按钮
- TaskDetail.tsx acts 逻辑改追加:running 时恒显示「停止任务」,test/release 附加按钮紧随其后(原覆盖 bug 修复)
