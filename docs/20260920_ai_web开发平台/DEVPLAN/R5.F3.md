# R5.F3 — 修复 BUG-072:任务 AI 对话 MCP 工具调用无响应(权限层双层缺陷)

> 来源:rd-fix 第 40 轮(2026-09-29)用户实测报障
> 关联 BUG:BUG-072;波及 R34.F3 权限桥接(4dc7d45)/R17 MCP 配置
> 分析底稿:../.scratch/fix-analysis.md § 第 40 轮

## 描述(即 bug)

任务 AI 对话让 AI 使用 mysql_dev MCP 工具(查测试库)拿不到结果。mysql_dev 本身健康(配置引用 `${ENV_MCP_MYSQL_*}` 键名一致、`claude mcp list` ✔ Connected、容器→120.27.217.194:3306 TCP 通),病根在**权限层**:

- **路径①(无桥接降级)**:runner `setup_permission_bridge` 失败时 perm_ok=False,cmd 无桥接 → headless 默认 permissionMode 下 MCP 工具触发 `permission_denied` 系统事件,无人应答静默拒绝,tool_result=`is_error`「you haven't granted it yet」→ AI 回「请授权」→ 用户看到无结果
- **路径②(有桥接)**:cmd 带 `--mcp-config /tmp/permgate/mcp.json --permission-prompt-tool mcp__permgate__approval` → CLI 2.1.280 下 permgate server init 报 connected 但 `approval` 工具不进 tools 列表(实测 43 项无此项)→ CLI 报 `MCP tool mcp__permgate__approval (passed via --permission-prompt-tool) not found` → **每个 MCP 工具调用返回 tool_use_error**(附带推论:任何需审批的内置工具(Bash/Edit)走桥接同样失败,桥接机制在 2.1.280 整体失效)

## 实现要点(修复方案)

- **F1(主修,立即恢复 MCP 可用)**:runner `claude_prompt_stream` cmd 拼接(container_manager.py:493-496)追加 `--allowedTools` 放行 MCP 工具面——任务 AI 对话本身即授权环境,读/查类 MCP 免人工审批:
  `mcp__mysql_dev__* mcp__mysql_beta__* mcp__filesystem__* mcp__brave-search__* mcp__figma__* mcp__github__* ListMcpResourcesTool ReadMcpResourceTool ReadMcpResourceDirTool`
  - ⚠ 留痕:mysql_query 类工具具备写库能力(mcp-server-mysql 不限只读),放行后 AI 可直写该测试库——任务容器环境由用户自配凭据,接受;如需收紧改工具侧
  - Bash/Edit/Write 等危险内置工具**不**放行,保持审批语义
- **F2(桥接机制修复尝试)**:`setup_permission_bridge`(container_manager.py:906-921)把 permgate server 配置**合并写入 `~/.claude.json` 的 mcpServers**(复用 R3 claude_inject 合并语义,幂等),cmd 去掉 `--mcp-config`,保留 `--permission-prompt-tool`;容器内实测 approval 是否进 tools 列表——**若 CLI 2.1.280 仍不暴露**(permission-prompt-tool 专用槽位不进列表/时序),如实留痕并保留 F1 兜底(需审批工具在桥修复前仍会失败,但不再殃及 MCP);该结论归档供 R34.F3 特性后续跟进(CLI 升级/换实现)
- **防双写核验**:改动函数(cmd 拼接段、setup_permission_bridge)与工作区既有未提交改动函数级不相交(R5.F2 累积兜底在 claude_prompt_stream 读循环、R8.F6 超时在 main.py、第 38 轮 list_dir)
