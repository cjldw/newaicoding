## PRD 引用

### 边界定义(摘录)

- **做什么**:platform_settings 新增 3 键(llm_base_url/llm_api_key/llm_model,单组,api_key AES-GCM);保存连通性测试;回退链=项目启用配置优先 → 平台默认 → 两者皆无禁用入口;会话级临时切换优先级最高;模型 Tab 回退提示+只读回显
- **不做什么**:平台级主/备多组;项目级"禁用回退"开关;配置变更对运行中任务生效

### 异常与边界场景(摘录 + 挖掘)

- 密钥同 PLATFORM_SECRET_KEY,泄露处理同 R1
- 连通测试过但模型名错:运行时任务 failed(同 R13 口径,不做白名单)
- 打码沿用平台设置 mask(前 5 + 掩码 + 后 4)
- (挖掘·一致性)平台默认被清空:运行中任务不受影响(配置已在 env/SDK 会话内),仅影响新任务判定——规格已写入服务端行为规格
- (挖掘·数据)存量行:platform_settings 无 llm_* 键 = 未配置,代码兼容读 None,无迁移

### 验收标准(摘录)

1. 超管可保存/更新模型默认配置,连通测试失败被拒绝,key 加密落盘且接口打码
2. 项目未配模型时创建任务,SDK 与 CLI 两种模式均使用平台默认 LLM 跑通
3. 项目配置了自己的模型后,任务使用项目配置而非平台默认
4. 项目与平台均未配置时入口禁用并引导
5. 项目设置模型 Tab 显示回退提示与平台默认只读回显

## 接口契约

**接口契约** 总览——响应结构统一外层 `{"code": 0, "data": ..., "message": "ok"}`(错误时 code 为业务错误码):

| 接口 | 类型 | 响应结构(data 内容) | 备注 |
|---|---|---|---|
| PUT /api/admin/platform-settings | 复用现有(扩展) | `updated: string[]`(既有实现响应键为 `updated`,分片原写 `updated_keys` 系笔误,实现期更正) | 白名单加 3 键 + 连通测试 |
| GET /api/admin/platform-settings | 复用现有 | `{key: value}`(敏感键打码) | llm_api_key 打码回显 |
| GET /api/projects/{id}/model-configs/resolvable | **新建** | `{effective_source, base_url, model, api_key_masked}` | 见下接口 3 |

### 接口 1:更新平台设置(扩展,复用现有)

- 类型:**复用现有** `PUT /api/admin/platform-settings`(`backend/app/api/admin/platform_settings.py`)
- 变更:SETTING_KEYS 白名单(`platform_settings_service.py:32`)加 3 键;新增 "str" 校验类型
- 鉴权:require_superadmin
- 请求:现有 dict payload;含 llm_* 键时三键必须齐备
- 响应:现有 `{updated_keys: [...]}`
- 错误码:
  - `2007` 非法配置键/值(现有)
  - **`2008` 新增:LLM 连通性测试失败**(`ErrCode.LLM_CONNECT_FAILED = 2008`,response.py 2xxx 段顺延)
- 服务端:payload 含 llm_base_url/llm_api_key 时,校验通过后、落库前调 `llm_service.test_connectivity(base_url, api_key, model)`(复用 llm_service.py:53,10s 超时);失败抛 2008,整批不落库

### 接口 2:平台设置回显(复用现有)

- 类型:**复用现有** `GET /api/admin/platform-settings`
- 变更:llm_api_key 进 SENSITIVE_KEYS 自动打码(mask_sensitive);llm_base_url/llm_model 明文回显

### 接口 3:生效配置查询(新建)

- 类型:**新建** `GET /api/projects/{project_id}/model-configs/resolvable`
- 路径文件:`backend/app/api/projects.py`(model-configs 路由组内追加)
- 鉴权:JWT(项目成员,viewer 可读)
- 响应:
  ```json
  {"code": 0, "data": {
    "effective_source": "project | platform | none",
    "base_url": "string | null",
    "model": "string | null",
    "api_key_masked": "string | null"
  }, "message": "ok"}
  ```
- 实现:内部调 `llm_service.resolve_config`(捕获 13005 转 none);响应最小化——**禁止**返回 api_key 明文/config_id/user_id
- 用途:前端入口判定(替代"配置 404 才知道未配置")+ 模型 Tab 回退提示条

## 服务端行为规格(含负向探查结论)

| 行为 | 规格 |
|---|---|
| 回退链 | resolve_config(db, project_id, config_id):会话级 config_id 优先(现有)→ 项目 is_default 且 enabled → 项目任一 enabled → **平台 llm_* 三键齐备时回退**(解密 llm_api_key)→ 否则 13005(语义改为"项目与平台均未配置") |
| 返回标记 | resolve_config 返回体增加 `source: "project"|"platform"` 字段,调用方(task_service)透传至任务日志便于排障;不进容器 env |
| 事务 | 平台默认保存与既有键同一事务,连通测试在落库前(测试通过才 UPSERT) |
| 并发/幂等 | PUT 幂等(UPSERT 现状);并发保存以最后提交为准(单超管操作,不加锁) |
| 存量兼容 | 无表变更;现存未配模型项目从 13005 拦截 → 平台配置后自动可用(预期行为变化) |
| 清空 | PUT 传三键中任一为空串 → 整批拒绝(secret/url 校验非空);**V1 不提供清空入口**(删除键值行无 API),变更走覆盖 |
| 响应最小化 | llm_api_key 仅打码;resolve_config 返回体不解密进任何 API 响应(仅任务执行链路内存使用) |
| 负向:键部分存在 | llm_* 仅部分键存在(手工改库等异常):resolve_config 按整体齐备判定,部分存在视为未配置并 logger.warning |
| 不适用 | 状态机/删除保护/取消补偿/时效/频控(无状态机、无删除入口、无有效期) |

## 实现要点

- resolve_config 内项目级判定失败后,查 platform_settings 三键:任一为 None → 维持 13005;齐备 → decrypt llm_api_key,返回 `{base_url, api_key, model, source:"platform"}`
- platform_settings_service.validate_setting_value 增加 "str" 分支(非空、strip、≤64)
- update_settings(或 API 层)在 payload 含 llm_* 时:三键齐备校验 → test_connectivity → 失败抛 2008(文案"连接失败,请检查 Base URL 和 API Key")
- **审计**:平台设置更新审计由 R25 统一接入(platform_settings.update,本需求点不自接)
- 前端 ModelConfigManagement 顶部:effective_source=platform 时显示 info 提示条"项目未配置模型,当前使用平台默认配置({base_url} / {model})";=none 时显示 warning"尚未配置模型,任务入口不可用,请联系管理员配置平台默认或项目默认模型"
- 任务创建入口已有引导逻辑保持:仅当 resolvable=none 时禁用并引导(后端 13005 语义已更新,前端文案同步)
