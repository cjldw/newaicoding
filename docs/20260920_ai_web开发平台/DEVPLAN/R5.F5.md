# R5.F5:修复 BUG-076 AI 对话长消息发送失败(模块 M4)

- **状态**:⬜ 未开始
- **BUG 引用**(BUGS.md BUG-076,2026-09-29 用户报障):AI 对话,消息长的时候发送失败;短消息正常
- **根因实锤**(分析产物 `.scratch/fix-analysis.md` BUG-076 节):
  - **P0 主因**:prompt 以 CLI 参数传递——`runner/container_manager.py:1008` 用 `shlex.quote(prompt)` 拼进 `claude -p` 命令行;用户消息 + @附件注入(每文件 <100KB 全量注入)叠加后超过 Linux ARG_MAX(单参数上限 ~128KB / 全局 ~2MB),容器内 exec 直接失败 → 表现为「发送失败」
  - **P1 副因**:`TaskMessage.content` 列为 TEXT(64KB 上限),长 AI 回复落库被 sql_mode 静默截断(数据劣化,不发错但内容缺失)
  - **P2 防线缺失**:`SendMessageRequest.content` 无 max_length 校验,超长输入直达底层才失败,无友好报错
- **实现要点**(三层,按优先级):
  1. **P0**:prompt 改为 stdin / 临时文件传递,不再拼命令行(runner 侧 `container_manager.py` + 平台侧发起调用如涉及协议字段;保持 runner↔平台 WS 协议兼容——若加新字段需向后兼容旧 runner 或同步升级)
  2. **P1**:`task_messages.content` TEXT → MEDIUMTEXT(alembic 迁移,SQL 进 DEPLOY.md;存量行不动,兼容读)
  3. **P2**:`SendMessageRequest.content` 加 max_length(取值依据 fix-analysis 建议;超限返回 422 校验错,前端 toast 友好提示)
- **涉及文件**:`runner/container_manager.py`、`backend/app/models/task.py`(列类型)、`backend/app/schemas/task.py`(校验)、alembic 新迁移、`docker/`(如 runner 需同步部署)
- **测试验证逻辑**(回归依据):
  1. Red→Green:长消息(>128KB,含多字节中文)经 send_message_stream(mock claude/runner)完整发送成功,回复落库
  2. exec 命令行不再包含完整 prompt 文本(stdin/文件路径代替;静态断言)
  3. AI 超长回复(>64KB,如 100KB)落库不截断(读回 length 一致)
  4. content >max_length 的请求返回 422/400 校验错(非 500),前端有友好提示
  5. 短消息回归:既有对话流测试(chat_stream/inject/cancel)全绿
