## PRD 引用

### 边界定义

- **做什么**:
  - **两级角色叠加**模型:平台级(`users.role`:superadmin / user)+ 项目级(`project_members.role`:owner / editor / viewer,R12);权限规则**代码固化**,不做动态配置
  - 超管 = 普通用户全部能力 + 平台管理能力(**叠加,非互斥**;超管可正常创建/参与项目)
  - **超管在所有项目(含未参与)自动等同 owner**(Q15):可查看、编辑需求、创建任务、评审、改配置、邀请/移除成员、归档/删除项目;审计日志记录其 superadmin 身份
  - **用户管理页**(仅超管):用户列表 / 禁用 / 启用 / **平台注册邀请**;**禁用即全失效**(Q16):登录被拒 + 现有 JWT 立即失效(D17 token_version)+ 进行中任务立即取消(销毁前强制 push,Q11)
  - **审计日志查询页**(仅超管,Q17):按时间 / 用户 / 操作类型过滤;日志**只读追加、不可删改**
  - 平台注册邀请(超管)与项目成员邀请(owner,R12)分离:超管邀请新用户注册,项目 owner 只能邀请已有用户进项目
  - 平台管理功能权限收口:平台设置 / Runner 管理 / 用户管理 / 审计日志 / 平台级 Skills 市场维护**仅超管可用**(Runner 已按 R16、平台级 Skills 已按 R17 实现超管鉴权,本需求点统一 Guard 并补前端导航与路由守卫)
- **不做什么**:
  - 不做平台角色细分(仅 superadmin / user 两档)
  - 不做权限点动态配置(矩阵固化在代码)
  - 不做组织/团队层级
  - 不做超管操作的项目级审批流

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 普通用户访问平台管理功能 | 前端隐藏入口;直接调 API 返回 403(前后端双重拦截) | 拦截 |
| 超管禁用用户 | status=disabled → 现有 JWT 立即失效 → 该用户 running 任务立即取消(销毁前强制 push) | 用户被踢出 |
| 超管启用用户 | status=active → 可重新登录 | 恢复访问 |
| 超管操作任意项目 | 按 R12 owner 权限矩阵执行;审计日志记录操作者 superadmin 身份 | |
| 超管重置/新建 Runner token | 沿用 R16 规则 | 旧 token 失效 |
| 超管访问审计日志页 | 按时间 / 用户 / 操作类型过滤,分页查询 | 只读 |
| 首个注册用户 | 自动成为 superadmin(平台引导期;后续注册默认 user) | |

### 异常与边界场景

- **最后一个超管不可被禁用/降级**(平台必须 ≥1 个超管)
- 禁用用户时,其在 GitLab 上的 repo 成员资格**不同步移除**(V1);若需彻底收回 GitLab 权限,超管先将其移出项目(R2 会同步移除 GitLab 成员资格)
- 禁用用户是某项目唯一 owner:项目保留,其他成员可继续工作;owner 空缺由超管代管(其本身等同 owner)或转让
- 禁用用户已提交的 commit 历史保留(Git 天然特性)
- 超管之间的操作(如超管 A 禁用超管 B)允许,受"最后一个超管"保护约束
- 审计日志写入失败不阻塞业务操作(异步写 + 重试;连续失败进告警)
- (挖掘)禁用用户**恰在容器内持有其个人 token 的进行中任务**:任务取消 + 销毁前强制 push(push 用该用户 token,仍有效——容器内 token 是快照,不因禁用即回收;销毁后该 token 不再产生新副作用)

### 验收标准

1. 普通用户访问任何平台管理 API 返回 403,前端无入口
2. **仅超管可见并操作 Runner 管理页**(新建 / 禁用 / 重置 token / 删除)
3. 超管进入任意项目(含未参与)拥有 owner 全部权限,且审计记录 superadmin 身份
4. 禁用用户后:登录被拒、现有会话立即失效、进行中任务立即取消
5. 最后一个超管不可被禁用
6. 审计日志可按时间 / 用户 / 类型过滤,记录不可删改
7. 权限校验前后端双重拦截

### 服务端行为规格(负向探查结论)

| 行为 | 规格 |
|---|---|
| 双层 Guard(D16) | 平台级 `require_superadmin`;项目级 `require_project_role(min_level)`(superadmin=虚拟 owner);越权统一 403,平台管理 `code=19002`、项目角色不足 `code=12006`(R12 错误码段延伸);**后端为唯一事实源**,前端仅隐藏入口 |
| 禁用即全失效(Q16/D17) | PATCH status=disabled 同一事务:① `users.status='disabled'` ② `token_version += 1`(所有在途 JWT 立即 401,含 access/refresh)③ 查该用户 `status='running'` 任务逐个取消(复用 R4 stop:销毁前强制 push,push 失败保留容器 30 分钟重试(Q11),超时销毁 + critical 告警)④ 审计 `user.disable` |
| token_version 校验 | 每请求鉴权点查 `users(status, token_version)`:status=disabled 或 version 不匹配 → 401(前端全局拦截 → 跳登录页);access 与 refresh 双 token 均携带并校验 |
| 最后一个超管保护 | 禁用/降级前 `COUNT(users WHERE role='superadmin' AND status='active') <= 1` → 拒绝 `code=19001`;超管间操作允许(受此约束) |
| 禁用 × 唯一 owner | 不拦截(项目保留;超管可代管/转让);审计与通知记录 |
| 唯一性 | `users.phone` 唯一(沿用 R1);`audit_logs` 无业务唯一键(追加型);`invitations.token_hash` 唯一 |
| 审计写入(异步域) | 应用内 asyncio 队列异步写;失败重试 3 次(间隔 1s/5s/30s);连续失败 → R18 critical 告警(接收人=超管);**写失败不阻塞业务操作**;完成判定:`audit_logs` 出现对应记录(或告警发出) |
| 审计保留期 | 每日定时任务(UTC+8 03:00)删除 `created_at < now() - 365 天`;删除操作本身记审计(自举记录 `audit.cleanup`,不计入保留期清理范围) |
| 响应最小化 | 用户列表/详情禁止外泄:`password_hash`、`gitlab_token_encrypted`、`gitlab_token_scopes`;他人手机号打码(前 3 + **** + 后 4) |
| 存量兼容 | 全新项目无存量行;`role`/`token_version` 随建表默认值;首个注册用户应用层置 superadmin |
| 频控 | `/api/admin/*` 全组:同一用户 60 req/min(防误操作刷接口;超限 429,code=19004) |

### 页面结构说明

#### 用户管理页 `/admin/users`(仅超管)

- **区块结构**:
  1. **顶部筛选栏**:状态下拉(全部/正常/已禁用)+ 搜索框(手机号/昵称,防抖 300ms)
  2. **操作工具栏**:右侧"邀请新用户"按钮(primary)
  3. **用户列表**(Table):手机号(打码)/ 昵称+头像 / 角色徽章(superadmin=primary/user=outline)/ 状态徽章(active=success/disabled=danger)/ GitLab 绑定(已绑定✓/未绑定—)/ 注册时间 / 操作(禁用|启用 / 邀请记录)
  4. **分页器**:默认 20/页
  5. **邀请新用户对话框**:手机号输入(可选备注)+ "生成邀请"按钮 → 显示 `invitation_token`(一次性,复制按钮)+ 有效期提示
  6. **禁用确认对话框**:"确定禁用用户 {nickname} 吗?其现有登录将立即失效,进行中的任务将被取消"→ 取消/确定

- **区块结构**:
  1. **顶部筛选栏**:时间范围(DateRangePicker,默认最近 7 天)+ 用户下拉(可搜索)+ 操作类型下拉(action_type 枚举)+ 查询按钮
  2. **日志列表**(Table):时间 / 操作者(昵称 + superadmin 徽章若适用)/ 操作类型(常量文案)/ 项目 / 目标 / 详情(JSON 摘要,悬浮展示全量)/ IP
  3. **分页器**:默认 20/页,created_at 倒序

- 左侧导航新增**平台管理**分组(仅 `authStore.user.role==='superadmin'` 渲染):平台设置 / Runner 管理 / 用户管理 / 审计日志

### 页面交互流程

- 禁用用户:用户管理页点"禁用" → 确认对话框 → 确定 → 调 `PATCH /api/admin/users/{id}/status` → 成功后列表行状态徽章变"已禁用" + toast"已禁用,取消 N 个进行中任务";失败(code=19001)→ toast"最后一个超级管理员不可禁用"

- 平台设置/Runner 管理/Skills 市场:入口从旧位置(用户中心)迁到"平台管理"分组,页面行为不变(R2/R16/R17 分片为准)
