# R14.F1:BUG-UI-071 归档接口全量 500(stray import)+ useTourSteps 链式请求治理

> 状态:✅ 完成(2026-09-25 rd-fix 第 27 轮;verified 迁移 ISSUES.md)
> 模块:M7(后端 app/api/knowledge.py;波及 M10/R29 导览 hook)
> 关联:BUG-UI-071(2026-09-24 浏览器核对批次);波及 R29 useTourSteps

## 描述(BUGS.md 原文要点)

- **复现**:访问任意 `/requirements/:reqId/archive` 归档页;超管与普通用户均 500。前端 R29 导览 hook `useTourSteps`(projects→第一条需求→fetchArchive 链)全局挂载,每个页面加载都打出一次该 500(走查 10 页 = 10 次 console error)
- **期望**:归档接口按业务语义返回(200 列表 / 404 需求不存在 / 403 无权),绝不 500
- **根因(一手 traceback,进程内 ASGITransport 复现)**:`app/api/knowledge.py:31` `from app.services.project_service import get_requirement_or_404 as _get_req` → `ImportError: cannot import name 'get_requirement_or_404'`(该函数实际定义在 `requirement_service`,下一行已正确导入且使用之;此行为遗留无效 import,每请求执行必炸)

## 实现要点

1. **后端(主修,一行)**:删除 `backend/app/api/knowledge.py:31` 该行遗留 import;下一行自 requirement_service 的正确 import 不动
2. **前端(触发源治理,R29 波及)**:`frontend/src/hooks/useTourSteps.ts` 的 archive/tasks 链式查询改为导览打开时才发(`enabled: tourOpen && !!requirement` 语义,按现有 react-query 结构落实);导览未开时全站不发链式请求
3. 明确不做:不改归档端点业务逻辑;不动导览交互流程
