# R8.F3 — 修复 BUG-029:容器内 git clone 认证缺失(未用 GITLAB_TOKEN)

> 来源:BUGS.md BUG-029(本地 E2E round2 实测:容器存活已修(BUG-028),clone 卡认证)
> 状态:✅ verified(2026-09-23:round3 clone 成功(remote 洗净 0 残留)+ round4 回填验证(BUG-030 修复并入本分片:container_service.handle_container_started 回填 tasks.container_id/runner_id,后端重启后 round4 实测成功);pytest 之外 runner 相关单测待并行会话回归批统一跑)

## 描述(即 bug)

容器内 clone 报 `fatal: could not read Username for 'http://47.111.69.64'`——`_clone_repo` 用裸 URL,而平台 start_container 消息的 env 已按 D10 注入 `GITLAB_TOKEN`(bot token,task_service.py L87/L340),Runner 未使用 → 私有仓库必然克隆失败 → 容器被清理 → 任务失败。

## 实现要点(已实现于 runner/container_manager.py)

- `_clone_repo(container, repo, env)`:先裸 URL clone;失败且 env 有 `GITLAB_TOKEN` → 用 `http(s)://oauth2:{token}@host/path` 重试;成功后 `git -C {path} remote set-url origin {干净URL}`(**凭据不落 .git/config**);无 token 则按原逻辑抛真实报错
- 模块级新增 `_embed_token(url, token)`
- `start_container` 透传 `env` 给 `_clone_repo`

## 测试验证逻辑

1. E2E:创建 dev 任务(demo 需求)→ Runner 日志无 git 报错、容器保持 running、`docker exec cat /workspace/main/.git/config` 无 oauth2 字样(remote 已洗净)
2. 平台任务状态 running 且 container_id/runner_id 落库
3. 回归:runner 测试套件 `pytest tests/`(container_manager 相关段)全绿
