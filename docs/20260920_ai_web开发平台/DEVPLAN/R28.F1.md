## 描述(即 BUG-040)

用户报障「用户头像编辑没有实现么」。核实:R28 头像编辑**功能已实现**——`/settings/profile` 页面有 80px 圆形预览 + 「上传头像」/「移除头像」+ 确认弹窗;但**无任何 UI 入口**:

- MainLayout 侧栏 NAV 无个人设置分组(仅 项目管理/知识/平台管理·仅超管)
- 顶栏用户下拉(`.user-menu`)仅「退出登录」一项(MainLayout.tsx:342-352)
- MainLayout 全文件唯一 Settings 链接是 `/admin/platform-settings`(平台设置,仅超管)

→ 普通用户只能手敲 URL 到达,等效"没实现"。同断链波及 `/settings` 区全部三页:个人资料 / GitLab Token(R2.F8 提及)/ 通知设置。

vp 原型语义佐证(vp/index.html 为唯一视觉事实源):用户按钮 `title="个人信息 / 退出登录"`、L1734「未绑定将引导个人设置」——个人设置入口本就是设计意图,React 版漏接。

## 实现要点(根因 + 修复方案)

- **根因**:R19.F2 建 admin 路由时用户菜单只做了退出登录;R28 交付时只实现了页面与显示链路(MainLayout 头像展示),漏了入口接线(同 BUG-011 MCP/Skills 入口断链模式)。
- **修复方案**(最小,单文件 MainLayout.tsx):
  1. `.user-menu` 下拉补「个人设置」菜单项(icon 复用已导入的 `Settings`,15px,文案「个人设置」),置于「退出登录」之上,`onClick={() => { setUserMenuOpen(false); navigate('/settings/profile') }}`;
  2. 「退出登录」行为不变;user-menu-item 既有样式零新增 CSS;
  3. 点击外部关闭逻辑(userBtnRef)对新增项天然生效(在菜单容器内)。
- **不扩scope**:侧栏不加设置分组(侧栏 12 项已满,vp 原型侧栏无个人设置;单入口经 SettingsLayout 左导航可达全部三设置页)。
