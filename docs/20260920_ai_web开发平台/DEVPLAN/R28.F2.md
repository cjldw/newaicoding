# R28.F2:BUG-UI-072 超管头像文件 404(失效引用清理 + 前端失败记忆)

> 状态:✅ 完成(2026-09-25 rd-fix 第 27 轮;verified 迁移 ISSUES.md)
> 模块:M1(数据 users 表 + 前端头像组件)

## 描述(BUGS.md 原文要点)

- **复现**:每页 `GET /api/files/avatars/1f5868f7-84b3-4127-b8ec-4c3c7b4f14b9.png` 404——超管 18767169856 的 avatar 引用指向磁盘上不存在的文件(疑 R19 数据事故后文件未随 DB 恢复)
- **期望**:头像引用与磁盘文件一致;失效引用不产生每页 404 噪音
- **现状兜底**:前端 onError 已回退首字母粉色圆形头像,视觉无异常;代价是每页 1-2 条 404 console error

## 实现要点

1. **数据侧**:清掉该用户的 avatar 引用(avatar_url / avatar_file_path,列名以 models 实际为准),经后端自身 session/.env 直改 dev 库;不补传文件(原文件已丢失,无法恢复)
2. **前端**:头像组件对加载失败的 URL 记忆(模块级 Set),失败后再次渲染同一 URL 直接走首字母回退,不发请求;静默,不弹错
3. 明确不做:不改 /api/files 静态服务逻辑;不做头像重新上传引导

## 决策留痕

- 选「清引用」而非「补文件」——原文件已丢失无源可补;用户下次可在个人设置重新上传(R28 能力仍在)
- 失败记忆用模块级 Set 而非组件 state——跨组件实例(顶栏/下拉多处头像)共享;页面刷新即重置,文件若日后恢复可自愈
