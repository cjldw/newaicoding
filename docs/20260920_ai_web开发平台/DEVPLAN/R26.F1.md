## 描述(即 BUG-041)

用户实测:POST /api/admin/runners/88b6cb82-…/shell-sessions 返回 `{"code":6003,"message":"Runner 版本过旧,请升级 Runner 镜像后使用终端"}`。该 runner 是本地 Windows 裸跑进程(local-win-test,rd-fix 第 8 轮注册),并非版本过旧:

- `runner/main.py:82`:`self_container_id = os.getenv("HOSTNAME", "")`——容器内 HOSTNAME=短容器 id ✓;**Windows 裸跑无 HOSTNAME 环境变量 → 空串**
- `runners.py:174-176`:空值一律落 6003「版本过旧」——对非容器化部署的 runner 语义错误,误导排障方向(用户会去找"升级镜像"的无关操作)

6003 拦截本身是正确设计(R26 决策④:裸跑同落 6003 兜底;裸跑进程无自身容器,`docker exec {self}` 根本不可执行)——**缺陷仅在文案**。

## 实现要点(根因 + 修复方案)

- **根因**:runners.py 开会话校验第 4 段把"machine_info 无 self_container_id 键"(旧版镜像)与"键存在但空串"(新版跑在非容器环境)折叠成同一文案。
- **修复方案**(错误码 6003 不动,按形态细分 message,前端零改动——Dialog 直显后端 message,RunnerManagement.tsx:78 仅注释):
  1. `machine_info` **无该键** → 6003「Runner 版本过旧,请升级 Runner 镜像后使用终端」(语义准确:R26 前的镜像没有上报逻辑);
  2. **键存在但空串** → 6003「该 Runner 未运行在容器中(非容器化部署),无法打开 Runner 终端」;
  3. `response.py:115` 枚举注释同步语义:6003 = Runner 容器标识缺失(版本过旧或非容器化部署)。
- **不扩 scope**:裸跑 runner 的宿主机 shell(绕过 docker exec)是新能力且涉安全敏感面,不在修复范围,如需走 /rd-prd;Linux 裸跑上报主机名(非空)的 exec 探活兜底路径维持现状。
