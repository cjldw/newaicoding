## PRD 引用

### 边界定义

- **做什么**:
  - 一个需求可创建**多个开发任务**(按模块/功能拆分,**可并行**)
  - AI 在容器内编码 → 自动 commit + push 到 `req-{reqId}` 分支
  - AI 执行过程中用户可通过 Web TTY 介入(手动跑命令/改代码)
  - 开发任务可**读取同需求下的测试报告**(R6 产出),作为修复上下文
- **不做什么**:
  - 任务级 MR(MR 在 R7 发布任务时统一处理)
  - 代码评审 Web 界面(评审在最终 merge 时进行)

### 字段定义

沿用 R4 通用字段;特定字段:
| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| related_test_task_id | ref | 否 | null | 若由测试驳回创建,关联原测试任务 |
| fix_context | text | 否 | null | 驳回时携带的失败用例上下文 |

### 交互规则

| 场景/条件 | 行为/规则 | 结果/去向 |
|---|---|---|
| 创建 dev 任务 | 用户填 description(要让 AI 做什么) | running |
| AI 编码 | 沿用 R4 通用规则 | |
| 从测试驳回创建 | 自动填充 fix_context(失败用例 + 报告路径),提示 AI 优先修复 | running |
| 需求下所有 dev 任务 done | 需求详情页"创建测试任务"按钮亮起 | - |

### 异常与边界场景

- 需求下并行 dev 任务数无硬上限(受 R4 项目级并发 3 限制)
- AI 修改 `docs/req-{reqId}/PRD.md` → 警告(PRD 是评审产物,原则上不应在 dev 任务中改)

### 验收标准

1. AI 编码能 commit + push 到需求分支
2. 测试驳回能创建携带上下文的 dev 任务
3. 用户可在执行中通过 TTY 介入

### 接口契约

(沿用 R4 通用接口;特定逻辑在创建任务时处理)

#### 创建开发任务(从测试驳回)

- **路径**:`POST /api/tasks/{test_task_id}/reject-to-dev`
- **鉴权**:JWT(owner/editor)
- **请求**:
  ```json
  {
    "title": "string(128)",
    "description": "string"
  }
  ```
- **响应**:
  ```json
  {
    "code": 0,
    "data": {
      "task_id": "uuid"
    },
    "message": "已创建修复任务"
  }
  ```
- **服务端行为**:
  1. 读测试任务的 `test_cases`(失败用例)+ `report_file_path`
  2. 创建 dev 任务,`extended_attributes` 填充:
     ```json
     {
       "related_test_task_id": "test_task_id",
       "fix_context": "失败用例:\n1. 用例1: ...\n2. 用例2: ...\n\n测试报告: docs/req-xxx/test-reports/{task_id}/report.md"
     }
     ```
  3. AI 的 prompt 中自动携带 `fix_context`
