## 描述(即 bug)

`docker/devbox/Dockerfile` 基础镜像 `mcr.microsoft.com/devcontainer/universal:linux` 已被微软**整仓退役**(MCR tags 接口 404 实证),`platform/devbox:v1` 无法构建 → R8 任务容器全链路无镜像可用。

## 实现要点(根因 + 修复方案)

- **根因**:上游镜像退役(ARCH D10 决策时的选型当时有效;环境变化非代码缺陷)
- **修复**:`FROM mcr.microsoft.com/devcontainers/typescript-node:dev-bookworm`(tags 已核验存在;含 node/npm/git)
  - apt 补:`python3 python3-pip inotify-tools`(R8 执行 + R11 watcher)
  - `pip3 install --break-system-packages`(Debian 12 PEP 668)
  - npm 全局:Claude CLI / vite / MCP server 3 个(**修正留痕 1:移除 create-react-app,已停止维护;修正留痕 2:server-git/server-sqlite 已从 npm 退役——npm view 为空,官方形态转 Python uvx,R17 契约层后续接**)
  - 用户适配:universal 的 codespace → devcontainers/typescript-node 的 **node**(uid 1000,HOME=/home/node;实测 whoami 确认)→ Skills 目录 `/home/node/.claude/skills/` + chown,/workspace 建目录授权
- **镜像 tag 不变**:`platform/devbox:v1`(R8 containers 默认值/平台引用零改动)

## 测试验证逻辑(修复后按此回归)

1. `docker build -t platform/devbox:v1 -f docker/devbox/Dockerfile .` 成功
2. `docker run --rm platform/devbox:v1 bash -lc "node -v && python3 -V && claude --version"` 三件套可执行
3. 本地 Runner E2E:创建任务 → 平台调度本地 Runner → 容器在本地 Docker 拉起(任务启动依托容器启动)→ Runner 日志/容器状态 running
