# R3.F2:知识条目超管全权限开放

- **状态**:✅(QA 实证接口层 D16 虚拟 owner 短路已使超管全通;本轮补 permissions.can_publish/can_promote + 前端按钮消费;48 用例全绿)
- **来源**:用户指令「知识条目管理员都开放」(2026-09-25);顺带收口 R2 审计遗留的超管提升按钮不可见缺口

## 描述

超管(superadmin)对知识条目**不受项目成员身份限制**:项目级/平台级条目的查看、创建(任意项目)、编辑、删除、发布、提升全部放行。

## 接口契约变更

| 端点 | 变更 |
|---|---|
| GET /knowledge/{id}、GET /knowledge/{id}/code | 项目级条目:`_ensure_entry_readable` 超管直通(现非成员 403) |
| POST /projects/{pid}/knowledge | 超管即使非项目成员也可创建 |
| GET /projects/{pid}/repos/{repo_id}/branches | 超管直通(关联代码 Tab 依赖) |
| PATCH /knowledge/{id} | 项目级:超管全字段(含 AI 条目全字段?**否**——AI 白名单是内容治理规则,超管也仅 tags,与 owner 一致);平台级已超管专属 |
| DELETE /knowledge/{id} | 项目级:超管可删(现创建者/owner/editor) |
| POST /knowledge/{id}/publish | 项目级:超管直通(现 editor+) |
| POST /knowledge/{id}/promote | 超管直通(现 owner;R2 审计已提及后端放行,确认落实) |

## permissions 结构扩展(R2 预埋基础上)

`permissions`: `{can_edit, can_delete, editable_fields, can_publish, can_promote}`——**can_publish/can_promote 由后端计算**(editor+ 可发布,owner+ 可提升,超管全真),前端按钮显隐改为消费这两个字段(替换现在前端本地角色判断,顺带修审计缺口)。

## 实现要点

- 后端:knowledge_service 的权限计算函数统一加 `user.is_superadmin` 短路分支(is_superadmin 取值方式看现有 user 对象/JWT claims,与 require_superadmin 同源)
- 前端:EntryDetail 的「发布」「提升」按钮显隐改读 permissions.can_publish/can_promote;platform-settings 无关不动
- 前端归属项目下拉维持「我的项目」数据源不变(超管项目列表开放属项目域权限,不在本点)
