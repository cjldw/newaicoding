# R1:手动添加双类型(代码引用 / 直接创建)

- **状态**:⬜
- **依赖**:无(数据形态与 R2 共定义,建议 R2 先定消费结构)
- **模块**:M1 后端 + M2 前端

## PRD 引用

类型 A:关联已有代码——选项目绑定的 GitLab 仓库 + 分支 + 路径(同库同分支多路径,上限 10);存引用信息,查看时实时拉取;可同时填 Markdown 说明。类型 B:直接创建——标题+类型+标签+Markdown 正文,编辑器带预览。创建即 published。异常:路径不存在/拉取失败逐块降级。

## 字段定义

| 字段 | 类型 | 规则 |
|---|---|---|
| title | string ≤128 | 必填 |
| type | enum code_snippet/pattern/pitfall/doc | 必填,A 型建议默认 code_snippet |
| content | text | B 型必填(markdown);A 型可选(说明文字) |
| tags | string[] | 可选 |
| source_links | dict[] | A 型含且仅含一个 `{type:"code", repo_id, branch, paths[]}`;paths 1-10 个,同 repo 同 branch |

## 接口契约

**复用扩展** `POST /api/projects/{pid}/knowledge`(api/knowledge.py:115,现鉴权 viewer):
- 请求体扩展:`source_links` 增加 code 对象校验——type="code" 时必填 repo_id/branch/paths;repo_id 必须属于该项目(ProjectRepo);paths 长度 1-10,每个 ≤500 字符
- 服务端校验失败:400 + 错误码(新增 20010=路径数超限,20011=仓库不属于本项目;沿用现有错误码风格,定稿时核对 ErrCode 表)
- 响应:沿用 entry 对象

**新增** `GET /api/projects/{pid}/repos/{repo_id}/branches`:
- 用途:Dialog 分支下拉(现全仓无分支列表接口)
- 实现:gitlab_service 新增 `bot_list_branches`(GET /repository/branches,per_page=100),ProjectRepo.gitlab_repo_id 直连
- 鉴权:项目 viewer;响应 `[{name, default}]`

## 实现要点(前端)

- KnowledgeBase.tsx「新建条目」Dialog(:263-317)升级:顶部 Tab「直接创建 | 关联代码」
- 直接创建:现状四字段 + markdown 编辑/预览切换(预览用 utils/markdown.ts 渲染)
- 关联代码:title/type/tags/说明 textarea + 仓库 Select(project.repos,参照 RepoManagement.tsx:144)+ 分支 Select(新接口)+ 路径列表编辑器(每行一个路径 Input + 添加/删除,上限 10,占位提示如 `backend/app/services/`)

- 复用清单:ui/Dialog、ui/Select、.btn/.input 类、project detail payload 的 repos(api/projects.ts:54)

## 页面交互流程

- 打开 Dialog → 默认「直接创建」Tab → 填完点「创建」→ 成功关 Dialog + 列表刷新 + toast「已创建」→ 可点进详情(R2)
- 关联代码 Tab:选仓库后分支下拉加载;未选仓库禁止提交;路径为空行自动剔除

## 文案清单

- Tab:「直接创建」「关联代码」
- 按钮:「创建」「取消」「+ 添加路径」

- 错误:「路径最多 10 个」「请先选择仓库」「该仓库不属于本项目」
- 成功:「已创建」

## 完成判据

- [ ] B 型创建:四字段提交成功,列表出现新条目,状态 published
- [ ] A 型创建:选仓库+分支+2 个路径提交成功,DB source_links 含 code 对象
- [ ] A 型 paths=11 个时前端拦截 + 服务端 400 兜底(异常)
- [ ] A 型选其他项目 repo_id 提交 → 400(异常)
- [ ] 分支下拉:选仓库后正确列出分支,default 分支置顶/标注
- [ ] markdown 预览:输入 `# 标题` 预览区渲染 h1
