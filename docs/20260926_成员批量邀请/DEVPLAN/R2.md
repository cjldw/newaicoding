## PRD 引用

owner 多选用户统一角色批量加入;**整体事务**:任一校验不满足→400 整批拒绝并列原因;全过→单事务插入+审计+GitLab 同步。50 上限、user_ids ≤50 去重、空列表拒绝。

## 接口契约

**新建** `POST /api/projects/{project_id}/members/batch`:
- 鉴权:require_project_role + require_owner(同现 invite,service 内;超管旁路)
- 请求 `{user_ids: string[], role: "editor"|"viewer"}`;校验:user_ids 非空/去重/单次 ≤50/role 枚举 → 违反 400
- **预检(全量,任一失败整批 400)**:每个 user_id 存在+status=active;均非项目成员(联项目成员表);现成员数+len(user_ids) ≤ 50。错误响应 `{code:400xxx?, message, data:{errors:[{user_id, reason}]}}`(错误码沿用现有 12002/12004 体系,新增批量专用码定稿时核对 ErrCode 表顺延)
- 通过 → 单事务:批量 INSERT ProjectMember(invited_by=operator)+ 逐条审计 project_member.add → 提交后 _sync_all_repos(沿用现 invite:同步失败不回滚成员)
- 响应 200:`{added: n, role, users:[{user_id, nickname}]}`

## 服务端行为规格(负向探查)

- **并发**:预检+插入同事务,唯一约束 uq_project_member_user 兜底——并发撞车触发 IntegrityError → 整体回滚返回 400「部分用户刚被加入,请刷新重试」(挖掘:并发域)
- **user_ids 重复**:~~服务端静默去重~~ **定稿修正:整批 400 逐条列重复**(PRD.md:46 与完成判据同侧优先;rd-dev 裁决,原规格行与 PRD 矛盾,按已确认 PRD 执行)
- **disabled 用户**:预检拒绝,status!=active 逐条列「用户已停用」(挖掘:状态域)
- **事务原子性**:任一 INSERT 失败全部回滚,不留半批(用户拍板整体事务)
- **审计**:逐条 project_member.add(invited_by=operator),与单邀请同格式
