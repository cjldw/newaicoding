# R3:选择式邀请 Dialog(替换手机号直添)

- **状态**:⬜
- **依赖**:R1/R2 接口契约
- **模块**:M2 前端

## PRD 引用

「邀请成员」Dialog 替换为选择式:搜索+分页候选列表(checkbox 多选,已成员/disabled 置灰禁选)+统一角色 RadioGroup+已选计数;整体成功关窗刷新,整批失败 Dialog 内错误条。**移除旧手机号搜索卡片逻辑**。

## 接口契约(前端消费)

- GET /projects/{pid}/candidate-users(R1)
- POST /projects/{pid}/members/batch(R2;400 时取 data.errors 渲染原因列表)

## 实现要点

1. **新建 frontend/src/components/ui/Checkbox.tsx**(全站首个):受控 checked/onChange/disabled,label 可点;样式 zinc 体系(原生 input + accent-color 或自绘方框对勾,参照 RadioGroup 写法风格)
2. **重构 MemberManagement.tsx 邀请 Dialog**:搜索 Input(300ms 防抖)→ candidates 列表(每行:Checkbox+头像+昵称+打码手机号+is_member→「已是成员」置灰/status=disabled→「已停用」置灰);分页器;底部统一角色 RadioGroup(editor/viewer,默认 viewer)+「已选 n 人」+ 提交按钮(0 人禁用,Plus 规范不适用于 Dialog 内主按钮——primary 变体)
3. **提交**:useBatchInviteMember hook(membersApi.batch);400 → Dialog 内 Alert 列 errors 原因(不关窗);200 → toast「已添加 n 名成员」+关窗+invalidate ['project-members']
4. 移除旧 useUserSearchByPhone/SearchedUser 卡片逻辑与 api(若无他处引用);页头「邀请成员」按钮保留(变体/图标不动)
5. 全选(当前页):表头 Checkbox,只勾选可选项

## 文案清单

- 标题「邀请成员」;搜索占位「搜索昵称或手机号」
- 禁选标注:「已是成员」「已停用」
- 角色组:「角色」editor=「编辑」viewer=「查看」
- 按钮:「邀请」(禁用态 title「请先选择成员」);「取消」
- 结果:成功 toast「已添加 {n} 名成员」;失败 Alert 标题「添加失败」+逐条「{昵称}:{原因}」
- 空态:「未找到匹配用户」;分页「共 {total} 人」

## 页面交互流程

打开 Dialog → 搜索/翻页勾选 → 选角色 → 邀请 → 成功关窗刷新 / 失败留窗显原因 → 取消关窗不刷新
