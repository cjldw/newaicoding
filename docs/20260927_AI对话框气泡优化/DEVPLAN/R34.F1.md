# R34.F1:修复 BUG-UI-090 对话框停止操作

## 描述(bug)

「停止生成」按钮仅在流式增量已开始(`streamText` 非空)后渲染,首个 chat_delta 到达前(thinking/后端执行最长 10 分钟)没有停止入口;且停止仅前端展示层中止,后端任务继续。

## 实现要点

**前端(本轮可做)**:
- 停止按钮条件 `{streamText && ...}` → 整个 `sendMut.isPending` 期间常显
- 点击行为不变(stoppedRef 展示层中止)

**后端(契约已按调研写实,2026-09-27 rd-plan;证据 .scratch/fix-analysis.md)**:
- 现状:执行体=POST 内联 await 协程(task_service.py L662 `async for` 消费内存 queue);runner 侧 `asyncio.to_thread` 阻塞读 docker socket,**线程不可强杀**(runner/main.py L460 注释);任务级 stop 靠销毁整个容器间接终止
- 真取消方案:新增 runner 消息 `{"type":"exec_tool_cancel","req_id"}` → runner 按 req_id 找执行中容器 `docker exec pkill -f claude` → socket EOF 线程退出 → `finalize()` 错误结束 → 广播 `chat_done {ok:false, error:"cancelled"}`
- 平台侧:新建 `POST /tasks/{id}/messages/cancel`(或 WS 下行),调 runner_service 发 cancel;`_stream_requests`/`_pending_requests`(runner_service.py L126-127)已有 req_id 追踪骨架可复用
- 前端接线:停止按钮从 stoppedRef 伪取消改为调 cancel 接口 + 保留展示层中止兜底

## 测试验证逻辑

- 复现:发送消息后在 thinking 阶段(流式开始前)观察 → 期望:停止按钮可见
- 点击停止 → 期望:气泡清空、反馈条「已停止」;(后端就绪后)服务端执行真正中止
