## PRD 引用(无 PRD,本文件即规格)

**边界定义**:AI 执行中需要用户决策时,平台提供结构化确认通道:事件上行(CLI→Runner→后端→WS→前端)+ 应答下行(前端→REST→Runner→CLI),任务不再静默拒绝/跳过。

**验收标准**:① 触发权限/确认点时前端弹出确认卡;② 用户允许/拒绝后执行继续且结果可见;③ 无确认能力时维持现状静默拒绝(不回归)。

## 现状关键事实(调研结论,规格的前提)

1. 执行链:POST /tasks/{id}/messages → `send_message_stream` → runner WS `exec_tool` → 容器内 `claude -p --output-format stream-json --verbose --include-partial-messages`,`stdin=False`、`2>/dev/null`,无任何 permission flag(container_manager.py L385-392)
2. 确认通道**天然不存在**:-p 非交互下未放行工具被 CLI 自动拒绝,拒绝原因进回复文本,无结构化事件
3. WS 事件表:chat_delta/chat_done/tool_call/status_changed/ping;**`_stream_event_to_chat`(task_service.py L557)显式丢弃 CLI 的 system/init/user/result 事件**——透传缺口在此
4. 新增事件成本低:后端 1 处 broadcast + 前端 useTaskChatStream 加分支 + TaskChat 接线,共 3 处

## 接口契约(新建)

### 上行:WS 新事件 `chat_confirm_request`

```json
{"type":"chat_confirm_request","confirm_id":"uuid","prompt":"允许执行 Bash(git push) 吗?","options":["allow","deny"],"req_id":"..."}
```

- 产生点:`_stream_event_to_chat` 加分支,透传 CLI stream-json 的 permission/control 事件(CLI 侧需加 `--permission-prompt-tool` 或换可交互模式——**CLI 具体机制待 rd-dev 验证**,这是最大不确定点)
- 挂起语义:确认未应答期间任务状态不变,UI 显示「等待确认」;超时 5 分钟自动按 deny 处理并广播 `chat_confirm_resolved {confirm_id, choice:"deny", reason:"timeout"}`

### 下行:REST 新建 `POST /tasks/{task_id}/confirm`

- 请求:`{confirm_id: str, choice: "allow" | "deny"}`
- 鉴权:任务成员(与 send_message 同口径)
- 响应:`{ok: true}`;confirm_id 不存在/已应答 → 4001
- 服务端行为:内存挂起表 `dict[confirm_id, asyncio.Future]`,应答 set_result 放行执行;任务结束清理

### 前端接线

- `useTaskChatStream` onmessage 加 `chat_confirm_request` 分支 → TaskChat state
- 确认卡 UI:消息列表尾部插入确认区块(prompt + 允许/拒绝按钮),点击调 confirm 接口;应答后卡片转「已允许/已拒绝」灰态
- 与停止按钮并存:确认挂起期间停止按钮仍可点(语义=放弃本轮)

## 数据模型变更

无(确认挂起表为进程内存,不落库;重启=全部按超时 deny 处理,可接受)

## 服务端行为规格

- 同一时刻单任务最多 1 个待确认(串行执行天然保证)
- confirm_id 一次性,应答后即失效
- 超时兜底:5min
- **存量行处理**:无

## 负向探查摘录(适用项)

- 状态域:确认挂起 × 任务停止 → stop 优先,挂起确认按 deny 收口
- 异步域:执行协程在确认期间挂起,POST 不返回(与现行阻塞口径一致)
- 旅程域:发送消息 → 确认请求 → 应答 → 执行继续 → chat_done(J 旅程补录)
- 不适用:查询/数据/契约域(无新表无列表页)

## 涉及模块/文件

- runner:main.py(claude_stream 透传无需动)、container_manager.py(cmd 加权限参数——机制待验证)
- 后端:task_service.py(_stream_event_to_chat 分支 + 挂起表 + broadcast)、api/tasks.py(confirm 端点)
- 前端:api/tasks.ts(WS 分支)、TaskChat.tsx(确认卡 UI)
