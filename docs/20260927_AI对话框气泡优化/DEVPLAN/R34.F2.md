# R34.F2:修复 BUG-UI-092 对话框模型切换

## 描述(bug)

项目设置已有多模型配置(R13),对话框无切换入口,发送不携带模型选择。

## 实现要点

**前端(本轮可做)**:
- 数据源:`modelConfigsApi.list(projectId)`(已有,`frontend/src/api/projects.ts` L497),过滤 `enabled`,默认选中 `is_default` 项
- UI:输入区左侧(附件按钮旁)加模型切换下拉:显示当前模型 name,展开列出各配置(name + model 小字)
- 状态:组件级 `selectedConfigId`(会话级记忆,刷新回默认);无配置/未启用时不渲染切换器
- 发送:`sendTaskMessage(taskId, content, configId?)` 加可选入参,请求体带 `config_id`(后端暂忽略不影响——占位,待后端消费)

**后端(契约已按调研写实,2026-09-27 rd-plan;需改 4 层,证据 .scratch/fix-analysis.md)**:
1. api 层:`SendMessageRequest`(api/tasks.py L519)加 `config_id: str | None = None`,透传
2. service 层:`send_message_stream`(task_service.py L609)加参,函数内 `llm_service.resolve_config(db, task.project_id, config_id)`(**resolve_config 已预留 config_id 形参,llm_service.py L115,三级回退现成**);sync 版 send_message(L482)同改
3. claude_service 层:`run_prompt_stream`(L68)args 加 `model` 字段
4. runner 层:main.py L429 透传 → `container_manager.claude_prompt_stream`(L358)cmd 拼 ` --model {_shlex.quote(model)}`(**必须走 CLI flag:ANTHROPIC_MODEL env 在容器创建时固化,--model 覆盖它**);非流式 `claude_prompt`(L612)同改
- **越权校验**(负向探查):config_id 须校验 `ModelConfig.project_id == task.project_id`,否则可越权用其他项目配置(resolve_config 现状不校验归属;`_get_config_or_404` 模式可复用,model_config_service.py L54)

## 测试验证逻辑

- 项目有多个启用模型配置时,对话框出现切换器,默认选中默认配置
- 切换后发送,请求体携带对应 config_id(Network 面板可验)
- 无配置时切换器不出现

🔄 前端部分已实施(2026-09-27):输入区附件按钮旁模型切换下拉(启用配置过滤 + 默认选 is_default,组件级 selectedConfigId 记忆,无配置/无 projectId 不渲染);`sendTaskMessage` 加可选 configId,请求体携带 config_id——后端消费待契约(占位)收尾
