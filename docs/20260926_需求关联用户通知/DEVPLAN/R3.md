# R3:评审通过站内通知

- **状态**:✅ | **依赖**:R1 | **模块**:M1

## PRD 引用(PRD-A R3)

状态变 approved 时向当次关联用户发站内信;每次通过都通知;排除操作人;已移出项目成员跳过;空名单跳过;失败不阻塞。

## 接口契约(内部接线,无新接口)

- 挂钩:requirement_service.review_requirement approved 分支(:231-234 置状态后、:236-239 audit 旁),flush 前 try/except 包裹 send_notification
- 通知:type=review_approved(枚举已存在),level normal,title「需求《{title}》已评审通过」,content「可以开始开发了」+link=/requirements/{req_id},project_id
- 收件人:related_user_ids 去重 → 排除操作人 → 过滤仍为项目成员者

## 服务端行为规格(负向探查)

- 名单空/全被过滤 → 零发送零报错(挖掘:状态域)
- 单个 send_notification 抛异常 → 捕获记日志,不回滚评审(挖掘:异步域,判定=评审主流程必成功)
- related_user_ids 为 NULL 的存量需求 → 视同空名单(挖掘:存量域)

## 完成判据

- [x] 关联 2 人评审通过 → 2 人各收到站内信(内容/链接正确)
- [x] 操作人在名单内 → 操作人未收到(异常)
- [x] 名单含已移出成员 → 该人未收到,其余正常(异常)
- [x] 空名单通过 → 无通知无报错(异常)
- [x] mock send_notification 抛异常 → 评审仍成功(异常)
