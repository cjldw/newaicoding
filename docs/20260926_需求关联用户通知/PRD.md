# PRD:需求关联用户与评审通过通知

> 创建日期:2026-09-26
> 状态:**已确认**(2026-09-26,四项边界已拍板,待确认清单为空)
> 关联:平台主 PRD R4(需求流程)/R18(站内信)

## 背景与目标

需求创建时无法表达「这个需求和哪些人有关」;评审通过后相关开发者靠口口相传得知开工,信息断层。本需求在创建需求时支持选择**关联用户**,并在需求**评审通过**时自动站内通知他们可以开始开发。

## 用户故事

1. 作为需求创建者,我希望创建需求时选择相关成员,以便明确需求干系人
2. 作为被关联的成员,我希望需求评审通过时收到站内通知,以便及时开始开发

## 需求点清单

### R1:创建需求时选择关联用户

- **描述**:需求创建对话框新增「关联用户」多选下拉,选项=该项目全部成员(owner/editor/viewer,含创建者自己),可多选可不选
- **触发场景**:创建需求填写表单时
- **前置条件**:已进入项目内需求创建对话框
- **边界定义**:
  - 做什么:多选下拉(搜索定位成员,项目成员 ≤50 全量加载无需分页);选择结果随需求保存
  - 不做什么:不选平台非项目成员;不做分页;不设人数上限(成员数即上限)
- **字段定义**:
  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | related_user_ids | string[] | 否 | [] | 每项必须为该项目成员的 user_id;去重 | 关联用户;存储方案 rd-plan 定 |
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 点开下拉 | 列出项目成员(头像+昵称+角色) | 可搜索定位 |
  | 勾选/取消 | 已选以标签(chips)形式展示在输入框,可单个移除 | 计数更新 |
  | 提交 | related_user_ids 随创建接口保存 | 创建成功即生效 |
- **依赖**:无(复用现有成员列表接口)
- **异常与边界场景**:
  - 关联用户被移出项目:保留历史关联记录(通知时该用户已非成员——通知口径见 R3)
  - 提交时成员列表已变化:后端校验 related_user_ids 均为当前项目成员,非法项静默剔除(不阻塞创建)
- **验收标准**:
  1. 创建需求时可选 1~n 名项目成员,保存后详情可见
  2. 不选任何关联用户,创建正常(空数组)
  3. 传入非项目成员 id 被静默剔除

### R2:需求详情页关联用户可编辑

- **描述**:需求详情页可查看并编辑关联用户(增删),编辑权限沿用需求本身的编辑权限口径
- **触发场景**:详情页信息区「关联用户」标签行,编辑入口
- **前置条件**:用户有该需求的编辑权限(口径与现有需求编辑一致,rd-plan 调研对齐)
- **边界定义**:
  - 做什么:多选下拉增删;保存即生效
  - 不做什么:不做编辑历史;不改权限口径
- **字段定义**:同 R1
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 点编辑 | 进入多选编辑态 | 保存/取消 |
  | 保存 | 调更新接口保存名单 | 详情刷新 |
- **依赖**:R1(同一字段)
- **异常与边界场景**:空名单保存=清空关联(合法)
- **验收标准**:详情页可增删关联用户并保存生效

### R3:评审通过触发站内通知

- **描述**:需求状态变为「评审通过(approved)」时,向**当次**关联用户名单发送站内通知「可以开始开发」
- **触发场景**:owner/有权限者在评审流程中执行「评审通过」动作成功后
- **前置条件**:需求关联用户非空(空名单不通知,不报错)
- **边界定义**:
  - 做什么:状态每次变为 approved 都通知(驳回后再次通过会再通知,已确认);名单按当次保存值;复用 R18 站内信;通知含需求名与详情链接
  - 不做什么:不发钉钉;不通知操作人本人(自己触发通过且自己在名单内则跳过自己);不对已移出项目的历史关联用户发通知
- **字段定义**:无新字段(复用 notifications 表)
- **交互规则**:
  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 评审通过动作成功 | 向当次关联用户(去重、排除操作人、仍为项目成员者)各发一条站内信 | NotificationCenter 可见 |
  | 关联用户为空 | 跳过通知 | 无副作用 |
- **依赖**:R1(名单来源)、R2(通过前可修正名单)
- **异常与边界场景**:
  - 名单中有用户已被移出项目:跳过该用户(不通知)
  - 通知发送失败:不阻塞评审通过主流程(通知失败仅记日志)
- **验收标准**:
  1. 关联 2 人 → 评审通过 → 2 人各收到站内信(内容含需求名+链接)
  2. 操作人在名单内时,操作人本人不收到
  3. 驳回后再通过,再次通知
  4. 空名单通过,无通知无报错

### R4:工作台「与我相关」口径升级(2026-09-26 补录,用户指令)

- **描述**:首页工作台四维统计与最近列表口径从 created_by=me 升级为「与我相关」(关联用户 ∪ created_by;任务含需求传导去重);排序改行动优先(逾期>临期>运行中>最近);布局骨架保留,不按角色分叉
- **验收标准**:关联用户(非创建者)首页可见该需求及其任务;逾期置顶红标;他人数据不出现

## 非功能需求

- 通知发送为评审通过的同步附加动作,单用户发送失败不阻塞(见 R3 异常)

## 范围外

- 钉钉通道(R18 已有,本需求不接)
- 关联用户的编辑历史/审计报表
- 存量需求批量补录关联用户(存量需求无关联用户,自然不触发通知)
