- **状态**:✅ 完成(2026-09-26)
- **PRD 引用**:
  - **边界**:做什么 = llm_model 单值升级为模型名列表 `llm_models`(≤10)+ 默认模型 `llm_default_model`;模型名 tag 风格展示(添加前逐个连通测试);存量单值读取层兼容。不做什么 = 平台级多组接入(仍一套 base_url+key)、per-model 独立 key、模型名自动发现。

  ### 接口 1:更新平台设置(复用现有,扩展 llm 分支)

- **实现要点**:
  - 后端①:`SETTING_KEYS` 加 `llm_models: ("strlist", None)`(新增类型:数组、每项 str 1-64、去重、≤10)与 `llm_default_model: ("str", None)`;`LLM_KEYS` 三键集合扩为四键(替换 llm_model)。
  - 后端②:PUT llm 分支齐备校验改为四键;连通测试对象 `llm_models` 中的 `llm_default_model`(取自 payload,校验 default ∈ models 后测试)。
  - 后端③:GET `get_all_masked` 加兼容映射(llm_models 缺失且 llm_model 有值 → 返回映射);`_resolve_platform_config` 改读 `llm_models`+`llm_default_model`(含旧键回退)。
  - 前端①:`llmForm` 模型字段从单串改为 `models: string[]` + `default_model: string`(reset 从 GET 兼容数据初始化);`onLlmSubmit` 改四键校验(空列表 → "请至少添加一个模型名")与 PUT payload。
  - 前端②:renderLlm 的「模型」Input 替换为 tag 输入组(输入框 + 「添加」按钮):点添加/Enter → 先调 test-connection(按钮转 loading)→ 成功 push 进 models(若列表为空,该项同时设为 default)→ 失败 toast 并保留输入。
  - 前端③:tag 渲染 `.chip`:默认项带 `Badge variant="primary"`「默认」;hover 出 Star(设默认,`w-3 h-3`)与 X(删除,`w-3 h-3 hover:text-red-fg`);删除最后一项禁用 X。
  - 页面生成逻辑数据映射:tag 列表 = 本地表单态 `models` 数组循环;「默认」徽章由 `default_model === item` 驱动;保存成功后 `loadData(false)` 静默刷新打码回显。

- **页面交互流程**:
  - 添加:输入模型名 → 点「添加」(或 Enter)→ 按钮转"测试中" → 成功:tag 追加到列表、输入框清空;失败:toast 错误文案、输入保留
  - 设默认:tag hover 点 Star → 该 tag 加「默认」徽章,原默认移除(纯本地态)
  - 删除:tag 点 X → tag 移除;若删的是默认 → 第一个剩余 tag 自动成为默认 + 行内提示"已将 {model} 设为默认";列表仅剩 1 个时 X 禁用
  - 保存:点「保存」→ 前端校验(四键齐备/列表非空/key 编辑态完整)→ PUT → 成功:提示"保存成功"、静默刷新打码回显、退出 key 编辑态;失败:提示错误(2007/2008/13008/13009 message),编辑态保留
- **错误处理行**:
  - 添加时测试失败(2008 message,如"连接失败,请检查 Base URL 和 API Key")→ toast 展示 message,模型名不入列
  - 保存返回 2007 → toast"平台默认模型需完整配置四项";2008 → toast message;13008 → toast"模型名数量已达上限(10 个)";13009 → toast"模型名重复"
  - 防重:「添加」与「保存」按钮请求期间禁用(loading),响应返回后恢复;页面级 tryLock('llm') 沿用
  - 401/403/500 → 沿用全局错误处理(toast)
