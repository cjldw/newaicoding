- **接口契约**:

  ### 接口 1:可选模型清单(新建)
  - 类型:**新建** `GET /api/tasks/{task_id}/model-options`(handler 追加于 `backend/app/api/tasks.py`;聚合逻辑在 `llm_service.list_model_options(db, task)`)
  - 路径与方法:`GET /api/tasks/{task_id}/model-options`
  - 鉴权:登录 + 项目成员(`get_project_role` 非 None,含超管虚拟 owner;非成员 → 404;已确认 2026-09-26)
  - 请求参数:无(task_id 路径参数)
  - 响应结构(`data`):

    | 字段 | 类型 | 说明 |
    |---|---|---|
    | current | object \| null | 当前生效模型;项目与平台均未配置时为 null |
    | current.source | "project" \| "platform" | 生效来源 |
    | current.config_id | string \| null | source=project 时的配置 id |
    | current.config_name | string \| null | 配置名(source=platform 为 null) |
    | current.model | string | 生效模型名 |
    | current.selected | boolean | true=任务手动选择;false=回退链解析 |
    | current.stale | boolean | true=手动选择已失效,本次为回退接管 |
    | project_configs | array | 启用配置(is_default 置顶,其余 created_at 升序);每项 {config_id, name, is_default, default_model, models}(default_model 排 models 首位) |
    | platform | object | {configured: bool, models: string[](default_model 在首位), default_model: string\|null} |

  - 错误码与异常:404(任务不存在/非成员);项目平台均未配置时不报错,`current=null` 且两组为空(configured=false / project_configs=[])
  - 分页格式:无

  ### 接口 2:切换模型(新建)
  - 类型:**新建** `PUT /api/tasks/{task_id}/model`
  - 路径与方法:`PUT /api/tasks/{task_id}/model`
  - 鉴权:同接口 1(项目成员;已确认 2026-09-26)
  - 请求体:

    | 参数 | 类型 | 必填 | 说明 |
    |---|---|---|---|
    | config_id | string \| null | 是 | 项目配置 id;null 表示平台模型或清除选择 |
    | model | string \| null | 是 | 模型名;与 config_id 均为 null = 清除选择恢复回退链(已确认 2026-09-26) |

    语义:①config_id 非空 → 配置存在且 enabled 且 model ∈ models,否则 13006;②config_id 为空且 model 非空 → model ∈ 平台 llm_models,否则 13006;③均空 → 清除 tasks.chat_config_id/chat_model。
  - 响应结构(`data`):

    | 字段 | 类型 | 说明 |
    |---|---|---|
    | current | object | 同接口 1 current(切换后的生效结果,selected=true) |
    | new_session | boolean | true=跨接入切换已重置 claude 会话(前端据此提示"已切换模型,开启新会话") |

  - 错误码与异常:**13006**(目标不可用:配置不存在/禁用/模型名不在列表/平台未配置或模型名不在 llm_models)、404、403(1901 非成员)
  - 分页格式:无

  ### 接口 3:发送消息(复用现有端点,执行链路与响应扩展)
  - 类型:复用现有 `POST /api/tasks/{task_id}/messages`(`tasks.py:436`;`task_service.send_message_stream`)
  - 请求体:不变(`{content}`;**不接收**模型参数——模型由任务当前选择决定)
  - 响应结构(现有基础上新增 2 键):

    | 字段 | 类型 | 说明 |
    |---|---|---|
    | (现有字段) | - | 沿用 |
    | model | string | 本条消息实际执行的模型名(resolve 后,含回退接管) |
    | model_stale | boolean | true=任务所选模型已失效,本次回退链接管 |
    | session_reset | boolean | true=同接入 resume 失败已自动新开会话重试(前端提示"已切换模型,开启新会话") |

  - 错误码与异常:13005(均未配置)、TERMINAL_UNAVAILABLE(容器/Runner 不可用,沿用);切换后模型运行时报错 → 该条消息执行失败(沿用 Runtime 口径),**不自动回切**
  - 分页格式:无

  ### 接口 4:消息历史(复用现有端点,响应扩展)

- **服务端行为规格**(负向探查 9 域过筛结论):

  | 域 | 行为 | 规格 |
  |---|---|---|
  | 状态域 | 会话重置 | 跨接入切换(base_url 或 api_key 与当前生效不同)→ PUT 时直接 `task.claude_session_id=None`(下次消息 `--session-id` 新建)+响应 new_session=true(已确认 2026-09-26:切换时主动重置,不等 resume 失败);同接入 resume 失败 → 执行链路自动重置重试**一次**,响应 session_reset=true,不二次重试 |
  | 状态域 | 非法状态迁移 | 任务终态(failed/cancelled/done/timeout)切换:允许(只改选择,不影响执行);执行时容器不运行 → 沿用 TERMINAL_UNAVAILABLE,不做额外状态机 |
  | 引用域 | 悬空引用 | 切换目标校验(接口 2 语义 ①②)防悬空;不存"配置已删但 task 仍指它"的脏数据——允许发生(删配置是合法并发),由执行时 resolve 兜底回退 + stale 标记 |
  | 引用域 | 删除保护 | 删配置(R13 DELETE)**不**级联清理 tasks.chat_config_id——指向被删配置的任务由回退链接管(执行时检测),不做删除拦截(切换是可再指派的弱引用) |
  | 数据域 | 存量兼容(必答) | chat_config_id/chat_model NULL → 回退链解析(现行为);task_messages.model NULL → 前端不渲染小字;无回填 |
  | 契约域 | 响应最小化 | model-options/切换/消息响应**禁止出现** base_url、api_key(含打码)、api_key_masked——清单只含 config_id/name/models/default_model |
  | 契约域 | 向后兼容 | POST/GET messages 新增键为附加字段,旧调用方不读不受影响;SendMessageRequest 请求体不变 |
  | 一致性域 | 快照语义 | task_messages.model 是**执行时快照**(回溯准确);切换后历史消息标注不变 |
  | 安全域 | key 暴露面 | 解析出的 api_key 仅存在于后端内存与 runner WS exec args(与容器创建 env 同信任域),禁落日志/审计/事件广播/chat_delta |
  | 旅程域 | 见 DEVPLAN.md J1/J2 | 配置→清单→切换→执行→留痕;失效→回退→提示 |
  | 异步域 | 流式事件 | 切换不新增 WS 事件类型;chat_delta/chat_done 结构不变(chat_done 现有 duration_ms 等沿用) |
  | 并发/幂等 | 并发切换 | 两成员同时 PUT → last-write-wins(单行 UPDATE,无版本冲突);并发发送+切换 → 该条消息用发送时已 resolve 的模型(执行开始后切换不影响进行中消息) |

  执行链路规格(resolve→注入):
  1. `llm_service.resolve_chat_config(db, task) -> {base_url, api_key, model, source, config_name?, selected, stale}`:task 选择优先(config_id+model 校验通过 → project;config_id 空但 chat_model ∈ 平台列表 → platform);校验失败 → 回退链(R2 的 default 配置×default_model → R1 平台默认模型),stale=true;全部无 → 13005。
  2. `claude_service.run_prompt_stream(..., env={"ANTHROPIC_BASE_URL": container_base_url(resolved.base_url), "ANTHROPIC_API_KEY": resolved.api_key, "ANTHROPIC_MODEL": resolved.model})` → runner args.env 透传 → `exec_create(..., environment=env)` 覆盖容器 env(同接入不传 env 时维持容器 env,实现统一为**每次都传**,幂等)。
  3. assistant 落库 `model=resolved.model`;响应附 model/model_stale/session_reset。
