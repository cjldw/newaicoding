# PRD:模型多配置与 AI 对话切换

> 创建日期:2026-09-26
> 状态:已确认(2026-09-26 三轮访谈收口,待确认清单已清零)

## 背景与目标

- 平台设置「模型默认配置」目前仅支持**单组三键**(llm_base_url / llm_api_key / llm_model,R23),只能配一个模型;实际使用中同一接入下需要在多个模型间切换(如 gpt-4o / deepseek-chat)。
- 任务详情 AI 对话框目前**无法选择模型**,消息一律走回退链解析出的唯一模型;切换模型只能改配置,成本高。
- 目标:平台默认配置支持「一套接入 + 多个模型名」(tag 风格展示);项目级模型配置升级为「一条配置挂多个模型名」(与平台结构对齐);AI 对话发送区支持选择模型、调接口切换(任务级持久);每条 AI 回复可追溯所用模型。
- 衡量成功:超管可在平台设置维护多个模型名 tag;项目成员在任务对话中一步切换模型且后续消息生效;消息可查所用模型。

## 用户故事

1. 作为超管,我希望平台默认配置里添加多个模型名并以 tag 展示,以便项目在同一接入下有多个模型可选。
2. 作为项目成员,我希望在任务 AI 对话框底部选择模型,以便当前任务用我想要的模型继续对话。
3. 作为项目成员,我希望看到每条 AI 回复用的哪个模型,以便对比效果、排查问题。

## 需求点清单

### R1:平台级模型默认配置 —— 一套接入 + 多模型名(tag 风格)

- **描述**:平台设置「模型默认配置」从单组三键升级为:一套 Base URL + API Key + **多个模型名**;模型名以 tag 风格展示,可逐个添加/删除,其中一个标记为默认模型。
- **触发场景**:超管在平台设置页维护平台默认 LLM 配置。
- **前置条件**:超管权限(沿用 require_superadmin);Base URL 与 API Key 已配置有效。
- **边界定义**:
  - 做什么:llm_model 单值升级为模型名列表(≤10 个);tag 展示(点击=编辑入口、×=删除);默认模型标记;每个模型名保存前连通性测试;存量单值自动兼容为列表。
  - 不做什么:**不做平台级多组接入**(仍是一套 base_url + key,R23"不做平台级主/备多组"边界维持);不做 per-model 独立 key;不做模型名白名单/自动发现(GET /models 拉取)。
- **字段定义**:

  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | llm_base_url | url | 是 | 无(未配置) | http(s) 非空 | 沿用 R23,OpenAI 兼容 endpoint |
  | llm_api_key | secret | 是 | 无(未配置) | 非空 ≤255;AES-GCM 加密;接口永不回显完整(打码:前5+掩码+后4) | 沿用 R23 |
  | llm_models | string[] | 是 | [](未配置) | 每项非空、1-64 字符、列表内去重;**≤10 项** | 模型名列表(升级自 llm_model 单值) |
  | llm_default_model | string | 是(列表非空时) | 列表第一项 | 必须存在于 llm_models | 回退链/新任务默认使用的模型,tag 高亮"默认" |

- **交互规则**:

  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 添加模型名 | 输入模型名 → 用当前 base_url+key 对该模型名连通性测试 → 失败拒绝(沿用 2008 口径提示)→ 成功加入 tag 列表 | tag 上屏 |
  | 删除 tag(×) | 列表仅剩 1 个时不可删(至少保留一个,避免"有 key 无模型"的部分配置态) | tag 移除 |
  | 删除的是默认模型 | 自动将剩余列表第一个设为默认,并提示 | 默认顺延 |
  | 修改 base_url / api_key | 整批保存 + 用默认模型做连通测试(沿用 R23 三键齐备→改为"两键+列表齐备") | 保存成功/拒绝 |
  | 设置默认模型 | tag 操作菜单中标记;必须是列表内已有项 | tag 高亮 |
  | 存量数据兼容 | 已配置的 llm_model 单值自动读作 llm_models=[旧值] 且为默认,无感迁移 | 行为不变 |
  | 模型名重复添加 | 拒绝(去重),提示"该模型已存在" | 拦截 |

- **依赖**:R23(平台设置承载、打码与连通测试口径)、R3(对话可选清单的来源)
- **异常与边界场景**:
  - 超上限(10 个):拒绝添加并提示
  - 连通测试通过但模型名运行时报错:沿用 R23 口径(运行时任务 failed,不做白名单)
  - key 泄露处理同 R23/平台设置既有口径
  - 并发保存:沿用平台设置现有锁定(tryLock)口径
- **验收标准**:
  1. 超管可逐个添加模型名(每个都过连通测试)并以 tag 展示,tag 可删、可标默认,≤10 个
  2. 存量单模型平台配置升级后行为不变(回退链正常,默认=原模型)
  3. 删除默认模型自动顺延;最后一个模型名不可删
  4. key 全程打码,不明文出现在接口/日志

### R2:项目级模型设置 —— 一条配置支持多模型名

- **描述**:项目级模型配置升级为「一条配置 = Base URL + API Key + **多个模型名**」(数据结构与平台级 R1 对齐);管理 UI 沿用 Table + 编辑对话框形态,仅模型字段改为 tag 输入/展示;为 R3 提供可选模型来源之一。
- **触发场景**:项目 owner 在项目设置「模型配置」Tab 管理配置。
- **前置条件**:owner 权限(沿用)。
- **边界定义**:
  - 做什么:model 单值升级为模型名列表(每配置 ≤10 个);配置内 default_model 标记;新建/编辑对话框内模型名 tag 逐个添加(逐个连通测试);Table「模型」列多 tag 展示;配置组数上限 ≤10;存量单值自动兼容为列表。
  - 不做什么:不做整套 Table→tag 改版(仅模型字段);不改 R13 既有约束(配置名唯一/default 配置唯一/default 配置不可删);不做 per-model 独立 key;不做模型名自动发现。
- **字段定义**(替代 R13 的 model 单值,其余字段沿用 R13):

  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | models | string[] | 是 | - | 每项非空、1-64 字符、列表内去重;**每配置 ≤10 项** | 该接入下可用的模型名列表(升级自 model 单值) |
  | default_model | string | 是 | 列表第一项 | 必须存在于 models | 配置内默认模型(回退链/新任务未选择时使用) |
  | (其余字段) | - | - | - | - | config_id / project_id / name / base_url / api_key / is_default / enabled / created_by 沿用 R13 |

- **交互规则**:

  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 对话框内添加模型名 | 输入 → 用当前 base_url+key 即时测试该模型名 → 失败拒绝加入(提示沿用 2008/13001 口径)→ 成功加入 tag | tag 上屏 |
  | 删除模型名 tag | 每配置仅剩 1 个时不可删;删除的是 default_model → 自动顺延剩余第一个并提示 | tag 移除 |
  | 保存(模型名有新增) | 前端已逐个测过的项不重复测;保存即落库 | 成功 |
  | base_url / api_key 变更 | 保存时对列表内**全部**模型名依次重测,任一失败整批拒绝(沿用 13001) | 保存/拒绝 |
  | 仅改名/启停/default 标记 | 不重测(沿用 R13) | - |
  | 既有约束 | 配置名唯一(13002)/ default 配置唯一(13003)/ default 配置不可删(13004)沿用 | - |
  | 数量上限 | 第 11 组配置拒绝;每配置第 11 个模型名拒绝 | 拦截(错误码由开发计划定) |
  | Table 展示 | 「模型」列显示 tag 列表(超过 3 个折叠为 +N),default_model 带"默认"徽章;其余列不动 | - |
  | 存量数据兼容 | model 单值自动读作 models=[旧值] 且 default_model=旧值,无感迁移 | 行为不变 |

- **依赖**:R13(全部既有约束沿用)、R1(结构对齐)、R3(可选清单来源)
- **异常与边界场景**:
  - 上限判断与并发创建:服务层校验,后到者拒绝
  - 连通测试通过但模型名运行时报错:沿用 R13/R23 口径(运行时 failed,不做白名单)
- **验收标准**:
  1. owner 可在一条配置内逐个添加多个模型名(逐个测试),tag 展示,每配置 ≤10 个;配置组数 ≤10
  2. default_model 可标记/顺延;最后一个模型名不可删
  3. base_url/key 变更时全量模型名重测,任一失败整批拒绝
  4. 存量单模型配置升级后行为不变(回退链、任务执行正常)
  5. 既有 R13 行为回归通过

### R3:AI 对话框模型选择与切换(任务级持久)

- **描述**:任务详情 AI 对话(TaskChat)发送区新增模型选择器:列出可选模型(项目启用配置 + 平台模型名),选中后调用切换接口持久化到任务,后续消息按所选模型执行;每条 AI 回复记录并展示所用模型。
- **触发场景**:项目成员在任务对话中希望换用其他模型。
- **前置条件**:任务存在且对话入口可用;至少一个可用模型来源(项目启用配置,或平台已配置模型列表)。
- **边界定义**:
  - 做什么:选择器 UI(分两组:项目配置 / 平台默认);切换接口(任务级持久,任务内全员可见同一状态);切换后下一条消息生效;同接入内切换尽量延续 claude 会话上下文,跨接入续接失败自动新开会话并提示;消息级模型记录 + 气泡小字展示。
  - 不做什么:不做消息级临时选择(每次发送都选);不做用户级跨任务偏好;不做其他 AI 入口(仅任务详情 TaskChat);不做模型使用量/费用统计。
- **字段定义**:

  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | 任务当前模型 | 引用:项目某配置的某模型名(config_id + model),或平台某模型名 | 否 | 空=按回退链解析 | 切换时校验目标存在于可选清单 | 任务级持久,任务内共享 |
  | TaskMessage.model | string(64) | 否 | null | ≤64 | 该条 AI 回复实际所用模型名(落库+展示) |

- **交互规则**:

  | 场景/条件 | 行为/规则 | 结果/去向 |
  |---|---|---|
  | 打开选择器 | 两组:「项目配置」= 按配置分组的模型名(default 配置置顶,组内 default_model 靠前并带标记;项显示 配置名·模型名)+「平台默认」= 平台模型名列表(仅模型名;平台/项目 key 对成员永不可见) | 下拉/弹出选择 |
  | 当前生效项 | 未手动切换=回退链解析结果(项目 default 配置×default_model → 平台默认模型),选择器中高亮;已切换=任务当前所选 | 高亮标识 |
  | 选择模型 | 选中项语义 = 项目某配置的某模型名,或平台某模型名;调切换接口 → 成功后任务当前模型更新,后续消息用新模型;失败则选择器回弹并提示 | 即时反馈 |
  | 切换生效边界 | 下一条消息生效;进行中的执行不受影响 | - |
  | 上下文延续 | 同接入(url+key 相同,仅换模型名,含同配置内切换)尽量 `--resume` 延续会话;跨接入切换续接失败 → 自动新开会话,提示"已切换模型,开启新会话" | 对话继续 |
  | 权限 | 切换跟随发消息权限(项目成员均可,含 viewer);配置增删改仍 owner/超管,不变 | - |
  | AI 回复展示 | 气泡小字标注该条所用模型名(如 `deepseek-chat`);消息记录落库 model | 可追溯 |
  | 并发切换 | 两成员同时切换:后写赢(last-write-wins) | - |

- **依赖**:R1(平台模型名列表)、R2(项目配置清单)、R32.F3(对话流式链路)、R23(回退链解析)
- **异常与边界场景**:
  - 平台与项目均未配置模型:选择器禁用/隐藏,沿用现有 13005 禁用与引导口径
  - 所选模型失效(配置被删/禁用,或模型名被移除):下一条消息自动回退链接管(项目 default 配置×default_model → 平台默认模型),选择器回显回退后的生效项并提示"原模型已不可用"
  - 切换后的模型运行时报错(如模型名错):该条消息执行失败(沿用运行时失败口径),**不自动回切**;用户可手动再切
  - 切换接口失败(网络/权限):任务当前模型不变,选择器回弹
- **验收标准**:
  1. 对话发送区可选择项目配置与平台模型,切换后下一条消息即用新模型(可从回复模型标注验证)
  2. 任务级持久:刷新页面/他人打开该任务,所见当前模型一致
  3. 同接入切换上下文延续;跨接入切换失败自动新会话且有提示
  4. 每条 AI 回复落库并展示所用模型
  5. 无任何可用模型时选择器不可用,引导文案出现
  6. 所选配置失效时自动回退并提示,不阻塞发送

## 非功能需求

- **安全**:平台/项目 API Key 全链路不明文出后端(打码口径沿用);切换接口仅传模型标识,不传 key。
- **审计**:任务模型切换写审计日志(沿用 R25 model_config.* 风格,如 task.model_switch:task_id、from、to)。
- **性能**:可选清单复用/扩展现有接口,选择器打开不引入明显延迟(<500ms);连通测试仅在配置变更时发生。
- **兼容**:存量平台单模型、存量任务(无当前模型字段)按回退链解析,行为不变。

## 范围外

- 项目级模型配置的整套 Table→tag 改版(仅模型字段 tag 化)
- 平台级多组接入(多套 url+key)
- 模型名自动发现(GET /models 拉取可选列表)
- 用户级/跨任务的模型偏好记忆
- 任务详情以外入口的模型切换
- 模型费用/用量分模型统计
