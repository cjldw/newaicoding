# PRD:打磨 PRD 持久化(PRD 内容入库 + 免容器预览)

> 创建日期:2026-09-29
> 状态:已确认(2026-09-29 用户终审通过)
> 背景:方案 D(rd-fix 第 42 轮「打磨产物持久化」咨询收敛结果)

## 背景与目标

打磨任务(type=requirement)的 PRD.md 由 AI 写在容器临时文件系统(`{prd_file_path}`,如 `docs/{YYYYMMDD}_{slug}_{taskid8}/PRD.md`)。正常收尾有 force-push 保底;容器异常关闭(crash/OOM/Docker 重启/被对账销毁,本机 BUG-073 实证高频)即丢失,仅能从对话记录人工捞回。

**目标**:PRD 内容以平台为持久层,容器对「不丢、能看」彻底无状态化;顺带实现**不启动容器也能预览 PRD**。成功标准:任何时刻销毁打磨容器,已产出的 PRD 仍可预览;新打磨任务首轮回复后副本即建立。

## 用户故事

1. 作为需求提出人,我希望容器异常关闭后仍能预览已产出的 PRD,以便不重跑打磨
2. 作为需求提出人,我希望不启动容器也能在打磨页和需求详情页直接预览 PRD
3. 作为打磨者,我希望每轮对话后 PRD 自动保存,无需手动 push

## 需求点清单

### R1:PRD 平台副本存储

- **描述**:`requirements` 表新增 `prd_content` 列,存放 PRD.md 最新内容副本
- **触发场景**:系统内部回传时写入(见 R2);不开放任何 API 直接写该列
- **前置条件**:需求存在且 `prd_file_path` 非空(打磨任务创建时已固定)
- **边界定义**:
  - 做什么:新增列;系统写入;随库备份
  - 不做什么:不做版本历史(单最新值);不做 API 编辑入口;不做多文件产物
- **字段定义**:
  | 字段 | 类型 | 必填 | 默认值 | 校验规则 | 说明 |
  |---|---|---|---|---|---|
  | prd_content | MEDIUMTEXT | 否 | NULL | 内容 ≤16MB,超长截断 + warning 日志 | PRD.md 平台副本(最新值);NULL=尚无副本 |
- **交互规则**:
  | 场景 | 行为 | 结果 |
  |---|---|---|
  | 系统回传读到非空内容 | 覆盖更新 prd_content | 副本为最新值 |
  | 回读为空/失败 | 不覆盖(保留旧副本) | 旧值不劣化 |
- **依赖**:无(本 PRD 基础点)
- **异常与边界场景**:
  - 超长截断必须留日志(可回溯)
  - 迁移走 alembic,存量行 prd_content=NULL(不做回填,源在容器的才拉得到)
- **验收标准**:
  1. 列存在且 alembic 迁移可升降级
  2. 无任何用户可达 API 能直接写该列

### R2:回传机制(容器 → 平台副本)

- **描述**:两个回传时机——主链路「每轮 AI 回复结算后拉取」+ 兜底「预览时拉取」
- **触发场景**:
  - **主**:type=requirement 任务每轮对话结算后(send_message_stream 收尾),若容器在线 → 回读 `{prd_file_path}` → 非空则更新副本
  - **兜底**:预览请求时若库无副本且容器在线 → 回读并回填(覆盖用户在终端手动改文件的场景)
- **前置条件**:容器 running;`prd_file_path` 非空
- **边界定义**:
  - 做什么:上述两个时机;拉取失败记日志跳过(不重试轰炸,下一时机自然重试)
  - 不做什么:不做 file_watcher 事件驱动(实时链路,范围外);不阻断对话/预览主流程(回传失败对用户透明)
- **交互规则**:
  | 场景/条件 | 行为 | 结果 |
  |---|---|---|
  | 每轮回复结算且容器在线 | 回读路径文件 | 非空→更新副本;空→跳过 |
  | 回读失败/超时 | 记日志跳过 | 对话与预览主流程不受影响 |
  | 预览时库无副本且容器在线 | 回读+回填 | 副本建立并返回 |
- **依赖**:R1
- **异常与边界场景**:
  - 容器恰在结算瞬间销毁 → 拉取失败跳过,不报错给用户
  - 用户终端手改文件 → 下一次预览兜底拉取覆盖副本
- **验收标准**:
  1. 打磨首轮 AI 回复后 ≤5s,`prd_content` 非空且与容器内文件一致
  2. 人为杀容器后副本仍在(R1/R3 联合验收)
  3. 回读失败时对话正常出回复、预览正常降级,无 500

### R3:打磨 Tab 免容器预览(读侧切换)

- **描述**:任务工作台中栏「PRD 草稿容器」预览改为优先读平台副本
- **触发场景**:打磨任务工作台打开/切换到 PRD 预览
- **前置条件**:无(容器离线也可用——核心诉求)
- **边界定义**:
  - 做什么:打磨 Tab 读侧切平台副本;降级口径见交互规则
  - 不做什么:dev/test/release 任务的文件预览**完全不动**;不做编辑
- **交互规则**:
  | 场景/条件 | 行为 | 结果/去向 |
  |---|---|---|
  | 库有副本 | 直接展示平台副本 | 容器开关无关 |
  | 库无副本且容器在线 | 读容器 + 回填(R2 兜底) | 展示并建立副本 |
  | 库无副本且容器离线 | 空态「暂无 PRD,完成首轮打磨后可预览」 | 明确引导,不报错 |
- **依赖**:R1、R2
- **异常与边界场景**:
  - 容器在线但文件尚未产出(AI 还没写) → 同「库无」空态
- **技术注记(留 rd-plan)**:预览接口形态——扩展现有 `GET /tasks/{id}/files/content` 分支,或新增 `GET /requirements/{id}/prd-content`;前端 useTaskFileContent / 新 hook 取舍
- **验收标准**:
  1. 有副本时**销毁容器**后刷新页面,预览正常显示(核心验收)
  2. 全新任务容器离线时,预览显示空态文案而非报错
- 3. dev 任务文件预览回归不变

### R4:需求详情页 PRD 预览入口

- **描述**:RequirementDetail(需求详情页)新增 PRD 只读预览区块,读平台副本
- **触发场景**:需求详情页查看(用户拍板 Q5 纳入本期)
- **前置条件**:同 R3 降级口径(库有副本展示;库无且容器在线走 R2 兜底;双无空态)
- **边界定义**:
  - 做什么:只读渲染(markdown);复用 R3 同一读接口/降级口径
  - 不做什么:不做编辑;不重复实现拉取逻辑(与 R3 共用)
- **交互规则**:同 R3 交互规则表(降级口径一致)
- **依赖**:R1、R2
- **异常与边界场景**:无 prd_file_path 的历史需求 → 区块隐藏或空态
- **验收标准**:
  1. 有副本时需求详情页直接可见 PRD(容器离线亦可)
  2. 无副本空态不报错

## 非功能需求

- 回传失败静默降级,任何情况下不得阻断对话/预览主流程
- prd_content 读写不进审计敏感键列表(非密文)
- 迁移幂等,可重复执行

## 范围外

- 反向回填(平台副本 → 新容器恢复文件;续打磨靠对话上下文)
- 版本历史/快照/回滚
- file_watcher 事件驱动回传
- dev/test/release 任务文件预览改造
- PRD 在线编辑
