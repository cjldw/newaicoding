# R5:系统级采集(probe_claude)

- **状态**:⬜ | **依赖**:容器基建 | **模块**:M1+Runner

## PRD 引用(PRD-B R1)

临时容器探测 Claude 实际安装的 skills(ls /root/.claude/skills/)+MCP(读 /root/.claude.json mcpServers)入库;首采/重新采集同一超管入口;进程锁防并发;用后即毁。

## 接口契约

- **Runner 新指令** `probe_claude`(runner/main.py handle_message + container_manager 新方法,照 claude_inject :429 先例):start_container(repos=[],task_id 哨兵)→ exec_capture 探测 → stop_container 单次调用内完成;返回 {skills:[name...], mcps:[{name,transport...}]}
- **平台** POST /api/admin/system-assets/collect(require_superadmin):system_asset_service.collect——asyncio.Lock 防并发;request_runner 下发 probe_claude 并等待结果(超时 120s);覆盖入库;响应 {skills:n,mcps:n,collected_at,image_tag}
- **迁移**:新表 claude_system_assets(id/name VARCHAR(128)/kind ENUM(skill,mcp)/detail JSON/collected_at DATETIME/image_tag VARCHAR(128))→ DEPLOY.md

## 服务端行为规格(负向探查)

- 容器启动失败/exec 失败 → 502 可重试,旧数据保留(不因失败清库)(挖掘:一致性域)
- 并发采集 → 锁内串行,第二次等待后直接返回首次结果(挖掘:并发域)
- 采集结果为空 → 清空旧表入库+警告「镜像未内置」(挖掘:状态域)
- Runner 离线 → 502 提示无可用 Runner(挖掘:状态域)

## 完成判据

- [ ] 超管点采集 → 临时容器起→探→毁,列表入库(真机)
- [ ] 并发二次点击串行不重复起容器(异常)
- [ ] 采集失败旧数据保留(异常)
- [ ] 非超管 403(异常)
